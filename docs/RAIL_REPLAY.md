# 철도 경로와 지하철 심도 재생

기준: 2026-09-16. 구현 파일은 `pipeline/rail_routes.py`이며, 입력은 이미 확보한 공식 코레일 기록·OSM 선로·공식 서울교통공사 역사 심도 자료입니다. 이 모듈에는 네트워크 수집이 없으며 기존 아카이브를 재현 가능하게 변환합니다.

## 현재 검증한 범위

| 항목 | 실제 검증 결과 |
|---|---|
| 코레일 운행일·열차 | 2026-09-09 / 01001 |
| 공식 출발·도착 | 조치원 07:26 → 대전 07:49, 한국시간 |
| 공식 운행일련번호 | 6 → 7, 사이 순번 누락 없음 |
| 계산 선로 경로 | OSM 연결 선로 36,962.014m, 381개 원본 형상점 |
| 역 대표좌표→선로 스냅 거리 | 조치원 24.317m, 대전 76.765m |
| 계산 평균속도 | 96.423km/h, 운행 중 실제 순간속도 아님 |
| 지하철 심도 연결 예 | 5호선 광화문 → 종로3가 |
| 지하철 평면 형상 | OSM `5호선` 명칭 선로 1,262.229m, 9점 |
| 공식 두 역 선로 심도 | 25.5m / 31.3m, 각 역 원천 지면 기준 |
| 양끝 표시 선로 높이 | WGS84 타원체고 38.163m / 26.364m |
| 테스트 | 7개 통과 |

코레일 추가 수집은 조치원역 하루의 공개 조회 2회, 107건으로 제한했습니다. 기존 대전역 343건과 결합한 수동 검증 표본입니다. 전국의 운행 기록, 전 구간 열차 여정, 실시간 차량 GPS를 확보했다는 뜻이 아닙니다.

## 실행

프로젝트 폴더의 PowerShell에서:

```powershell
.venv\Scripts\python.exe -m pipeline.rail_routes
.venv\Scripts\python.exe -m pipeline.rail_routes --depth-sample
.venv\Scripts\python.exe -m pytest tests/test_rail_routes.py -q
```

일반 철도 결과는 `.local/review/rail-routes/route-20260909-01001-e7bf8e72553d.json`, 지하철 결과는 `.local/review/rail-routes/seoul-line5-gwanghwamun-jongno3ga-depth.geojson`입니다. 입력이나 변환 결과가 달라지면 일반 철도 파일의 해시는 바뀝니다. 검수 기록은 `.local/audit/rail-route-20260909-01001.json`, `.local/audit/subway-depth-line5-sample.json`에 있습니다.

일반 철도 화면에서 `height`가 없는 선로 재생점을 **지상 투영**하도록 적용하고 동작을 확인한 후, 다음 명령으로 실제 로컬 카탈로그에 반영할 수 있습니다.

```powershell
.venv\Scripts\python.exe -m pipeline.rail_routes --publish
```

`--publish`는 로컬 자산·카탈로그만 갱신합니다. Cloudflare 배포가 아닙니다. 지하철 `--depth-sample`은 지하 선형 렌더러 통합 검수가 필요하므로 자동 공개하지 않습니다.

## 데이터와 계산의 구분

- **공식 기록:** 열차번호, 운행일, 역코드·역명, 역별 순번, 출발·도착 시각, 두 지하철 역의 심도.
- **공개 지도 원천:** OSM 역 대표 좌표·선로 노드와 연결관계. 실제 배정 선로나 특정 승강장을 증명하지 않습니다.
- **계산:** 역 좌표를 가장 가까운 연결 선로 노드에 연결한 뒤 최단 선로 경로를 구합니다. 원본 선로 형상점을 모두 유지하고 거리 비례로 두 공식 시각 사이 시간을 부여합니다. 급가속·감속·신호대기·실제 운전 속도는 확인되지 않습니다.
- **추정:** 지하철의 역간 선로 높이는 두 역의 지형 타원체고에서 공식 선로 심도를 뺀 높이를 경로 거리에 따라 보간합니다. 역간 터널의 실측 깊이·경사·단면을 생성한 것이 아닙니다.
- **미확인:** 열차의 실제 배정 선로, 교량 높이, 역간 터널 수직선형, 승강장별 정차 위치. 일반 철도에서는 높이를 넣지 않습니다.

선로에는 터널과 교량이 포함됩니다. 지상 투영 모드에서 보이는 높이를 실제 운행 고도라고 표현하면 안 됩니다. OSM 형상 스냅샷은 운행 기록일과 다르며, 결과 감사 기록에도 이를 명시합니다.

## 입력 계약과 실패 처리

일반 철도 입력은 `.local/raw/korail/YYYYMMDD-역명.json`의 `records`와 같은 파일명의 `.meta.json`입니다. 각 역마다 선택한 날짜·열차가 정확히 한 행이어야 합니다. 두 행의 `run_ymd`, `trn_no`, `mrnt_cd`, `uppln_dn_se_cd`는 같고 `trn_run_sn`은 1 증가해야 합니다. 순번 누락이 있으면 중간 정차가 없다고 가정하지 않고 실패합니다.

역명은 OSM의 `station=train`, 한국철도공사 운영자와 함께 정확히 대조합니다. 중복·누락 역명은 실패합니다. OSM 선로 모드는 일반 철도 `rail`만 허용합니다. 실제 노드로 연결되지 않은 구간은 직선으로 메우지 않습니다.

기본 선로 스냅 한계는 300m이고, 인접 후보 8개 안에서 **연결 가능한 양끝 스냅 거리 합이 가장 작은 조합**을 먼저 선택합니다. 역 직선거리 100m 미만, 경로 우회비 3.5 초과, 운행시간 0초 이하·2시간 초과, 계산 평균속도 350km/h 초과는 거부합니다. 이 값은 검수 정책이며 원천 데이터가 아닙니다.

지하철 표본은 `5호선`, `서울 지하철 5호선`이라는 OSM 선로 명칭으로 필터링합니다. 필터 없이 광화문 좌표의 최근접 선로를 찾으면 근처 1호선에 잘못 붙을 수 있음을 실제 검증에서 확인했습니다. 전국 확장에는 OSM 노선 관계와 공식 역순서를 함께 대조해야 하며, 단순 최근접 이름 조합으로 확장하면 안 됩니다. 두 심도 기록의 호선이 다르거나 공식 심도가 없는 경우 보간을 거부합니다.

## 프런트 통합 사항

1. `Track.position_evidence=calculation`을 그대로 표시합니다. 공식 출발·도착 기록과 계산 위치를 같은 관측 배지로 합치지 않습니다.
2. 일반 철도 재생은 높이 없는 점을 지상 투영합니다. `coordinate_provenance.display_mode=surface_projection`, `vertical_evidence=unverified`가 들어 있습니다.
3. 지하철 표본의 GeoJSON은 `LineString`의 세 번째 좌표가 타원체고입니다. 지하투시 모드에서는 그 높이를 유지하고, 지상 투영 모드에서는 명시적으로 지면에 투영합니다.
4. 지하철 선형에는 `evidence_type=estimate`가 들어 있습니다. 설명과 양끝 공식 심도 출처를 선택 정보에 유지합니다.
5. 역 심도 점과 선형이 정확히 같은 XY에 놓이지 않을 수 있습니다. 원천 역 대표 좌표와 실제 지도 선형의 차이이므로 숨기거나 임의의 직선 연결을 만들지 않습니다.
