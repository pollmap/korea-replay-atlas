# 비공개 복구본 압축 운영

기존 `.bin`과 새 `.encoded` 객체를 함께 읽습니다. 새 객체는 기존 D1에서 검증한 제한형 zlib/XZ 디코더를 재사용하고, 압축 결과가 작을 때만 저장합니다. 객체의 논리 SHA·원문 바이트 수·과거 head는 바뀌지 않습니다.

`LocalArchive.compact(retire_raw=False)`는 기존 객체를 검증한 뒤 압축본을 추가합니다. `retire_raw=True`는 압축본을 디스크에서 다시 읽고 원문 SHA·바이트를 확인한 객체의 `.bin`만 제거합니다. 원천 XML·수집 DB·head는 삭제하지 않습니다. 실패하면 아직 제거하지 않은 원본은 유지됩니다.

운영 순서:
1. 새 디코더를 사용하는 수집 이미지와 복구 도구를 배포합니다. 수집은 기존 안전 hold에서 유지합니다.
2. 프로젝트 `bulk-work.lock` 아래에서 압축을 실행합니다. 최소 30GiB 여유를 유지하고 다른 프로젝트를 정리하지 않습니다.
3. 모든 현재 head의 객체를 다시 읽고, 표본 복원과 원본 SHA를 검사합니다.
4. 실제 여유 공간을 확인한 뒤 저장공간 hold만 해제합니다. 인증 등 다른 hold는 자동 해제하지 않습니다.

압축 객체가 생긴 이후에는 `.bin`만 읽던 과거 이미지로 복귀하면 안 됩니다. 코드 롤백 시에도 새 디코더를 유지해야 합니다. 같은 디스크의 압축 백업은 서버 디스크 손실을 막는 외부 백업이 아닙니다.

완료된 복원 시험용 폴더는 보존 원본·백업의 전체 해시를 확인하고 시험 기록·체크포인트만 남긴 뒤 정리합니다. 시험할 때마다 원문 전체 복사본을 영구 보관하지 않습니다. 논리 파일 크기와 하드링크를 제외한 실제 회수 공간은 구분해 보고합니다.
