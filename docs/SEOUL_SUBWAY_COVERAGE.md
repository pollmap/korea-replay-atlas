# 서울 원천의 수도권 실시간 도시철도 범위

명세 확인일: **2026-09-19 KST**, 실제 조회 확인: **2026-09-20 00:38:25~00:38:36 KST**. 대한민국 전체 지도 서비스 중 서울시 OA-12601 원천의 공식 명세 16쌍을 등록하고 최종 미리보기에서 모두 1회씩 조회했습니다. 10노선은 현재 역 상태, 6노선은 정상 0건 응답이었습니다.

기존 1호선의 연결 증빙은 [실시간 교통 원천 기록](LIVE_TRANSPORT_SOURCES.md)의 10절에, 이번 16노선은 [최종 미리보기 조회 증빙](../.local/national-upgrade-20260919/preview-subway-final/verification.json)에 있습니다. 비공개 서버는 `270d7204`로 배포했고, 16노선 선택자가 포함된 지도 `da3dfd41`은 미리보기입니다. 공개 지도는 기존 `095795c4`를 유지합니다. 이 목록을 수도권 모든 노선·모든 운행 열차, 또는 전국 도시철도 연결 완료로 해석하면 안 됩니다.

## 공식 근거

1. [서울시 지하철 실시간 열차 위치정보 OA-12601](https://data.seoul.go.kr/dataList/OA-12601/A/1/datasetView.do): TOPIS 원천의 노선별 역 상태 API입니다. 확인 시 화면의 데이터 갱신일은 2026-09-19, 메타정보 수정일은 2025-03-20이었습니다. 갱신일 자체가 모든 메타데이터의 최신성을 보장하지는 않습니다.
2. 같은 페이지가 읽는 [공식 API 명세 화면](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-12601&srvType=A)의 출력 항목 `subwayId`: 아래 16쌍을 명시합니다. 필수 요청 인자는 `KEY`, `TYPE`, `SERVICE`, `START_INDEX`, `END_INDEX`, `subwayNm`입니다. 서비스명은 `realtimePosition`이며 실제 요청에는 ID가 아니라 원문의 노선명을 사용합니다.
3. 페이지의 **명세서다운로드** 버튼: `POST https://data.seoul.go.kr/dataList/down2api.do`, 공개 폼 필드 `infId=OA-12601&infSeq=1&srvType=A`로 받은 문서의 같은 출력 표와 대조했습니다. HTTP 200, 7,804 B, SHA-256 `83e26fc07a432f9bfd80e7c117686c5c9d5f65576334c07ed08b381be1de01f7`입니다. 다운로드 이름은 `서울시 지하철 실시간 열차 위치정보.xls`지만 내용은 UTF-8 HTML 표입니다. 인증키나 로그인은 사용하지 않았습니다.

공식 페이지의 이용허락은 공공누리 제1유형이며 출처를 표시합니다. 공개 명세의 요청 주소는 `http://swopenAPI.seoul.go.kr`입니다. 현재 서버의 명시적 HTTP 원천 허용 정책은 [기존 연결 기록](LIVE_CONNECTION_20260919.md)에 있으며, 이번 목록 확장은 프로토콜이나 TLS 검증 정책을 바꾸지 않습니다.

## 추가 확인이 필요한 범위

서울 열린데이터광장의 활용사례에는 [18개 노선을 소개한 이용자 게시물](https://data.seoul.go.kr/dataVisual/gallery/galleryView.do?bbsCd=10005&ditcCd=APP&seq=4e824910dce3d4b013a16df349a34984&ver=1)과 [19개를 소개한 이용자 게시물](https://data.seoul.go.kr/dataVisual/gallery/galleryView.do?bbsCd=10005&ditcCd=APP&seq=dc68580bafb687635dee8352c0cd328f&ver=1)이 있습니다. 공식 도메인에 게시됐지만 서비스 제공자의 API 코드 명세와는 성격이 다릅니다. 이 주장으로 빠진 ID를 추정하지 않았습니다.

| 대상 | 이번 판단 | 추가로 필요한 근거 |
|---|---|---|
| 경강선·서해선·신림선 | 확인한 OA-12601 출력 코드 표에 없어 미등록 | 제공기관의 현재 노선명·ID 명세 또는 제한된 공식 원천 응답과 정합 검증 |
| 김포골드라인·의정부경전철·용인경전철 등 | OA-12601 연결 여부 미확인 | 해당 제공자의 현재 공식 지원 범위와 이용 가능한 원천 |
| 인천 자체 도시철도 노선 | 서울 원천이 일부 수도권 운행을 포함하는 사실과 별개로 미연결 | 인천 원천의 공식 실시간 계약과 노선·역 식별자 |
| 부산·대구·광주·대전 등 다른 도시철도 | 이번 서울 원천 확장에 포함되지 않음 | 지역별 공식 원천·권한·식별자·관측 의미·요청 예산 검증 |
| KTX·일반열차·화물열차 | 도시철도 역 상태 API 범위 밖 | 전국 철도 원천의 별도 계약과 실제 운행 자료 |

노선명이 등록됐어도 해당 노선의 모든 구간·운영기관·분기·열차가 반환된다는 근거는 아직 없습니다. `empty`는 해당 조회에서 원천이 0건을 반환한 상태이며, 미지원·장애·인증 오류와 구분합니다. 역 상태를 3D 선로 위에 임의 보간하거나 좌표를 발명하지 않습니다.

공개 목록의 `configured: true`는 브로커에 원천 키가 설정됐다는 상태입니다. 이 값만으로 해당 노선의 현재 차량 응답을 검증했다고 판단하지 않습니다.

## 시간과 위치 필드의 의미

공식 출력 표의 노선·역·열차 식별 필드는 `subwayId`, `subwayNm`, `statnId`, `statnNm`, `trainNo`입니다. 수신 날짜/시간은 `lastRecptnDt`, `recptnDt`, 방향은 `updnLine`, 종착역은 `statnTid`, `statnTnm`, 열차 상태는 `trainSttus`입니다. 급행·특급 구분 `directAt`와 막차 구분 `lstcarAt`도 문서에 있으나 현재 공개 차량 계약에는 이를 추가하지 않았습니다.

현 구현은 `recptnDt`를 KST로 검증해 `source_received_at`에 보존합니다. 방향 0/1과 상태 0/1/2/3을 명시된 의미로 해석하고, 5분 초과 수신 자료·미래 30초 초과 자료·모호한 중복을 구분합니다. 서버 조회·응답 시각은 별도입니다. 센서 측정시각과 GPS 좌표를 제공한다는 근거가 없으므로 `observed_at: null`, `position: null`, `station_mapping: "unresolved"`를 유지합니다.

## 공유 예산과 공개 전 검증

기존 중앙 브로커의 서울 원천 정책은 **일일 기준 1,000회, 보수적으로 집계하는 공용 예산 800회, 노선별 캐시 120초**입니다. 16노선이 같은 예산을 나눠 쓰며 노선당 800회가 아닙니다. 공식 문서의 “한 요청 최대 1,000행” 제한과 일일 요청 횟수는 서로 다릅니다. 현재 조회는 한 노선당 최대 400행, 원천 HTTP 요청 1회로 제한합니다.

목록을 제공한다고 모든 노선을 자동 조회하지 않습니다. 가령 16노선을 하루 내내 120초마다 새로 조회하면 산술상 11,520회가 필요하므로 현재 공용 예산에 맞지 않습니다. 사용자가 고른 노선만 조회하고 캐시·동시 요청 병합·원천 요청 전 예약을 그대로 적용합니다. 과거 운행 자료를 연속 보관하는 기능은 없으며 `continuous_collection: false`입니다.

설정은 [지도 Worker](../worker/index.ts)와 [비공개 브로커](../worker/live-broker-entry.ts)가 함께 읽습니다. 공개 지도만 새 목록으로 배포하면 이전 브로커가 새 노선을 거부하므로 **양쪽 코드에 같은 설정을 반영**해야 합니다. 기존 1호선 선택자는 유지되고 브로커의 고정 Durable Object·요청 예산도 유지됩니다.

로컬 회귀는 [subway-config.test.ts](../tests/subway-config.test.ts)에서 공식 16쌍·공개/원천 ID 중복·기존 별칭을 검사합니다. 실제 HTTP를 보내지 않는 fixture로 각 공개 선택자가 브로커를 거쳐 정확한 원천 이름을 요청하고, 16건이 하나의 공용 카운터에 기록되는지, 재조회가 예산을 늘리지 않는지, 모든 차량의 좌표·관측시각이 `null`인지 확인합니다. 이 테스트는 실제 노선별 현재 응답을 대신하지 않습니다.

이번 변경의 `vitest run tests/subway-config.test.ts` 3개, 해당 파일 ESLint, `npm run typecheck`가 통과했습니다. 문서의 로컬 링크 6개도 존재를 확인했습니다.

최종 운영 검증은 노선별 1회, 재시도 0회로 실행했고 정상 HTTP·노선 ID·수신시각·건수·공용 예산·120초 캐시·좌표 및 관측시각 null 계약을 모두 통과했습니다. 키와 키 포함 URL·차량 원문은 기록하지 않았습니다. 0건은 해당 조회의 빈 응답이며 운행 종료나 미지원 판정이 아닙니다. 최상위 `INFO-200`을 정상 빈 응답으로 처리한 수정과 최초 오류 확인 과정은 [이번 변경 기록](STREAMING_AND_SUBWAY_EXPANSION.md)을 따릅니다. 공개 지도 전환과 새 버전의 롤백은 별도로 남아 있습니다.
