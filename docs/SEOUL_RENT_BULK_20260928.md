# 서울 전월세 공식 연도 ZIP 검증 — 2026-09-28

## 판정

서울 열린데이터광장 OA-21276의 **2011~2025년 공개 ZIP 15개 모두 다운로드·전체 파싱·CRC 검증을 완료**했다. 원본 합계 121,828,697바이트에 전체 7,224,000행, 아파트 2,897,895행, 오피스텔 694,639행이 있다. 이는 파일 행 수로, 중복·취소 검증을 마친 고유 거래 건수가 아니다. 서울 과거 전월세의 초기 확보를 빠르게 하는 독립 원천 후보다. 다만 거래별 영구 ID, MOLIT 단지 ID, 취소·해제·정정 필드가 없으므로 **현재 MOLIT 수집 완료 상태나 거래 이력의 동등한 대체물로 사용할 수 없다.** 아직 서비스에 연결하거나 기존 자료와 합산하지 않았다.

2025년 원본에는 접수연도와 다른 계약연도, 완전히 같은 23개 필드의 반복 행이 존재한다. 이들을 계약연도별 파일이라고 취급하거나 내용 해시로 자동 중복 제거하지 않는다. 원천의 한계를 보존하는 별도 계약과 검증이 필요하다.

## 공식 출처와 권리

- [서울시 부동산 전월세가 정보 OA-21276](https://data.seoul.go.kr/dataList/OA-21276/A/1/datasetView.do): 국토교통부 공개자료를 연계한 서울시 자료. 공공누리 1유형, 출처표시 조건으로 상업적 이용·변경 가능. 원문은 FILE 탭을 빠른 다운로드 방법으로 안내한다.
- 페이지에서 확인한 범위는 2011~2025년 ZIP 15개다. 초기 2개 검사 후 나머지 13개도 다운로드했으며, 최종 결과는 아래 전체 연도 확보표에 기록했다. Sheet는 당년·최대 1,000건, API는 최근 3년만 제공한다는 안내가 있어 과거 확보에는 첨부파일이 적합하다.
- 페이지의 데이터 갱신일과 첨부파일 수정일은 다르다. 이번 2011 첨부 수정일은 **2022-05-18**, 2025 첨부 수정일은 **2026-02-04**다. 페이지에 매일 갱신한다고 표시되어 있어도 오래된 ZIP까지 최신 정정을 반영했다고 간주하지 않는다.
- 국토부 RTMS 웹 시스템의 자동추출 경로는 사용하지 않았다. 별도 서울시 공식 첨부파일에 노출된 다운로드 동작만 사용했다.

## 초기 2011·2025년 다운로드와 보존

공식 페이지의 `downloadFile('24')`(2011), `downloadFile('40')`(2025) 링크 및 같은 HTML의 `frmFile` 폼을 확인했다. 폼이 안내한 다음 경로로 파일만 읽었다. 신청·등록 요청이 아니다.

```text
POST https://datafile.seoul.go.kr/bigfile/iot/inf/nio_download.do?&useCache=false
infId=OA-21276&seqNo=&seq=24&infSeq=3   # 2011
infId=OA-21276&seqNo=&seq=40&infSeq=3   # 2025
```

원본·출처 HTML·요청 메타데이터·수집시각·내용 SHA·분석 요약은 로컬 전용 `.local/seoul-rent-bulk-20260928/`에 보존했다. 키·로그인 세션은 사용하지 않았다. 원본 주소·건물명 등 개별 행은 이 문서에 전재하지 않는다. 신규 폴더를 생성했으며 기존 파일을 덮어쓰거나 삭제하지 않았다.

ZIP 구형 파일명 인코딩 차이는 멤버 이름으로 경로를 생성하지 않아 영향을 주지 않는다.

## 연결 설계와 남은 검증

1. **별도 출처 계약:** `seoul-rent-bulk` 원천으로 관리하고 OA-21276, ZIP SHA, 첨부 수정일, 내려받은 시각, 인코딩, 원본 멤버와 행 번호를 보존한다. `ZIP SHA + 멤버 + 행 번호`는 파일 내부 출처 식별자일 뿐 영구 거래 ID로 표시하지 않는다.
2. **계약월로 재분할:** 원천 접수연도는 유지하면서 실제 계약일로 월별 뷰를 만든다. 2025 파일 하나를 받았다고 2025년 계약 자료 전체가 완료됐다고 판정하지 않는다. 인접 접수연도 파일과 공표 범위 확인이 필요하다.
3. **정밀 정규화:** 돈은 원천 만원 단위를 별도 보존하며 정수 원화 변환, 면적·날짜·지역코드 검증을 수행한다. 빈값은 미확인으로 남긴다. 코드 결측·날짜 불일치·반복 행을 별도 감사한다. 이번 작업은 헤더·형식·분포 검증이며 금액과 면적 전수 의미 검증까지 마친 것은 아니다.
4. **단지 연결:** 기관 ID가 없으므로 법정동·지번·건물용도·건물명 등 다중 근거를 검토한 연결 테이블이 필요하다. 동명 단지나 모호한 다대다 연결은 확정 위치로 채택하지 않는다.
5. **중복·취소 경계:** 기존 MOLIT API 거래와 자동 합산·내용 해시 중복 제거하지 않는다. 원천끼리 같은 기간을 비교한 뒤 식별 불가 사례를 남기고 사용자 통계에서 이중 계산하지 않는 정책이 필요하다. 취소 확인이 불가능한 자료를 취소 검증 완료로 표시하지 않는다.
6. **화면 상태 분리:** 공식 연도 파일 확보, 정규화 완료, 단지 연결, 계약월 확보, 취소·정정 검증을 각각 기록한다. 현재 수집 장부의 `complete`를 이 파일 도착만으로 변경하지 않는다.

## 공간과 속도 판단

두 공식 다운로드로 서울 2개 접수연도의 1,401,008행을 확보했다. 매 구·월마다 API를 호출하는 방식보다 초기 전송 요청 수를 줄이는 경로는 실제 존재한다. 단, 같은 계약기간·취소 상태·단지 ID 범위가 아니므로 동등 자료의 속도 배수는 측정하지 않았다.

보존 원본은 ZIP 30.28MB이고 비압축 텍스트는 194.68MB다. ZIP 원본 하나와 체크섬·파서 버전·행 위치를 보관하고 파생 산출물을 다시 만드는 방식이 공간상 유리하다. 현재 아카이브가 사용하는 zlib 이후 Base64 저장에 이미 압축된 ZIP을 넣으면 추가 압축 이득은 작고 Base64 크기는 약 4/3로 증가할 수 있다. 파생 JSON·색인·스냅샷도 추가 공간을 차지하므로 이 두 파일만으로 9개 권역 전체가 남은 저장 한도에 들어간다고 추정하지 않는다.

공식 서버의 파일이 나중에 변경될 수 있으므로 URL만 남기는 것은 원본 보존을 대체하지 못한다. 기존 원본·스냅샷 삭제, 아카이브 구조 변경, 원격 수집 변경은 수행하지 않았다. 이후 추가 승인된 2012~2024년 원본 확보 결과는 다음과 같다.

## 2011~2025년 원본 확보 최종 결과

공식 페이지에 실제 노출된 15개 연도 첨부파일을 모두 확보했다. 신규 13개는 `.local/seoul-rent-bulk-remaining-20260928/`에 보존했고 기존 두 ZIP·기존 감사 파일은 변경하지 않았다. SHA·공식 다운로드 URL·POST 폼 값·첨부 수정일·수집시각·원문 페이지 SHA는 각 연도의 `*-download.json`에 있다. 전체 파싱 결과는 `*-analysis.json`, 최종 13개 검증 결과는 `report-after-encoding-check.json`, 기존 2개를 포함한 전체 요약은 `final-2011-2025-summary.json`이다. 초기 인코딩 실패와 중간 보고서도 남겨 최종 복구 과정을 확인할 수 있다.

추가 수집은 **연도별 한 개 파일을 하나의 배치**로 진행했다. 각 배치 최대 다운로드 40MiB·비압축 512MiB·ZIP 멤버 100개를 유지했고 요청 사이 최소 1.2초를 두었다. 다운로드 실패는 최대 3회 재시도하며 원본 덮어쓰기 없이 시도별 파일을 보존하는 체크포인트 경로를 마련했다. 이번 실제 HTTP 다운로드 실패는 없었다. 추가 13개 ZIP은 91,550,361바이트다. 전체 연도의 누적 압축해제 크기는 1,006,798,997바이트로 512MiB보다 크지만, 디스크에 해제하지 않고 연도별 한 파일씩 스트리밍 검증하여 배치별 상한을 준수했다.

모든 파일은 같은 23개 헤더, 경로 안전성 검사·전체 CSV 행 길이 검사·ZIP CRC 검사를 통과했다. **2023년만 UTF-8(BOM 대응), 나머지 14개는 CP949**다. 2023년 CP949 디코딩 실패 후 헤더로 인코딩 차이를 확인하고 기존 ZIP을 UTF-8로 재검증했다. 문자를 무시하거나 대체하여 통과시키지 않았다. 추가 13개 연도의 아파트·오피스텔 계약일 형식 오류는 0행이다.

### 추가로 확인한 원천의 제약

- **파일 연도·접수연도·계약연도를 각각 보존해야 한다.** 2022 파일의 전체 행은 접수년도 2022년 554,241행, 2021년 50행, 2023년 6,374행으로 섞여 있다. 그 파일의 아파트 계약일은 모두 2022년이다. 다른 연도의 파일 이름 규칙을 일괄 적용할 수 없다. 이 자료는 신고일 필드가 따로 없으므로 접수년도를 계약일 또는 정확한 신고일로 바꾸지 않는다.
- **계약 구분은 문자열 원문을 보존한다.** 2011~2020에는 아파트 신규계약구분이 모두 비어 있고 2021부터 신규·갱신 값이 나타난다. 2024 아파트에는 `1` 368행·`2` 73행도 존재한다. 공식 코드 설명 없이 신규·갱신에 임의 대응하지 않는다.
- **15개 파일 모두 거래별 영구 ID, MOLIT 단지 ID, 취소·해제·정정 필드가 없다.** 과거 시점 원본 확보를 현재 API의 정정 검증 완료와 동일시하지 않는다.
- **내용이 같아도 자동 제거하지 않는다.** 아파트 전체 필드 동일 반복 초과 행은 2024년 1행, 2025년 181,785행, 그 외 연도는 0행이다. 추가 2012~2024 오피스텔에서는 전체 필드 동일 반복 초과 행이 0행이다. 기존 2011·2025 오피스텔의 반복 검사는 이번 범위에서 별도로 수행하지 않았다. 파일 사이 중복 및 MOLIT 데이터와의 중복은 검증하지 않았다.
- **raw 확보 완료의 범위는 공개 첨부 2011~2025년 15개 파일이다.** 모든 실제 계약의 확보, 최신 취소 반영, 단지 연결, 2026년 계약월 전체 확보, 타 지역 확보, 서비스 공개 완료를 의미하지 않는다. 2025 파일에 일부 2026년 계약이 있어도 2026년 전체 자료로 승격하지 않는다.
- 원본은 압축 상태로 약 121.83MB이며, 단지 연결·정규화·색인·게시 스냅샷 공간은 별도로 필요하다. 9개 권역 전체를 현재 무료 원격 저장 용량 안에 보관할 수 있는지는 아직 판정하지 않았다.
