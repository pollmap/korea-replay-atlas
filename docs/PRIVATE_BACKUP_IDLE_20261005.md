# 변경 없는 수집 실행의 백업 재사용

기존 VPS 수집기는 요청 0건이어도 압축 원본 전체의 백업을 반복했다. 변경 없는 실행에서는 과거 검증된 백업 head와 논리 체크포인트를 비교하고 재사용한다.

- 비교 대상은 스키마와 모든 테이블 행이다. 임시 수집 lease만 제외하며 호출 예산, 계획, 원본·snapshot 참조, 재시도 장부는 포함한다.
- 첫 실행은 해시가 검증된 백업에서 checkpoint.sqlite만 복원해 비교한다. 이후 동일 fingerprint·head·cache version이면 작은 head와 현재 체크포인트만 확인한다.
- 현재 source DB는 WAL 안전한 읽기 전용 트랜잭션을 사용한다. immutable 옵션은 복원한 변경 불가능한 임시 백업 DB에만 사용한다.
- API 요청·실패 재시도·실제 장부 변경은 기존 백업을 계속 실행한다. 백업 head 누락·변경·손상은 동일 실행으로 성공 처리하지 않는다.
- 128MiB 체크포인트 캐시 예산을 넘으면 기존 백업으로 돌아가며 수집을 중단시키지 않는다. 새 30GB 조건이나 원본 삭제는 도입하지 않는다.
- 이 개선은 백업 head를 삭제하거나 과거 버전으로 되돌리지 않으며 자동 공개 게시를 구현한 것으로 계산하지 않는다.

서버 배포는 수집기가 대기 중임을 확인한 후 collector 서비스만 갱신한다. API와 다른 VPS 프로젝트는 변경하지 않는다. 변경 없는 재시작 실행과 현재 공개 런타임을 확인하고 별도 결과를 기록한다.
