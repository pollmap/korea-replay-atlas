## 구현과 사전 검증

- VPS 기준 디스크 145GiB 중 약 46GiB 사용, 약 100GiB 여유, RAM 약 5.9GiB 가용을 확인했습니다. 기존 Hannun·hongong-learning·gateway의 올바른 health URL에서 정상 응답을 보존했습니다. 기존 failed systemd unit 3개는 이번 작업 이전 상태이며 수정하지 않았습니다.
- 고유 localhost 8437(컨테이너 8330), Compose `korea-replay`, 서비스 경로 `/srv/services/korea-replay`, TLS 도메인 `korea-replay.62-171-141-206.sslip.io`를 준비했습니다. 사전 선정한 8330은 다른 작업이 전환 중 먼저 사용했으므로 다른 서비스를 보존하고 재선정했습니다. 무료 인증서의 자동 갱신과 해당 도메인의 Nginx reload hook을 설정했습니다.
- Python 3.13 slim 이미지 digest를 고정하고 API 768MiB/0.5CPU, 수집기 1GiB/0.75CPU, 로그·healthcheck·network 격리를 적용했습니다. 인증키는 파일 600·상위 디렉터리 700으로 저장하며 코드·이미지·출력에 포함하지 않았습니다.
- CAS closure streaming과 SHA 영수증은 노트북에 두 번째 대용량 파일을 만들지 않습니다. 서버에서는 링크·경로·중복·크기·객체 SHA, manifest closure, 전체 복원 파일 SHA, SQLite·원본 참조·호출 기록을 검증합니다.
- 원천별 호출 한도가 찼을 때 다른 원천 수집을 이어가는 필터를 추가했으며, 기존 `_reserve()` 호출 기록 검사는 그대로 유지합니다. 인증/원천/해시 오류는 hold로 중단하고 마지막 성공본을 보존합니다.
- 타입·린트·프로덕션 빌드, 웹 1,141테스트 통과. Python 전체 검사 1,328통과·2skip·기존 경고 4개에 더해 최종 VPS 전환 관련 30테스트 통과. 새 CAS streaming·수신 영수증 일치·복원·잘못된 closure·실패 latch·수동 재시작 보호를 별도로 검사했습니다.
- 공개 전체 이력 119커밋·2,366blob 감사에서 자동 비밀키/개인정보 발견 0. 패턴 검사는 절대적인 비밀정보 부재 증명이 아닙니다.

## 실제 VPS 복원·HTTPS 검증

- 이전 SHA: `09400664e246ed1e5f9a322fe347e8216f42335a121ea340e3565a481486b193`, 송수신 전부 일치. 1,119,646,755바이트의 gzip closure에 검증 객체 5,444개가 포함됩니다. 노트북에 중간 대용량 복제 파일을 저장하지 않았습니다.
- VPS 새 장부에 35,919파일·5,860,624,472바이트 전부 복원, 기존 호출 17,525회·snapshot 17,177개·장부 참조 34,134개 일치. 원본·거래·장부·과거 snapshot을 축소하거나 삭제하지 않았습니다.
- API와 collector의 healthcheck 정상, 소스 `6af5e3c`, localhost 8437. API HTTPS `/health`, `/api/v1/property/acquisition` 응답 200을 확인했습니다. 송파 202609 매매 snapshot 총 35행에서 요청한 1행만 반환했고, 200610 매매는 `pending`/null, 같은 월 전월세는 `source_unavailable`/null입니다. 비밀·원본·누락 경로는 JSON 404, 대표 Pages CORS를 확인했습니다.
- 기존 Hannun 8210·hongong-learning 8320·gateway 8090의 올바른 health 응답은 전후 200입니다. 새 8330 점유 서비스를 수정하지 않고 8437로 격리했습니다. 공용 서비스 장부는 append로 추가했으며 다른 등록 항목을 덮어쓰지 않았습니다.
- PC 공개 앱에서 전국→서울→송파구→가락동의 목록·조건 유지·가격 표식 조작을 확인했습니다. 새 sslip.io API의 인앱 브라우저 탐색은 `ERR_BLOCKED_BY_CLIENT`로 제한됐으므로 브라우저 인증을 우회하지 않았습니다. 해당 API는 표준 TLS 검증을 유지한 HTTPS 클라이언트와 Nginx/컨테이너 상태로 검증했습니다. 이 제한을 API의 브라우저 검증 완료로 표시하지 않습니다.
- 노트북 예약은 비활성, 수동 wrapper에 `collector_owner_moved_to_vps` fence를 적용했습니다. 서버만 활성화하며 GitHub 수집은 비활성입니다. 첫 서버 실행의 신규 39회 원천 응답이 정상 검증됐고 hold는 없습니다. 이는 첫 전체 실행/백업 완료나 새 데이터 공개를 뜻하지 않습니다.
