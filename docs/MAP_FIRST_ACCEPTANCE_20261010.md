# 지도 중심 PC 탐색 개선 검수

2026-10-10. UI 후보 검증과 공개 데이터 확보는 별도 판정한다.

## 구현

- 1280~1919px는 목록340px 또는 상세360px, 1920px부터 목록240px+상세400px. 좁은 PC는 접힌 목록으로 진입하며 검색과 공통 조건은 유지한다.
- 상세 중복 버튼을 제거하고 검증된 외부 단지 원문 링크를 상단에 배치한다. 주소 확인 없는 단지는 명확한 주소 검색만 제공한다.
- 헬리오시티만 국토부 단지 ID, 송파구 가락동913, 네이버 단지111515를 실제 페이지에서 대조했다. 동명 부천 단지는 별개이며 자동 결합하지 않는다. 예산과 면적은 외부 사이트에 전달하지 않는다.
- 목록에서 실제 후보 수와 검증 위치 연결 수를 구분한다. 미완료 조회를 0건으로 표시하지 않는다.
- 선택이 조건 밖이어도 상세와 과거 거래를 유지하며 목록 결과에 근거한 상태를 표시한다. 오래된 조건의 비동기 결과는 현재 판정에 사용하지 않는다.
- 지도 조건 갱신 중 이전 표식 자료를 유지하고, 선택 위치는 실제 패널 폭을 제외한 영역으로 이동한다. 다른 지역·릴리스·거래 미연결 점을 현재 후보로 계산하지 않는다.
- 배포 전환 직전에 현재 앱과 데이터 pin을 다시 확인하는 guard를 추가했다. Cloudflare의 원자적 CAS가 아니므로 모든 게시자가 공통 VPS 잠금을 사용하는 것이 전제다.

## 실제 PC 검수

| 화면 | 기본 상세 패널 | 고정 UI 제외 지도 면적 |
|---|---:|---:|
| 1280×720 | 360px | 62.69% |
| 1366×768 | 360px | 64.82% |
| 1600×900 | 360px | 69.58% |
| 1920×1080 | 640px | 60.99% |

상단92px와 고정 패널을 제외한 직사각형 면적/전체 뷰포트로 계산했다. 임시 필터 창과 작은 지도 조작 버튼 면적은 별도다. 가로 넘침 없음. 1280×720에서 마지막 밀도 수정 후 차트 하단557.5px, 첫 거래 행 하단697.4px를 확인했다.

- 980×720 초기 진입은 목록 접힘, 검색·조건 유지, 목록 열기 정상.
- 가락동·국평·12억 이하·36개월: 후보13, 검증 위치0. 위치 없는 원인은 공개 연결 부족이며 렌더링 완료로 해결됐다고 하지 않는다.
- 우정에쉐르→주소 검색, 비교 담기→목록→주성파크빌→비교2개에서 예산·지역·면적·기간 유지 확인.
- 검색에서 서울 송파와 부천의 동명 헬리오시티가 전체 주소로 구분됨. 송파 선택시 기존12억 조건을 유지하고 조건 밖 표시, 과거29억 거래와 상세 보존.
- 브라우저 콘솔 표본 오류 없음. 일부 IAB 세션 종료 및 Chrome 스크린샷 타임아웃은 검수 도구 제한으로 기록한다.

## 검증과 남은 조건

전체 프론트 테스트에서1214개 통과·1개 기존 메타데이터 목록 건수 회귀를 발견했다. 해당 수정 후 관련44개, 배포충돌3개, 타입·린트·프로덕션 빌드 통과. 전체 CI는 PR에서 다시 확인한다.

이 변경은 위치832개 연결을 새로 늘리지 않는다. 모든 단지 위치·관리비·학교·지역지표 연결, 지도 범위 재검색, 정정분 전체 자동 공개, 모든 게시자의 공통 잠금·예약 정리, 운영 날짜 전환·성능 P95 측정은 남아 있다. 일반 앱과 별도 collection, 기존 거래 원본·2D 자산을 보존한다. 전체 무누락·무유출·경쟁서비스 동등성을 선언하지 않는다.
