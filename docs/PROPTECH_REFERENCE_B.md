## 레이아웃과 사용자 흐름에서 가져올 점

### 리치고: 지역과 단지를 오가는 비교

공식 홈은 지도, 지역별 정보, 두 단지 비교, 경매·청약 등 목적별 진입을 나눕니다. 소개상 지역 단계에서 가격·거래·인구·일자리를 비교하고 단지 단계에서 면적별 가격과 주변 생활 정보를 확인할 수 있습니다. 현재 PC 지도의 패널 배치와 실제 전환 동작은 확인하지 못했습니다. [공식 서비스 소개][R1]

**우리 흐름 제안:** 전국 검색 → 지역 요약 → 단지 선택 → 동일 면적 거래 → 비교함. 지역 평균과 특정 평형 거래를 한 수치처럼 연결하지 않도록 비교 단위를 고정합니다. 지도 위 숫자는 사용자가 선택한 지표 하나를 우선 표시하고 나머지는 상세 패널로 옮깁니다.

### 마당: 가격보다 사건의 상태를 먼저 읽는 탐색

주소/사건 검색과 경매·공매·일정·결과 메뉴를 제공합니다. 지도에서는 단계 제어가 검색과 함께 드러나고, 목록에는 최저가뿐 아니라 기일과 유찰·주의 표식이 배치됩니다. 이는 일반 매물 탐색과 다른 상태 중심 정보 구조입니다. [홈][M0] · [지도 검색][M1] · [검색 목록][M2]

2026-07-21 공지는 물건 상세에서 수요·공급, 정비사업, 교통·생활시설, 규제 등을 AI가 정리한다고 설명합니다. 이는 **지역 설명 기능 확인**이며 개별 문장의 원문 근거·최신성·권리분석 정답 여부까지 확인한 것은 아닙니다. [AI 지역분석 공지][M3]

**우리 흐름 제안:** 지역 → 사건 상태·일정 → 대상의 공식 원문 → 인근 거래 비교. 사건번호와 원문 연결을 유지하고, 상태 변경·기일 변경·자료 미수신을 명시합니다. AI 요약을 법적 권리판정이나 낙찰 수익 보장으로 제시하지 않습니다.

### KB부동산: 가격의 성격을 구별하는 비교

공식 앱 설명은 KB시세·실거래·공시·매물 가격을 구분하고 입지와 단지 커뮤니티를 별도 기능으로 소개합니다. 무료 다운로드 표시는 확인했지만 모든 부가 기능과 외부 데이터 사용권이 무료라는 뜻은 아닙니다. [국민은행 공식 앱 설명][K1]

2023.07 가이드의 16~17쪽에는 조건/가격/면적 필터 → 지도 마커·범례와 정렬 목록 → 단지·면적 선택 → 가격 종류별 시계열 비교 흐름이 설명됩니다. 11쪽의 위성·지형·지적·거리측정, 19~20쪽의 테마 지표는 과거 레이어 설계 참고입니다. **현재 PC 화면을 재현한 관찰이 아닙니다.** [KB 공식 데이터허브 가이드][K2]

**우리 흐름 제안:** ‘최근 실제 계약’, ‘현재 호가’, ‘조사 시세’, ‘모델 추정’을 다른 표식과 범례로 표시합니다. 첫 차트는 같은 거래유형·면적대의 관측값과 거래건수로 시작하고, 기준이 다른 지표의 결합은 사용자가 선택하게 합니다.

### 지구: 경계·용도·단계를 함께 읽는 공적 지도

지도 본문은 일반/위성 전환, 거리·면적 측정, 인쇄와 용도 범례를 제공합니다. 사업 단계는 지정·개발계획·실시계획·부분준공·준공으로, 철도·도로는 현행·계획·공사 중으로 나뉩니다. 사이트는 자료가 실제와 다를 수 있고 현재의 정확한 사업 정보는 시행자에게 확인해야 한다고 안내합니다. [지도 메뉴·범례·안내][J0]

**우리 흐름 제안:** 검색 → 사업 경계 선택 → 현재 단계와 기준 고시일 → 원문/시행자 → 주변 기존 도시 비교. 계획 도형과 완공 시설은 다른 선·면 스타일을 사용합니다. 사업 경계를 모든 도시계획 규제의 완전한 경계로 해석하지 않습니다.

## KOREA REPLAY 도입 순서와 완료 기준

아래는 이번 조사로 제안하는 구현 순서입니다. 원천 API 사용권이나 데이터 확보가 이미 완료되었다는 의미가 아닙니다. 전국 조회 구조를 먼저 마련하고 검증된 데이터 범위를 명시해야 하며, 몇 도시의 표본을 전국 완료로 표시하면 안 됩니다.

| 우선순위 | 실제 사용자 결과 | 필요한 구현·데이터 | 완료 기준 |
|---|---|---|---|
| P0 | 전국 어디든 주소·단지를 찾아 후보를 좁힘 | 주소/건물/단지 식별자 분리, 행정구역·거래유형·면적·기간 필터, 지도와 결과 목록 연결 | 동명이름·복수 건물·경계 지역 테스트. 미확인 단지는 빈 값을 명시하고 인접 건물에 임의 연결하지 않음 |
| P0 | 가격 근거를 이해함 | 허용된 공식 실거래 원천, 계약일/정정·해제 상태, 면적·층·유형, 출처·관측일·수집일 | 원문과 대조한 기록만 게시. 관측 공백·표본 부족·서로 다른 가격 개념을 구별 |
| P0 | 개발계획과 이미 있는 도시를 구별함 | 지구의 허락 확인된 사업/계획 파일, 사업 식별자·경계·단계·고시일·원문 | 실제 파일의 코드표·CRS·형상·중복 검수. 계획을 현재 건물·운행 시설로 표시하지 않음 |
| P1 | 후보 2~3곳을 비교함 | 동일 면적대·기간의 가격 차트/거래수, 생활시설 접근성, 비교함 | 조건·단위·자료 시점을 양쪽에 고정. 다른 표본 구성이 가격 변화처럼 보이지 않도록 설명 |
| P1 | 경매·공매 대상을 근거까지 확인함 | 공식 이용 가능한 사건 목록·상태·기일·원문, 변경 이력 | 재조회와 상태 변경 검증. 권리분석 확정·수익 보장 표현 없이 원문과 불확실성 제공 |
| P2 | 시세/예측·알림·분석을 확장함 | 필요한 경우 정식 데이터 계약, 자체 통계/모델 검증, 개인정보·알림 운영 설계 | 시계열 분리검증·오류 범위·라이선스·운영 비용이 확인된 기능만 공개 |

첫 화면은 **지도 + 검색 + 선택 조건 요약**을 중심으로 두고, 상세 패널은 선택한 대상이 있을 때 펼치며 접을 수 있게 합니다. 입문자에게는 거래유형·예산·면적을 먼저 보이고, 상세 필터·비교·출처 이력은 한 단계 뒤에 둡니다. 전국을 먼저 탐색할 수 있게 하되 전국 원본을 한 번에 브라우저로 보내지 않습니다.

지역·단지의 작은 인덱스와 상세 기록을 분리하고 지도 범위/축척에 맞춰 조회합니다. 원천 이름, 데이터셋 버전, 원본 ID, 대상 기준일, 수집일, 라이선스 식별자, 매칭 방법을 저장하는 계약이 필요합니다. 동일 이름·인접 위치만으로 단지·건물·필지를 확정 연결하지 않고, 연결 불확실성을 데이터와 화면에서 유지하는 것이 우선입니다.

## 다음 확인과 미완료 사항

1. 리치고와 KB의 실제 데스크톱 지도는 이후 승인된 브라우저 점검에서 검색→필터→선택→차트→복귀의 흐름과 패널/모바일 동작을 확인해야 합니다. 이번 문서는 현재 픽셀 레이아웃을 확정하지 않습니다.
2. 지구는 **개별 파일 제공 경로와 일부 허락까지 확인**했습니다. 실제 전국 파일 다운로드, 전체 데이터셋 권한·좌표계·버전 결합·지역별 누락률 검사는 다음 데이터 작업입니다.
3. 마당 상세 분석과 유료 기능은 소개·약관 수준만 확인했습니다. 경매/공매 원천을 우리 서비스에 재제공할 수 있는 방식은 별도로 확정해야 합니다.
4. 참고 서비스의 데이터 정확성, 전역 갱신 SLA, 비용 대비 품질과 GPU 성능을 이번 조사에서 비교 측정하지 않았습니다. 위 도입 순서는 기능 수가 아닌 핵심 사용자 흐름과 검증 가능성을 기준으로 한 판단입니다.
