# 전국 3D 공간 데이터 업그레이드 조사

확인일: 2026-09-16. 공개 원문·공식 파일을 확인한 조사이며, 실제 수집 성공·인증 필요·원본 이용심사를 구분합니다. 계정 등록, 로그인 조작, 결제, 약관 동의, 제공 신청은 수행하지 않았습니다.

## 권장 결정

전국 기본 지도를 Overture/OSM으로 계속 구축하면서 **국토교통부 GIS건물통합정보의 건물 외곽·행정대장 높이를 결합**하는 것이 가장 실용적인 정확도 개선입니다. 정밀 건물은 별도 모델로 교체하고, 원본의 출처·기준일·허가 범위를 개별 자산에 기록합니다. 건물 높이 추정치를 실측값으로 표시하지 않습니다.

Google 한국 포토리얼 3D를 가져오면 해결된다는 가정은 현재 공식 커버리지와 맞지 않습니다. S-Map과 VWorld의 정밀 원본은 화면 열람과 재배포 가능한 원본 확보가 다른 절차입니다. VWorld 자체 LoD1도 층수×3m이며 일부 제외 전국 서비스로 설명됩니다. 어떤 제공자도 모든 건물의 현재 형상과 높이에 무오류를 보증하는 근거는 확인되지 않았습니다.

## 즉시 적용 가능한 Overture 부분 건물

공식 현재 릴리스는 `2026-08-19.0`이며, `building.has_parts`와 `building_part.building_id`로 부모·부분 관계를 제공합니다. 단일 외곽을 한 높이로 올리는 현재 모델에서, 부분별 높이가 있는 건물은 그 부분 형상을 먼저 렌더링하고 부모 전체 외곽의 중복 압출을 피해야 합니다. 데이터 획득만으로 복잡한 지붕·파사드·텍스처가 생기지는 않습니다.

```text
s3://overturemaps-us-west-2/release/2026-08-19.0/theme=buildings/type=building_part/*
https://overturemapswestus2.blob.core.windows.net/release/2026-08-19.0/theme=buildings/type=building_part/*
```

완료 조건은 부분의 부모 연결률, 잘못된 높이·중복 면적, 부모와 부분의 중복 렌더링 여부, 타일 경계를 넘는 건물의 일관성입니다. Overture는 자료 누락·ML 추출 오차를 공식적으로 설명하므로, 처리된 건물 수를 한국 전체 실건물 수와 같다고 보고하면 안 됩니다.

후보119개는 **원천 검토 후보이며 아직 지형에 배치하거나 공개하지 않았습니다.** 부모별 후보 수·전체 부분 수·외곽 피복 비율을 기록합니다. 일부 부분만 유효한 부모를 통째로 숨기면 나머지 건물이 사라지므로, 완전 교체와 부분 추가 렌더링을 구분해야 합니다. 층수로 높이를 보충하지 않았고 높이·최소 높이·지붕 속성을 원문 그대로 보존했습니다. 적층 건물은 원천 사양상 수평 외곽이 겹칠 수 있습니다.

이 표본 실행은 전국 수집 이전 단계입니다. 현재 표본 회귀는 7개이며, 아래 전국 모듈과 함께 실행한 결과는 49개 통과입니다. 서울 도심에는 개선 가능성이 있지만 대전역 표본에는 해당 소스의 부분 자료가 없어 전국 정밀건물을 이 소스만으로 채울 수 없습니다.

### 2026-09-19 전국 경계 수집·부모 단위 교체 후보

`pipeline/building_parts_national.py`를 별도로 구현해 실제 실행했습니다. 릴리스 `2026-08-19.0`과 기존 한국 경계 `[124.5, 33.0, 132.0, 38.7]`를 고정합니다. **공개 타일·카탈로그를 수정하지 않는 사설 후보 생성 단계**입니다.

전 세계 `building_part` 원본은 574,884,796bytes / 4,339,150행 / 256개 Parquet row group입니다. 공식 STAC와 footer의 좌표 통계로 한국 경계와 교차하는 4개 구간(166·167·168·186)을 골랐습니다. 이 구간의 판독 상한은 63,889행이며, 원본 URL에 HTTP206과 정확한 `Content-Range`를 요구합니다. HTTP200 전체 파일 응답과 redirect는 받지 않습니다. 원본 압축 구간·footer·STAC·구간별 SHA256을 체크포인트에 보존하며 재시작 시 이미 저장된 구간을 검증해 재사용합니다.

사각 경계에는 한국 바깥의 자료도 들어오므로 16,287개를 한국의 실제 부품 총수로 부르지 않습니다. 연결 실패 3,052개 역시 모두 해외 또는 누락 건물이라고 단정하지 않습니다. 전국 기존 건물 370만 개를 메모리에 올리지 않고 필요한 ID가 있는 115개 셀을 순차 판독했으며, 해당 정규화 파일 약2.05GB만 해시·개수 검증했습니다. 공개 3D 자료 전체10GB를 재해시하지 않았습니다.

부분 높이·지붕 후보 509개도 그대로 공개하지 않았습니다. 부모별로 하나라도 유효 높이·지원 지붕·높이 의미가 미확정이면 기존 부모를 유지합니다. 연결된 그룹에서 유효 원천 높이 결측/오류 부품5,641개, 부모 외곽 포함 부족64개, 하단 높이 없이 `min_floor`만 있는174개를 확인했습니다. 사유는 중복될 수 있으며 이 품질 수치의 분모는 부모에 연결된 부품6,577개입니다. 지붕 모양이 명시되지 않은 부품의 평평한 상단은 단순 압출 표현이며, 실제 평지붕을 확인했다는 뜻이 아닙니다.

후보 판정은 다음 계약을 지킵니다.

1. `building_id`로 같은 릴리스 부모를 정확히 연결하고 원천·정규화 부모 형상이 일치해야 합니다. 근처 건물에 높이를 붙이지 않습니다.
2. 관측된 모든 부품의 높이 의미와 형상이 통과해야 합니다. 원천 좌표계에서 외곽 차집합·교집합을 계산한 뒤 EPSG:5186으로 면적을 측정해, 좌표변환으로 생기는 가짜 틈을 피합니다. 허용 면적 오차는 부동소수점 연산용 `0.000001m²`이며 원본을 자르거나 메우지 않습니다.
3. 부모 외곽을 완전히 덮고 외곽 밖으로 나가지 않아야 하며, 부품끼리 실제 높이 구간이 겹치는 부피 중복도 보류합니다. 단지 평면이 겹친다는 이유로 정상적인 수직 적층을 금지하지는 않습니다.
4. 현재 공개 `pub-a55c6a081e5782db`의 원격 카탈로그와 로컬 건물 root ID·URL·릴리스·개수·SHA256을 비교했습니다. root SHA256은 `67d3eb563703f4644727b35876bb4d5603544f4a552ba74fdf88214b1b61866f`입니다. 선택한 기존 detail GLB에서 각 후보 부모 ID가 정확히 한 번 존재하는 것도 확인합니다. 참조가 다르거나 부모를 찾지 못하면 `published_parent_verified=false`로 남기며 승격하지 않습니다.
5. 부품 ID·부모 ID·원천 높이·`min_height`·지붕 속성·출처를 보존합니다. 지반은 동일 공개 부모의 기존 타원체 기준 바닥고도를 상속하며, 별도 지반 실측 검증으로 표현하지 않습니다. 원천 `min_height=null`을 보존하고 `prepare_candidate_mesh`에서만 표시용 `render_min_height=0`을 기존 메시 계약에 전달합니다.
6. 후보 GeoJSON은 `proposal_only=true`, `render_eligible=false`를 유지합니다. 전체 교체 계획과 원본 ID가 맞는 경우에만 명시적으로 메시 입력을 준비합니다. 향후 공개할 때에는 최종 부모16개를 숨기는 변경과 부품61개 추가를 함께 적용해야 합니다. 단순히 부품을 덧붙이면 중복 모델이 됩니다. 논리적 건물 수는 유지하고 렌더 피처 수의 변화 `+45`는 별도로 기록합니다.

형제 누락 가능성은 별도 승인된 **ID 컬럼 전용 검사**로 확인했습니다. 같은 전 세계 원본의 `building_id` 값4,339,150개를 256구간·2,048개 배치로 읽어 해당 부모의 총 부품 수와 bbox에서 확보한 부품 수를 대조했습니다. 예비28개 부모 모두 개수가 일치했습니다. 외곽 피복만으로 완전성을 추정하지 않으며, 개수가 다르거나 전 세계 스캔이 끝나지 않으면 승격을 차단합니다. 이 단계는 ID 스칼라만 읽었고 한국 밖 건물 형상·높이·기타 속성을 추가 수집하지 않았습니다. 원천 객체의 `ETag`를 `If-Match`로 고정해 다른 객체 버전이 섞이지 않게 했습니다.

최고 높이의 원천값 충돌도 추가 검사했습니다. 마포타워의 부모65m/부품 최고52m, 삼구빌딩의 부모74m/부품 최고60m 등12개 부모를 근거 없이 부품값 우선으로 바꾸지 않고 검토로 남겼습니다. 최종16개는 부모·부품 최고 높이가 같은2개 부모와 부모 원천 높이가 없는14개 부모입니다. 후자는 기존 표시용 추정 높이를 유효 부품 원천 높이로 보완할 수 있는 후보이며, 실측 정확성이 확인됐다는 뜻은 아닙니다. 부모와 부품의 높이 일치 허용값은 부동소수점 계산용0.000001m입니다. 이름이 없는 부품은 같은 원천 부모 이름을 표시명으로 사용하고 그 출처를 별도로 남깁니다.

최종 후보로 **부모별 사설 GLB16개 / 부품61개**를 실제 생성했습니다. 총262,072bytes, 최대21,908bytes이며 원본 부품 ID·좌표·전체 속성이 GeoJSON과 일치하고 GLB의 원본 ID·속성·부모 연결도 왕복 보존됩니다. 기존 메시 감사와 Khronos glTF 핵심 검사16개 모두 오류0·경고0입니다. 최대 추가 float32 좌표 반올림 오차는 `0.000011641073m`로 측정됐습니다. 이는 변환 과정에서 추가된 오차이며 현실의 위치·높이 정확도가 아닙니다. 검토 GLB는 공개 계층에 연결하지 않았습니다.

합산 검증 응답은43,844,271bytes, 재시작까지 누적해 예약한 최대 전송량47,661,670bytes, 단계별 최대 프로세스 peak RSS234,549,248bytes였습니다. 수집·후보·ID검사·검토 모델 증빙은 약53.1MB입니다. 설정한64MiB 전송·512MiB 메모리·256MiB 신규 저장·30GiB 디스크 잔여 제한 안에서 완료했습니다. **형상·속성 판독 상한63,889행은100,000행 제한 안이며, 추가 승인된4,339,150개 ID 스칼라 판독과 구분합니다.** 원본 대체·삭제·추가 공식 신청·배포는 수행하지 않았습니다.

## GIS건물통합정보: 실제 어댑터 사양

공식 파일 페이지를 직접 읽은 결과 전체 자료 월간·변동 자료 일간 갱신, SHP 제공, CC BY, 무상공급입니다. 조회 당시 메타데이터는 **14,422,486건 / 6,605MB**, 목록에는 **2026-09-09 서울 전체 SHP 129MB**가 표시되었습니다. 이 수치는 원천 데이터 행 수이며, 중복·도형 분할·대장 관계를 검증하기 전 실건물 개수 또는 Overture 누락률로 환산하지 않습니다.

공식 배포 좌표계는 **2023-08-08 이후 GRS80/EPSG:5186**, 이전 구간은 **Bessel/EPSG:5174**로 안내합니다. 단순히 한국 SHP이므로 5179라고 추정하지 않습니다. 각 다운로드의 `.prj`를 확인하고 `always_xy=True` 변환 후 대한민국 경계·샘플 위치를 검사합니다. 파일 인코딩은 실제 `.cpg`/DBF 표본으로 확인합니다.

높이 문서는 단위 m와 예시 11.95를 제공하지만 지면 기준 상세·옥탑 포함·측정 방식은 정의하지 않습니다. 따라서 **대장 높이를 항공 LiDAR 실측 높이 또는 정밀 지붕 최고점이라고 단정하지 않습니다.** 바닥의 절대고도는 별도 지형/측량 자료가 필요합니다. A16에 지오이드 보정을 직접 더하지 않고, 원천 건물 상대 높이와 지형 타원체 바닥고도를 분리합니다.

병합 절차 제안:

1. 원본 ZIP/SHP/DBF/PRJ/CPG 해시와 행 수를 기록하고 전체·변동을 구분합니다.
2. 미터 좌표계에서 형상 유효성·중복 키·높이 결측/0/음수/비정상 범위를 검증합니다. 0은 지상0m 건물로 렌더링하지 않습니다.
3. 동일 원천 ID 연결을 우선하고, 불가능하면 외곽 IoU·중심거리·면적비·주소를 함께 평가합니다. 최근접 하나만으로 높이를 붙이지 않습니다.
4. 다대일·일대다·높이 충돌은 검토 대상으로 격리합니다. 높이만 공식이고 외곽은 Overture이면 각각의 출처를 유지합니다.
5. 원천이 유효한 건물은 GHSL 평균 높이를 대체하되, 기존 자료를 삭제하지 않고 버전별 교체 이력을 남깁니다.
6. 서울·경기·대전·세종·청주·부산·제주 등의 층화 표본에서 위치, 높이, 경사지 바닥, 부분 건물 중복을 검수합니다.

현재 확보된 것은 공식 문서·목록이며 **건물 SHP 본체는 미확보**입니다. UI의 로그인 요구를 확인했고 직접 다운로드 URL로 로그인 검사를 우회하지 않았습니다. 500MB 이상 파일은 공식 페이지에서 선택 다운로드 도구 사용을 요구합니다. 설치 프로그램 실행은 하지 않았습니다.

## 도로명 건물·랜드마크·참고 저장소

[행안부 전자지도 공식 설명](https://www.data.go.kr/dataset/3033566/openapi.do?lang=en)은 전국 시도/시군구별 자료와 신청·기관 승인 절차를 안내합니다. 건물 외곽을 가진 전자지도와 주소 텍스트 DB를 혼동하지 않아야 합니다. `TL_SPBD_BULD.shp` 등 형상 자료는 로그인 없는 텍스트 주소자료 다운로드와 다른 서비스입니다. 현재 무키·무신청 전국 건물 외곽 SHP 다운로드를 검증하지 못했습니다.

문화유산 랜드마크는 [국가유산 3D 이용 방법](https://www.heritage.go.kr/heri/html/HtmlPage.do?pg=%2FthreeD%2FhowToUse.jsp)과 [국가유산 디지털 서비스](https://digital.khs.go.kr/)를 우선합니다. 일반 모델링·프린팅 자료와 전문가 스캔 원본의 신청 절차가 다릅니다. 실제 확인한 경주 동궁과 월지 상세 화면은 공공누리1유형 표시와 이용신청 UI를 함께 제공했습니다. **현재시점 실측 모델인지 역사 복원 모델인지**를 분리한 후 위치·축척·방향을 검수하여 넣습니다. 현대 랜드마크를 비슷한 자유 모델로 대신하면서 정확한 모델이라고 표시하지 않습니다.

코드 참고는 [V-world 공식 API 예제 저장소](https://github.com/V-world/V-world_API_sample)의 2026 교육, 지형 clipping, GeoJSON 지면 정합, GLB 이동 예제가 유용합니다. 저장소의 코드 공개가 지도 원본의 무제한 재배포 허가를 의미하지는 않습니다. 사용자 키를 요구하는 예제의 타인 키를 가져와 사용하지 않습니다. 현재 프로젝트 Cesium 렌더러는 유지하면서 개념과 공식 API 계약을 적용하는 편이 전면 교체보다 합리적입니다.
