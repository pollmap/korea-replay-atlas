## 제품 범위: 아파트 우선, 오피스텔까지

2026-09-25 최신 지시: 아파트 핵심 제품을 우선 완성하고 오피스텔까지 포함합니다. 수집·연결·화면 개선의 우선 대상은 아파트 단지, 매매·전월세 실거래, 장기 거래 이력, 면적별 가격 추이와 단지 비교입니다. 아래 지역 순위를 두 유형에 적용하되 수집 장부와 통계는 분리합니다.

빌라·연립·다세대·개별 주택의 추가 수집과 일반 건물·작은 도로의 정밀 보강은 현재 우선 개발에서 제외합니다. 이미 확보한 지도 자료는 배경으로 보존하며, 일반 건물 수나 도로 수를 아파트 서비스 완성의 지표로 사용하지 않습니다. 핵심 검수는 아파트 검색 → 단지 선택 → 과거 거래 확인 → 다른 단지와 비교가 실제로 이어지는지로 판단합니다. 기존 수집기는 국토교통부 아파트 매매·전월세 API를 사용하므로 이 결정 때문에 수집 장부를 삭제하거나 바꾸지 않습니다.

## 지역별 수집 순서

| 순위 | 대상 | 현행 조회 코드 수 |
|---|---|---:|
| 1 | 경기도 전체 | 47 |
| 2 | 서울 전체 | 25 |
| 3 | 인천 전체 | 11 |
| 4 | 대전 전체 | 5 |
| 5 | 세종: 36110 | 1 |
| 6 | 청주: 43111·43112·43113·43114 | 4 |
| 7 | 천안: 동남구 44131·서북구 44133 | 2 |
| 8 | 아산: 44200 | 1 |
| 9 | 부산 전체 | 16 |
| 합계 | `priority-nine` | 112 |

범위는 검증된 [법정코드 목록](../config/molit-legal-region-registry.json)의 정확한 코드 112개를 [수집 범위 정책](../pipeline/real_estate_scope.py)에 고정합니다. 동명 지역이나 이름 부분일치로 대상을 추측하지 않습니다. 현재 목록의 인천 11개 구·군과 화성 4개 구도 포함합니다. 행정코드 개편은 목록과 정책을 함께 검토한 후 반영하며, 현재 코드를 과거 지역의 완전한 대체물로 취급하지 않습니다.

같은 순위에서는 최신 완료 계약월 → 당월 잠정 → 과거월 순입니다. 같은 월에는 지역 코드와 거래 유형 순으로 결정론적으로 처리합니다. 경기의 계획 이력을 먼저 처리하고 서울·인천 등 다음 권역으로 넘어갑니다. 월 필터를 명시한 갱신 실행도 선택한 월 안에서 같은 순서를 적용합니다.

자동 수집과 오프라인 계획 workflow는 `--scope priority-nine --require-scope-complete`를 명시합니다. `auto`·`backfill`·`recent`·`history`, 실패 재시도, 정정 대기 재설정, 페이지 예산 검사는 모두 범위 밖 작업을 제외합니다. 범위 밖 실패 때문에 범위 안의 월 완료 커서가 멈추지도 않습니다. 운영 보고서에 목표 112개·실제 코드 수·`missing_codes`를 기록하며, 운영 registry에서 대상 코드가 빠지면 원천 호출 전에 중단합니다. 작은 테스트용 registry는 API 호출 없는 검증에서만 완전성 옵션을 생략할 수 있습니다.

기존 완료/빈 응답/실패 상태, 페이지, 스냅샷, API 호출 장부와 자료 원본은 보존합니다. 복원·월 이월 계약을 유지하기 위해 전국 계획 슬롯은 남기지만 범위 밖 API 호출은 하지 않습니다. 보고서의 `coverage`·`acquisition`은 보존된 전국 장부이고 `scope_coverage`·`scope_acquisition`은 현재 대상만 집계합니다. 기존 명령과 fixture의 호환성을 위해 CLI 기본값과 명시적 `--scope nationwide`는 이전 전국 순서를 유지하지만, 현재 서버 workflow에서는 사용하지 않습니다.

20년 이력 확보·전국 좌표 검증·자동 수집 활성화·새 데이터 공개는 각각 별도입니다. 우선순위 코드 적용과 수집 계획 생성은 데이터 확보 완료가 아닙니다.
