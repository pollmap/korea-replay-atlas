## 이동 중 정적 형상 작업

[StaticWorkGate](../src/static-work-gate.ts)는 카메라가 이동 중이거나 문서가 숨겨졌거나 최신 화면의 필요한 자료 목록이 아직 확정되지 않았을 때 형상 작업을 대기시킵니다. 이동 종료만으로 즉시 재개하지 않고, 새 화면에서 필요한 자료를 정하고 불필요한 요청을 취소한 뒤 해당 revision을 확정해야 재개합니다.

[MapScene](../src/MapScene.tsx)은 Geometry Worker 호출 전과 응답 후, Primitive를 나누어 생성하는 경계에서 이 조건을 확인합니다. 대기 중인 작업도 취소할 수 있고, 화면이나 세션이 바뀐 오래된 결과를 다시 붙이지 않습니다. 공유 CPU 예산의 대기 시간도 작업 실행 시간과 분리합니다. 이 처리는 연결된 정적 Geometry 경로에 적용되며 Cesium 내부의 모든 지형·3D Tiles 작업까지 멈춘다는 뜻은 아닙니다.

부산·인천 이동 후 기록에서 `assetJobs=0`, `cameraMoving=false`, `cameraDetailPending=false`로 회복한 것을 확인했습니다. 이는 해당 방문의 요청·작업이 정리됐다는 확인이며 전국 모든 장소의 완전성 검사나 프레임 목표 달성 증거는 아닙니다. [부산 준비 완료](../.local/map-first-20260919/candidate-busan-ready.json), [인천 준비 완료](../.local/map-first-20260919/candidate-incheon-ready.json).

## Geometry Worker 속성 전송 개선

공통 속성과 행별 속성을 각 피처마다 미리 펼치던 Worker 경로를 바꾸었습니다. Worker에서 압축된 속성 사전과 실제로 참조하는 행만 유지해 전달하고, 좌표는 기존 `Float64Array`의 전송 가능한 버퍼를 사용합니다. 여기서 압축은 중복 속성을 공유하는 데이터 표현이며 네트워크 gzip·Brotli 설정을 바꾼 작업이 아닙니다.

렌더러는 그리는 데 필요한 속성 10개를 읽습니다. 객체 선택 시 원본 ID에 연결된 전체 속성을 복원하고 그 결과를 보관합니다. 도로를 제외해 그릴 때는 남은 피처가 참조하지 않는 속성 행도 전송하지 않습니다. 기존 호출자의 펼쳐진 `compileGeometry` 결과 계약은 유지합니다.

### Node 전송 측정

Node.js `v24.18.0`의 `worker_threads`에서 각 경로를 **9회** 측정한 중앙값입니다. 아래 시간은 요청 전달, 형상 컴파일, 송신·수신 복제와 이벤트 전달을 포함하는 `receivedMs`입니다. 로컬 파일 읽기와 각 Worker의 최초 JSON 해석은 측정 밖에서 수행했습니다. 좌표 버퍼는 전송 방식으로 처리했습니다.

| 대표 입력·표시 조건 | 피처 수 | 이전 중앙값 | 개선 중앙값 | 감소율 |
|---|---:|---:|---:|---:|
| 도로 포함 기반 시설 | 3,992 | 51.603ms | 29.313ms | 43.194% |
| 같은 기반 시설에서 도로 제외 | 100 | 7.979ms | 1.384ms | 82.649% |
| 철도 개략 형상 | 7,748 | 60.822ms | 45.559ms | 25.095% |
| 검토 건물 외곽선 | 1,351 | 30.406ms | 20.886ms | 31.311% |

도로 제외 사례는 원본 속성 행 3,992개 중 사용되는 100개만 전송합니다. 이 결과는 **대표 입력의 Node 작업 왕복 소요 시간**이며 Chrome의 프레임 시간·FPS·GPU 준비 시간 또는 전국 평균이 아닙니다. 초기 실험에서 신뢰성이 없었던 heap 차이 수치는 사용하지 않습니다. [9회 원시 표본과 중앙값](../.local/geometry-transfer-20260919/worker-transfer-final.json), [최종 검증 요약](../.local/geometry-transfer-20260919/final-verification.json).

### 원본 동등성과 선택 정보

대표 기반 시설·철도·건물 외곽선 3개 파일에 대해 도로 포함·제외의 **6개 경로**를 비교했습니다. 원본 ID, `Float64` 좌표, part·ring 구성과 복원된 전체 속성이 같았고 입력 자료를 변경하지 않았습니다. 원본 파일과 검증 코드의 SHA는 [동등성 기록](../.local/geometry-transfer-20260919/source-equivalence-final.json)과 [최종 검증 요약](../.local/geometry-transfer-20260919/final-verification.json)에 있습니다.

브라우저에서는 부산의 건물을 선택했을 때 표현 높이·원천 높이 **189.0m**, 자료 버전, `Overture Maps · Buildings` 출처와 원본 ID가 함께 표시되는 것을 확인했습니다. [선택 화면 증빙](../.local/map-first-20260919/candidate-selected-building-desktop.jpg). 선택 정보 보존을 확인한 표본이며 그 건물 높이의 독립 실측 검증이나 전국 건물 정확성 전수 검사는 아닙니다.

[클라이언트 교체 증빙](../.local/map-first-20260919/client-proof.json)은 기존 데이터 항목 유지와 컴파일 결과의 비밀값 검사를 통과했습니다. 이번 최적화에서 건물 좌표·높이 원본을 보정하거나 전국 재타일링을 수행한 것으로 해석하지 않습니다.

[브라우저 비교 진단](../.local/map-first-20260919/browser-comparison.json)은 1280×720, Radeon 860M, DPR 1의 기록이지만 `foreground_measurement=false`이며 측정 중 브라우저 visibility가 false였습니다. 두 실행의 초기 상호작용 시점도 달랐습니다. 따라서 이 파일의 프레임 수치를 전경에서 사용자가 느끼는 FPS 개선 성과에 포함하지 않습니다. Node 표의 소요 시간과도 비교하지 않습니다.

다음 성능 판정에는 실제 전경 탭에서 같은 뷰포트·DPR·화질·카메라 경로·캐시 조건을 고정한 반복 측정이 필요합니다. 차가운 로딩과 준비가 끝난 탐색을 분리하고, 프레임 P95뿐 아니라 생성 작업 최대 시간·메모리 회복·대기 작업 종료를 함께 확인해야 합니다. 지역별 원천 정확성과 데이터 제공 범위는 [실제 범위 보고](COVERAGE.md)와 별도로 판정합니다.

운영·공개 전환 절차는 [무료 배포 문서](STATIC_DEPLOYMENT.md), 기존 로딩 개선은 [로딩 성능 기록](PERFORMANCE_LOADING.md), 이전 라벨 생성 개선은 [라벨 성능 기록](LABEL_RENDERING_PERFORMANCE.md)을 따릅니다.
