## 3. 확인한 요청 주소와 응답 의미

아래 주소는 명세 확인용입니다. `KEY`는 실제 비밀값으로 대체해 문서·브라우저·로그에 남기지 않습니다. API 키는 서버 비밀 설정에서만 주입합니다.

### TAGO 버스

```text
GET https://apis.data.go.kr/1613000/BusLcInfoInqireService/getRouteAcctoBusLcList
    serviceKey=KEY
    cityCode=25
    routeId=DJB30300052
    pageNo=1
    numOfRows=100
    _type=json
```

`25`·`DJB30300052`는 [공식 명세의 대전 예시](https://www.data.go.kr/data/15098533/openapi.do)입니다. 운행 가능한 최신 노선이라는 보장은 아닙니다. `gpslong/gpslati`는 맵매칭 좌표이며 원시 센서 GPS 정확도는 제공되지 않습니다. `totalCount`와 페이지를 대조하고, 명세에 관측시각이 없으므로 수신한 좌표의 `observed_at`을 현재 시각으로 채우지 않습니다.

도착예측의 요청 경로는 `https://apis.data.go.kr/1613000/ArvlInfoInqireService/getSttnAcctoArvlPrearngeInfoList`이며 `serviceKey/cityCode/nodeId/pageNo/numOfRows/_type`을 사용합니다. `arrtime`은 도착까지 남은 초, `arrprevstationcnt`는 이전 정류장 수입니다. [공식 도착정보 명세](https://www.data.go.kr/data/15098530/openapi.do)

### 서울 버스

```text
GET http://ws.bus.go.kr/api/rest/buspos/getBusPosByRouteSt
    serviceKey=KEY
    busRouteId=APPROVED_ROUTE_ID
    startOrd=1
    endOrd=10
```

확인한 [현재 공식 페이지](https://www.data.go.kr/data/15000332/openapi.do)의 구간 조회 경로입니다. `dataTm`은 제공시간, `stopFlag`는 정류소 도착 여부이며 `tmX/tmY`, `posX/posY`가 있습니다. 필드명만 보고 모두 WGS84라고 처리하지 않습니다. 위 URL은 문서에 기재된 HTTP이며, 실제 비밀키를 연결하기 전 제공자가 지원하는 HTTPS 경로와 연결 정책을 검증해야 합니다. 이번 조사에서는 인증된 요청이나 좌표 변환 검증을 하지 않았습니다.

### 경기 버스

```text
GET https://apis.data.go.kr/6410000/buslocationservice/v2/getBusLocationListv2
    serviceKey=KEY
    routeId=233000031
    format=json
```

[경기 공식 매뉴얼](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusLocation)과 공공데이터포털 내 Swagger를 함께 확인했습니다. 반환 항목에 `stationId/stationSeq/stateCd/vehId`가 있고 위경도는 없습니다. `stateCd`는 교차로 통과·정류소 도착·출발 구분입니다. `queryTime`은 매뉴얼의 정보요청시간, Swagger의 응답시간으로 설명되므로 센서 관측시각으로 사용하지 않습니다.

### 서울 지하철

```text
GET http://swopenapi.seoul.go.kr/api/subway/KEY/json/realtimePosition/0/5/1호선
```

`subwayId/trainNo/statnId/updnLine/trainSttus/recptnDt`를 원문과 함께 보존합니다. `trainSttus`는 진입·도착·출발·전역출발 상태이고, `recptnDt`는 마지막 수신시각입니다. 역 좌표에 놓는 표현과 선로 위 보간은 별도 계산 근거를 붙입니다. 라이브 자료의 과거 이력은 원 API에서 제공하지 않는다는 안내이므로, 과거 재생은 허용된 수집 이후의 보관분에 한정됩니다. [데이터 안내](https://data.seoul.go.kr/dataList/OA-12601/A/1/datasetView.do)

## 5. 재사용·보관 판단

TAGO는 홈페이지 제공 공공데이터의 상업적 활용을 포함한 재사용을 안내하고, 제3자 권리가 포함된 비공개 대상 등은 제외한다고 명시합니다. 개별 API의 인증·호출 한도는 계속 적용됩니다. [TAGO 공공데이터 이용정책](https://tago.go.kr/v5/notice/publicData.jsp)

서울 버스·지하철에는 공급기관과 데이터명·원문 링크·수집시각을 표시합니다. 수정·계산한 좌표나 보간 결과는 우리 변환으로 구분합니다. 무료 또는 재사용 허용이라는 사실만으로 공개 조회기의 무제한 자동 접근이 허용되는 것은 아닙니다.

원본 보관에는 공급자·서비스·요청 조건(키 제외)·수집시각·원천 수신시각·해시·응답 코드·페이지 수를 함께 남기는 것을 권장합니다. 공개 파일에는 원문 키와 인증 URL을 넣지 않습니다. 시간별 재생에는 실제 보관 범위를 명시하고, 미수집 시간은 시간표나 최신 위치로 조용히 채우지 않습니다.

현재 조사에서 추가 확인이 필요한 것은 운영 호출량, 공급자별 허용 보관 조건의 상세, 원천 상태의 갱신 지연, 노선별 완전성입니다. 공개 웹 화면의 JSON이 보이더라도 인증 토큰 추출·비공개 인터페이스·다른 서비스의 프록시 키를 연결 경로로 삼지 않습니다.

## 6. Free Worker 운영 판단

[Cloudflare 현행 한도](https://developers.cloudflare.com/workers/platform/limits/)는 Free에서 HTTP와 Cron 모두 **CPU 10ms**, 메모리 **128MB**, 요청 **100,000/일**, 외부 하위 요청 **50/실행**, 동시 외부 연결 **6**입니다. 네트워크·DB 대기 시간은 CPU에서 제외되지만 파싱·해시·정렬·직렬화는 작업량입니다. 기존 수집기의 45초 벽시계 제한은 CPU 10ms 검증을 대신하지 않습니다. 초과 시 `exceededCpu`/1102가 발생할 수 있습니다.

| 작업 | 현재 코드/자료에 따른 판단 | 필요한 조치 |
|---|---|---|
| 작은 최신 상태 응답을 캐시에서 반환 | 9월 19일 전국 표본 17개 공개 요청이 정상 HTTP 응답을 반환했습니다. 원격 CPU 시간은 측정하지 않았습니다. | 응답 크기·차량 수·노선 수를 제한하고 원격 CPU P95/P99와 오류를 측정합니다. HTTP 경과 시간과 CPU를 혼동하지 않습니다. |

권장 구조는 **공급자별 중앙 호출 예산 → 제한된 수집 작업 → 최신 상태 저장 → 작은 조회 API**입니다. 정적 노선·역 연결표는 사전 생성하고, API가 전국 경로 탐색이나 전체 이력 정렬을 수행하지 않도록 합니다. 중복 요청 합치기와 캐시뿐 아니라 계정 전체 호출 예산을 원자적으로 관리해야 합니다. 장기 원본 보관은 최신 상태 캐시와 별도이며, 무료 저장소의 계정 한도와 실제 지속 가동을 확인해야 합니다. 이 문서에서는 R2나 유료 기능을 활성화하지 않았습니다.

## 7. 구현·검증 순서

1. **자료 계약부터 고정합니다.** 원천 관측시각, 공급자 수신/제공/응답시각, 우리 수집시각을 별도 필드로 둡니다. 원천에서 주지 않는 시각은 `null`로 유지합니다. 현재 `observed_at/retrieved_at`을 보존하면서 추가 시간 필드를 설계합니다.
2. **승인된 키가 있는 소스부터 연결합니다.** TAGO·서울 버스·경기 API는 해당 서비스 사용 승인을 확인합니다. 서울 지하철은 별도 실시간 키가 필요합니다. KORAIL 정식 API는 과거 운행 이력을 위한 연결입니다. 키 미확보는 운영 상태로 표시합니다.
3. **전국 지역별 제공 범위를 검증합니다.** 공개 목록에서 각 광역권과 도서 지역의 실제 노선을 정해 페이지 수, 빈 응답, 좌표·방향·회차·급행, 중복 차량을 확인합니다. 첫 표본은 9절의 17개 도시이며, 한 노선의 성공을 해당 도시 전체나 전국 전수 성공으로 전파하지 않습니다.
4. **신선도와 재생을 분리합니다.** 오래된 응답은 마지막 수신시각과 지연 상태를 보여주고, 운행 종료·빈 결과·실패를 구분합니다. 공급자 시각이 없으면 “최근 수집”이라고 표시합니다. 최신 화면을 역사적 관측으로 소급 저장하지 않습니다.
5. **부하를 수치로 판정합니다.** 실제 최대 입력·캐시 적중/실패·동시 요청·할당량 소진·공급자 장애에서 CPU, 요청 수, 응답 크기, 중복 수집 여부를 확인합니다. 노트북을 끈 상태에서도 새 자료의 수집시각이 전진해야 서버 수집 완료입니다.
6. **원문·코드·설정의 복구를 검증합니다.** 키를 제외한 배포 설정과 변환 버전, 원문 해시·스키마·기간별 누락표를 보관합니다. 기존 지도를 계속 제공하면서 교통 수집만 중단·재시작할 수 있어야 합니다. 로컬 정리는 이 복구 검증과 별도 작업으로 남깁니다.

최초 완료 판정은 “전국 기반지도 + 검증된 지역/소스의 최신 교통 상태”입니다. 모든 국내 차량의 실시간 위치와 전국 과거 연속 이력은 별도 범위로 검증해야 합니다. 이번 조사에서 무인 전국 운영을 보장하는 인증 없는 공식 교통 피드는 확인되지 않았습니다.

전국 도시 선택 UI와 배포 증빙은 [지도 집중·전국 화면 검증](MAP_FIRST_PERFORMANCE.md), 현재 운영 절차는 [무료 정적 배포](STATIC_DEPLOYMENT.md)를 따릅니다. 이 문서의 최초 3개 지역 실측은 역사적 연결 기록이며 현재 서비스의 우선 지역 또는 전국 지원의 전제 조건이 아닙니다.

### 10.1 인증과 제공자가 문서화한 서버 연결

서울 실시간 지하철 전용 키를 정상 발급받았으며, 키는 서버 비밀 바인딩에만 저장했습니다. [서울시 현재 명세](https://data.seoul.go.kr/dataList/datasetView.do?infId=OA-12601&serviceKind=1&srvType=A)에 기재된 원천 주소는 `http://swopenapi.seoul.go.kr`의 `realtimePosition` 경로입니다. 먼저 검사한 로컬·Cloudflare의 HTTPS 원천 요청은 8초 시간 제한에 도달했습니다. 이는 해당 검사에서 응답을 얻지 못했다는 근거이며 인증키 거부나 영구적인 HTTPS 미지원 판정은 아닙니다.

문서에 기재된 HTTP를 서버에서 사용할지 명시하는 `SEOUL_SUBWAY_ALLOW_HTTP=true`를 적용한 뒤 실제 응답을 검증했습니다. **브라우저→공개 Worker는 HTTPS, Worker→서울 원천은 제공자 명세의 HTTP**입니다. 이 원천 구간에는 TLS 암호화가 없으며 브라우저 보안 설정이나 인증서 검증을 변경한 방식이 아닙니다. 원천 호스트·서비스 경로를 고정하고 리다이렉트 없이 최대 400행·256KiB·8초로 제한합니다. 키 또는 키가 포함된 원천 요청 주소를 공개 응답·문서·검증 로그에 저장하지 않았습니다.

### 10.3 운영 한도와 남은 연결

- **서울 지하철 호출량:** 현재 응답의 `daily_limit:1000`, `local_budget:800`, `refresh_after_seconds:120`을 확인했습니다. 한 노선을 24시간 120초 간격으로 조회하면 캐시 공유가 완전히 작동한다는 가정에서 하루 720회입니다. isolate·지역 캐시의 가드일 뿐 `quota.global_enforced:false`이므로 여러 지역의 요청을 계정 전체에서 원자적으로 제한하는 보장은 없습니다. 호출량 증설이나 무제한 운영으로 해석하지 않습니다.
- **연속 보관:** 기존 공개 targets·미리보기 검사와 동일 코드의 계약은 `continuous_collection:false`입니다. 이번 최종 검사는 지정한 5개 경로로 제한해 targets를 다시 요청하지 않았습니다. 요청에 따라 최신 상태를 조회하며 전국 관측 이력을 상시 보관하지 않습니다.
- **연결 범위:** 실제 정식 인증 응답을 확인한 도시철도 대상은 서울 `1호선`입니다. 역 ID와 정확한 역 좌표 연결, 다른 호선별 지원과 응답, 서울 버스의 별도 API 연결은 남아 있습니다. 전국 열차의 현재 GPS 피드, 모든 버스 노선의 전수 관측, 장기 재생 이력까지 완료한 것으로 표시하지 않습니다.

서울특별시 원천 출처와 공공누리 1유형 표기를 유지합니다. 이번 작업은 공개 응답 검증과 문서 갱신이며, 무료 운영 제약을 바꾸거나 R2·D1·정기 수집·유료 기능을 활성화하지 않았습니다.
