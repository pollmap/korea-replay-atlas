### 장면 전체에서 프레임당 등록량 제한

정적 도로·시설 자료를 구성할 때는 위치·이름·원본 선택 ID를 가진 라벨 핸들만 만듭니다. 자료 구성이 끝나면 표시 가능한 핸들을 공통 대기열에 넣고, 실제 `preRender`에서 Cesium 라벨을 생성합니다. 한 자료의 라벨 준비 때문에 원본 형상이나 다른 자료의 완료를 기다리지 않습니다.

- 한 장면의 실제 렌더 프레임마다 최대 **라벨 2개**를 처리합니다. 세대가 바뀌거나 같은 프레임의 콜백이 다시 호출돼도 예산을 다시 주지 않습니다.
- 원문 **16 코드 포인트**를 합계 목표로 사용합니다. `Array.from(text).length` 기준이며 UTF-16 길이, 화면에 보이는 글자 수, 고유 glyph 수와 같다고 가정하지 않습니다.
- 첫 이름 하나가 16을 넘으면 그 원문 전체를 해당 프레임에 처리합니다. 이름을 자르거나 영구 대기시키지 않습니다. 따라서 **16은 엄격한 상한이 아니며, 단일 긴 이름의 CPU 작업이 8ms 안에 끝난다는 보장도 없습니다.**
- 장면의 Primitive 컬렉션이 숨겨져 있으면 등록하지 않습니다. 표시할 대기 항목이 남아 있으면 다음 렌더를 요청합니다.

`MapScene`은 렌더 CPU 시작 콜백을 먼저 등록하고 그 뒤에 스케줄러를 생성합니다. 라벨 등록·글꼴 처리 비용도 기존 `renderP95Ms`와 자동 화질 판단에 포함됩니다. `preUpdate`부터 측정하는 `sceneMs`는 장면 갱신까지 포함한 더 넓은 CPU 구간입니다.

### 누적 2,048 코드 포인트마다 컬렉션 분리

모든 지역이 컬렉션 하나를 영구 공유하면, 전국 라벨 한 개가 남아 있다는 이유로 방문한 모든 도시의 글자 텍스처가 계속 보관될 수 있습니다. Cesium의 라벨 삭제는 해당 라벨을 없애지만 공유 글자 캐시 전체를 비우지는 않습니다.

새 스케줄러는 `LabelCollection` 하나와 그 컬렉션을 사용하는 핸들 집합을 한 **세대**로 관리합니다.

1. 새 이름을 더했을 때 누적 합계가 **2,048 코드 포인트 이하**이면 현재 일반 세대를 사용합니다. 넘으면 새 일반 세대를 만듭니다.
2. 라벨을 삭제해도 이미 등록한 코드 포인트 수는 돌려주지 않습니다. 삭제된 이름의 글자 텍스처가 남을 수 있기 때문입니다.
3. 세대의 마지막 소유자가 사라지면 컬렉션 전체를 장면에서 제거하고 파괴합니다. 해제한 세대가 현재 세대였다면 현재 포인터도 비웁니다.
4. 이름 하나가 2,048을 넘으면 그 이름만 사용하는 별도 세대를 만듭니다. 원문과 ID를 유지하며, 이후 일반 이름을 이 세대에 추가하지 않습니다.

고정 라벨은 자신이 속한 한 세대만 유지합니다. 이후 도시의 세대는 마지막 소유자가 사라질 때 각각 해제되므로, 고정 라벨 하나가 모든 후속 글자를 붙잡던 경로를 끊습니다.

| 상태 변화 | 라벨과 자원 처리 |
|---|---|

| 구성 중인 형상 취소 | 숨겨진 라벨 핸들, 원본 선택 등록, 중간 Primitive를 함께 정리합니다. |

### 이 예산이 보장하는 범위

2,048은 **살아 있는 일반 세대 하나에 누적 등록한 원문 코드 포인트 수**의 상한입니다. 정상 세대가 G개라면 합계는 `2,048 × G` 이하이고, 이를 넘는 개별 긴 이름의 길이는 별도로 더해야 합니다. 비어 있지 않은 세대마다 소유 라벨이 최소 하나 있으므로 세대 수는 보유한 실제 생성 라벨 수를 넘지 않습니다.

숨긴 캐시 라벨과 화질 제한으로 숨긴 기존 라벨도 소유자입니다. 전체 보유량은 호출부의 자료·캐시 관리에도 의존하며, 스케줄러 자체의 전역 세대 수나 GPU 바이트 상한은 없습니다. 코드 포인트를 텍스처 바이트로 환산하거나 `generationCodePoints`를 GPU 메모리 사용량이라고 표시하지 않습니다. 세대가 달라지면 같은 글자의 텍스처가 중복될 수도 있습니다.
