## 2. 운영 구조와 보장 범위

```mermaid
flowchart LR
    U[현재 관측 조회] --> M[지도 Worker\n대상 검증·지역 캐시]
    M -->|Service binding| B[비공개 korea-replay-live-broker]
    B --> D[고정 SQLite Durable Object\ntransit-production]
    D -->|페이지별 영속 예약 후 요청| P[TAGO 버스 / 서울 도시철도]
```

- 지도 서버의 중앙 경로는 `LIVE_TRANSIT_MODE=broker`, `LIVE_TRANSIT_BROKER` Service binding으로 선택합니다. 브로커는 `LIVE_TRANSIT_COORDINATOR` namespace의 `TransitCoordinator` 클래스를 사용하며 객체 이름은 항상 `transit-production`입니다.
- 브로커 비공개 설정은 `workers_dev:false`, `preview_urls:false`, `routes:[]`입니다. 최종 확인에서 브로커 기본 주소, 임시 QA 기본 주소, QA 버전 미리보기의 **3개 경로 모두 HTTP 404**였으며 브로커 전달 표시는 없었습니다. [설정](../wrangler.live-broker.jsonc), [경로 검사](../.local/central-live-20260919/private-endpoints.json)
- 임시 QA 종료는 무인증 404만으로 판정하지 않았습니다. **올바른 QA 인증을 보낸 이전 미리보기도 HTTP 404·`text/html`·브로커 전달 없음**을 확인했습니다. 이전 버전 메타데이터의 `has_preview:true`가 남아 있으므로 이 값을 `false`로 바꿨다고 기록하지 않으며, 트리거 설정과 실제 인증 요청 결과로 차단을 판단합니다. [QA 종료 설정 기록](../.local/central-live-20260919/qa-closed.log), [인증 요청 차단 검증](../.local/central-live-20260919/qa-authenticated-closed.json)
- 내부 조회는 `POST /v1/snapshot`, 상태 확인은 `GET /v1/status`만 제공합니다. 초기화·리셋·예산 변경용 HTTP API는 없습니다. 키, 키 지문, 캐시 키, 임의 원천 URL을 상태 응답에 포함하지 않습니다.
- 실제 원천 HTTP **페이지를 보내기 전에** SQLite 예약을 기록하고 저장 완료를 확인합니다. 전송 실패도 예약을 되돌리지 않습니다. 버스는 조회당 최대 2페이지, 지하철은 최대 1페이지입니다.
- 동일한 공식 도시·노선 요청은 합칩니다. 공개 추천 노선 ID와 전국 목록 ID가 달라도 같은 원천이라면 예약·원천 조회를 공유하고, 반환 단계에서 요청한 공개 ID·표시명을 복원합니다. 원천 노선 ID의 대소문자와 한글은 보존합니다.
- 전체 동시 조회 작업은 최대 2개이며, 원천 응답 본문을 모두 받는 동안 슬롯을 유지합니다. 기본 원천 제한 시간은 8초, 최대 설정은 15초, 지도 서버의 내부 응답 수신 제한은 20초입니다. 내부 스냅샷 전체 JSON은 최대 512KiB입니다.
- 브로커나 저장소 실패 시 새 원천 직접 호출로 우회하지 않습니다. 중앙에서 확인한 오류에는 실제 `quota`를 전달합니다. 바인딩 누락·연결 실패처럼 중앙 정책을 확인하지 못한 오류는 `guard:unavailable`, `global_enforced:false`로 구분합니다.

| 원천 | 기본 일일 한도 정책 | 브로커 예약 상한 | 최신 스냅샷 TTL |
|---|---:|---:|---:|
| TAGO 버스 | 10,000 | 8,000페이지 | 90초 |
| 서울 도시철도 | 1,000 | 800페이지 | 120초 |

예약 창은 현재 시간대와 직전 24개 시간대 버킷을 합산하는 `rolling-24h-conservative`입니다. 실제 24시간을 빠짐없이 포함하되 일부 예약은 최대 약 25시간 유지할 수 있습니다. 공급자의 초기화 시간대를 추측해 KST 또는 UTC 자정에 예약을 지우지 않습니다. 인증 실패는 같은 원천·인증 세대에 300초 동안 차단하고, 키 변경은 예약 사용량을 초기화하지 않습니다.

**중앙 제한은 `scope:broker-mediated-requests`에만 적용됩니다.** 같은 키를 쓰는 외부 프로그램, 과거 직접 조회 방식의 불변 미리보기, 기상 원천 호출까지 이 예산으로 제한되는 것은 아닙니다. 여러 외부 소비자가 같은 키를 사용하면 공급자 전체 한도를 별도로 고려해야 합니다. 버스와 기상이 같은 공공데이터 키를 사용하는 기존 예외도 있으며, 이번 교통 이전만으로 지도 서버의 모든 인증키가 제거됐다고 표현하지 않습니다.

## 4. SQL 계측과 무료 운영의 판정 범위

다음 수치는 Node SQLite의 `total_changes()`가 아니라 **원격 Cloudflare SQL 커서의 `rowsRead`·`rowsWritten` 최종값을 합산한 차이**입니다. 커서는 동기적으로 모두 소비한 뒤 한 번만 계측합니다. 공식 API는 이 최종 커서 값을 SQL 비용 계측에 사용한다고 설명합니다. [Cloudflare SQLite Storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)

| 측정 구간 | SQL 읽기 행 증가 | SQL 쓰기 행 증가 | 원천 예약 증가 |
|---|---:|---:|---:|
| 버스 4개 동시 요청 및 후속 상태 확인 | 28 | 8 | 1 |
| 버스 캐시 재조회 및 후속 상태 확인 | 5 | 0 | 0 |
| 지하철 조회 및 후속 상태 확인 | 28 | 8 | 1 |
| 전체 비교 구간 | 61 | 16 | 2 |

표의 SQL 읽기에는 상태 조회 자체의 읽기가 포함됩니다. 버스 캐시 재조회 구간은 상태 확인까지 합쳐 쓰기 0행이었습니다. 상태 API에 새로운 테이블·카운터 영속 쓰기를 추가하지 않았습니다.

계측 계약은 다음과 같습니다.

1. `diagnostics.scope=activation`, `source=sql-cursor`입니다. 합계는 현재 실행 인스턴스의 브로커 SQL만 포함하고, 초기화와 상태 조회 비용도 포함합니다.
2. 두 응답의 `activation_id`가 같고 양쪽 계측값이 숫자일 때만 차이를 계산합니다. 재시작·배포·롤백으로 인스턴스가 바뀌면 이전 합계와 빼지 않습니다.
3. 커서 계측을 제공하지 않는 Node fixture, 잘못된 getter, 비용을 확인할 수 없는 SQL 예외는 `null`입니다. `null`을 0으로 바꾸지 않습니다.
4. 계정 전체·누적 청구서·일일 합계가 아닙니다. DO 요청 수, 실행 시간, 다른 서비스의 사용량과 별도로 봅니다. 캐시 만료 청소, 2페이지 응답, 인증 오류, 인덱스 갱신 등 다른 부하의 비용은 이 표본과 달라질 수 있습니다.
5. 원격 검사는 지도 클라이언트의 15초 상태 캐시를 거치지 않고 내부 `GET /v1/status`를 직접 호출했습니다. 지역 캐시가 있는 `client.status()` 값으로 즉시 전후 차이를 계산하지 않습니다.

운영 구성은 Workers Free의 SQLite DO이며, 이번 작업에서 R2·D1이나 새 유료 플랜을 활성화하거나 결제하지 않았습니다. 무료 한도 초과 시 서비스 오류가 발생할 수 있으며, 작은 표본의 성공을 전체 일일 무료 한도 충족으로 판정하지 않습니다. 적용 한도와 계정 전체 사용량은 [Cloudflare 무료 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/)를 기준으로 별도 확인합니다.

## 7. 현재 관측 자료의 의미

**서울 1호선은 역별 상태 보고입니다.** 이번 원격 표본의 55건 모두 `position:null`, `observed_at:null`이었고, 공급자 수신시각은 존재했습니다. 역 좌표 연결과 GPS 측정값이 없는 자료를 실제 좌표의 열차 이동이나 역 사이 선형 이동으로 만들지 않습니다. 다른 호선 전체의 운영 검증과 전국 열차 GPS 수집도 이번 완료 범위에 포함하지 않습니다.

버스는 공급자가 제공한 지도에 맞춘 좌표를 사용합니다. 이번 17대 모두 센서 관측시각과 공급자 수신시각은 `null`이므로 서버 조회시각을 센서 측정시각으로 바꾸어 표시하지 않습니다. 최신 스냅샷은 조회·만료시각을 지키며 연속 운행 이력을 저장한 것으로 설명하지 않습니다.

공식 위성과 레이더는 **현재 관측 패널**입니다. 기존 공개 위성 검사에서 목록 13개와 PNG 1장의 무결성·디코딩을 확인했으나 `map_overlay:false`, `projection:null`을 유지합니다. 패널의 범례·경계를 임의로 제거해 전국 지도에 정확히 투영했다고 표시하지 않습니다. 기상 원천은 이번 교통 브로커의 중앙 호출 예산 범위 밖입니다. [실시간 기상 계약과 증빙](LIVE_WEATHER.md)
