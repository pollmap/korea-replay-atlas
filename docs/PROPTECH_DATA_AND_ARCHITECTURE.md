# 전국 2D 부동산 지도: 데이터·아키텍처 전환안

기준일: **2026-09-20 KST**. 현재 저장소와 공식 공개 문서를 읽은 1차 설계입니다. 새 원천 수집·활용신청·키 확인·엔진 성능 비교·Git 작업·배포는 수행하지 않았습니다. 아래의 목표 수치는 측정 결과가 아닙니다.

## 1. 추천안과 제품 범위

**기본 화면은 전국 2D 지도와 부동산 검색·비교로 바꾸고, 장기 렌더러는 MapLibre 벡터 지도를 권고합니다. 기존 Cesium은 선택한 지역의 3D를 사용자가 열었을 때 불러옵니다.** 짧은 전환 단계에서는 Cesium의 공식 2D 모드를 쓸 수 있지만, 이를 벡터 2D 최적화 완료나 10배 성능 달성으로 표현하지 않습니다.

첫 사용 흐름은 `지역·주소·단지 검색 → 지도와 목록에서 후보 확인 → 면적·기간을 맞춰 실거래 확인 → 최대 3개 단지 비교`입니다. 햇빛·교통·기상·과거 재생은 보조 도구로 남깁니다. 전국 건물 형상이 존재한다는 사실과 전국 단지·실거래의 연결 완료는 다른 상태입니다.

## 3. 2D와 3D 엔진 선택

| 항목 | Cesium 2D를 먼저 도입 | MapLibre 2D 기본 + Cesium 3D 선택 |
|---|---|---|
| 도입 범위 | Viewer의 `SCENE2D`/`morphTo2D`와 2D 카메라·선택 정책 보완 | 새 벡터 스타일·타일 공급·공통 선택 계약 필요 |
| 기존 자료 | GeoJSON·출처·지형 공급 경로를 많이 재사용 | 도로·물·경계·건물 외곽·단지점을 벡터 타일로 재발행; 기존 GLB·3D Tiles는 Cesium에서 그대로 사용 |
| 기대 효과 | 조작·기본 화면을 빠르게 2D로 바꿀 수 있음 | 기본 사용에서 지형 고도 샘플·3D 모델 디코드·그림자·Cesium 초기화를 요청하지 않을 수 있음 |
| 성능 한계 | 기존 엔진·GroundPrimitive 생성 비용이 자동으로 없어지지 않음 | 전국 GeoJSON을 `setData`하거나 수천 DOM 마커를 만들면 다시 느려짐. 실제 비교 측정 필요 |
| 무료 운영 | 현재 Static Assets 구조를 유지하기 쉬움 | 렌더러는 BSD-3-Clause; 배경지도 데이터·폰트·타일 호스팅 비용과 이용조건은 별개 |
| 3D 품질 | 현재 상세 형상·선택·깊이 표현 유지 | MapLibre의 단순 extrusion을 기존 정밀 3D Tiles의 대체물로 취급하지 않음 |
| 권고 | 작은 전환 단계 | 최종 기본 구조 |

Cesium은 2D 전환 API와 명시적 렌더링을 제공하며, `scene3DOnly`를 켜면 2D 전환이 제한됩니다. MapLibre는 WebGL 벡터 타일 렌더러이고, 공식 대용량 안내도 GeoJSON 축소·분할·벡터 타일화를 권합니다. 어느 쪽도 우리 데이터에서 10배 빠르다는 공식 보증은 없습니다. [Cesium Scene](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html), [MapLibre 소개](https://maplibre.org/maplibre-gl-js/docs/), [대용량 자료 안내](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/), [라이선스](https://github.com/maplibre/maplibre-gl-js/blob/main/LICENSE.txt).

전환 시 공통 뷰는 경위도 중심·bbox·zoom 또는 metres-per-pixel·bearing으로 정의하고, 3D pitch/range는 추가 필드로 둡니다. 현재 3D 공유 링크는 기존 어댑터로 복원하고 새 공유 형식에는 `view=2d|3d`와 스키마 버전을 추가합니다. 데이터 릴리스·배포 버전 고정 계약을 유지합니다.

3D를 닫으면 요청 취소와 Viewer/WebGL 자원 해제를 수행하고 2D로 위치·선택을 되돌립니다. 두 엔진을 동시에 계속 그려 놓는 방식은 기본값으로 삼지 않습니다. 2D용 건물 외곽을 GLB에서 역추출하기보다 보존한 원천 형상에서 만들고, 화면 단순화 오차와 원본 선택 ID를 검사합니다.

SGIS의 공식 API 문서는 access token과 행정구역 경계·좌표변환을 제공합니다. 이번에 열린 문서 본문은 `sgisapi.mods.go.kr` 경로를 안내하므로 과거 `kostat.go.kr` API 주소를 코드에 그대로 고정하지 않습니다. 정적 전국 경계는 파일 수집을 우선해 사용자마다 경계 API를 호출하지 않는 편이 적합합니다. [공식 SGIS API 정의서](https://sgis.kostat.go.kr/developer/upload/doc/SGIS_OpenAPI_%EC%A0%95%EC%9D%98%EC%84%9C.pdf).

행정동·법정동·통계구역·필지 경계는 서로 다른 레이어입니다. 통계 경계를 거래 지역코드와 이름만으로 연결하지 않고 기준일별 코드 대응표를 검증합니다. 독도·울릉도·제주·해안 포함 여부, 원천 CRS와 경위도 축 순서도 검사합니다. 제공되지 않는 호수·개인 소유자 정보를 추론해 복원하지 않습니다.

## 5. 단지·실거래·지도 결합 계약

다음은 제안 스키마이며 아직 구현되지 않았습니다.

| 계약 | 필요한 핵심 필드·규칙 |
|---|---|
| `Complex` | 내부 안정 ID, K-apt/부동산원/건축물대장 등의 원천 ID를 각각 보존; 법정동코드·주소·PNU 후보·단지명·사용승인일·세대수·좌표 정확도·기준일 |
| `ComplexBuildingLink` | 단지 ID↔개별 건물 원본 ID; 공식 식별자 또는 검증된 주소·필지 근거; `confirmed/candidate/unmatched`와 결합 방법 |
| `Transaction` | 매매/임대차, 계약일, 원천 수신일, 금액 원문과 정규화 단위, 전용면적, 층, 해제/정정 상태, 공개된 원천 ID 또는 충돌 검사한 합성키 |
| `Boundary` | `legal/admin/statistical` 구분, 코드·상위코드·시행/기준일·원천 좌표계·출처 |
| `PropertyRelease` | 자료별 기준일·수집시각·해시·지역/월·원본 건수·게시/미연결 건수·면적/가격 단위·갱신 정책 |

동명이거나 가까운 건물을 같은 단지로 자동 확정하지 않습니다. OSM/Overture의 건물 ID와 K-apt 단지코드는 별개입니다. 경계에 걸친 단지는 실제 bbox로 조회하고 대표점은 클릭·라벨 용도로만 씁니다. 좌표가 없는 거래는 원문 목록에 남기되 임의의 건물에 붙이지 않습니다.

파이프라인은 `Raw(비공개 키 제거·수신시각·해시) → Silver(단위/코드/취소/주소 정규화) → Gold(확정 단지 결합·기간별 통계) → Audit → immutable release`입니다. 지도 타일에는 공개 ID·표시값·조회용 최소 속성만 넣고 상세 거래 이력은 선택할 때 받습니다. 전국 원문 XML을 브라우저에 보내지 않습니다.

갱신은 **제안**으로 최근 3개월을 매일 재조회하고 과거 월은 정기 순환 검증합니다. 원천 SLA가 아니라 정정 반영을 위한 운영 정책입니다. 과거 거래가 영구 불변이라고 간주하지 않습니다. 조회 실패를 ‘거래 없음’으로 저장하지 않고 이전 검증본과 마지막 성공일을 유지합니다. 원천 응답에 없는 데이터는 완료 여부를 명시합니다.

차트는 동일 전용면적 또는 명시된 면적 구간·매매/전월세·기간을 고정합니다. 기본은 거래 점과 거래량이며, 중앙값을 표시하면 표본 수와 취소 제외 기준을 붙입니다. 면적 구성이 달라진 전체 평균을 가격 상승률로 해석하지 않습니다. `실거래`, `공시가격`, `현재 매물 호가`, `계산 통계`를 분리하고, 이번 공공 원천에서 확보하지 않은 매물 호가를 만들어 넣지 않습니다.

## 6. 기본 사용과 전문가 확장

| 단계 | 초보자 기본 화면 | 전문가 확장 |
|---|---|---|
| 시작 | 2D 전국 지도, 지역/주소/단지 검색, 아파트 매매 기본, 최근 거래 기간 명시 | 경계 기준일, 도로등급 출처, 데이터 범위/시점 |
| 탐색 | 지역별 집계 → 확대 시 단지 가격 라벨; 화면에 보이는 결과 목록 | 법정동/행정동 전환, 토지·도시계획 레이어, 다중 필터 |
| 선택 | 단지명·주소·세대수·연식·선택 면적·최근 거래·차트 | 원문 거래 표, 해제/정정 표시, 식별자 매칭 근거, 필지/고시 링크 |
| 비교 | 최대 3개 단지, 같은 면적·기간·거래종류로 비교 | 기준을 바꾼 민감도·표본 수·수집 누락 확인; 미래 가격 예측으로 표현하지 않음 |
| 입체 확인 | 상세 패널의 ‘3D 보기’ | 기존 형상·추정 높이 출처·햇빛 실험. 미확인 높이로 일조권 판단을 확정하지 않음 |

상단은 검색·매매/전월세·가격/면적/기간 필터, 지도 우측은 확대·축소·현재 위치·2D/3D, 좌측은 목록/상세로 정리합니다. 모바일에서는 목록과 상세를 하나의 bottom sheet로 전환하고 지도 조작·검색 결과를 가리지 않게 합니다. 기본 흐름에 재생 타임라인이나 태양 방위각을 상시 노출하지 않습니다.

지도 이동 중에는 이미 보인 자료를 유지하고, 정지 후 최신 bbox를 확정해 조회합니다. 목록이 갑자기 바뀌는 것을 원치 않는 사용자를 위해 ‘이 지역에서 검색’을 제공할 수 있습니다. 선택한 단지는 지도 이동만으로 해제하지 않으며 뒤로가기는 검색/필터/지도 위치를 복원합니다. 자료가 부족한 경우 빈 가격 마커나 0원 대신 ‘거래 자료 없음’ 또는 ‘미연결’을 구분합니다.

공식 가이드에서 가져오는 원칙과 본 서비스의 설계를 구분합니다.

- **검색 접근성**: W3C APG의 combobox 키보드·역할 계약을 적용합니다. 방향키로 결과 탐색, Enter 선택, Esc로 팝업 닫기, 입력값 보존·초점 복귀를 검증합니다. `aria-expanded`, `aria-controls`, 선택 결과 안내도 포함합니다. [W3C Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).
- **일관된 화면 요소**: KRDS의 토큰·컴포넌트·검색 서비스 패턴을 참고해 버튼·필터·로딩·빈 결과·오류 상태를 통일합니다. KRDS가 부동산 수치 해석까지 보증하는 것은 아닙니다. [KRDS](https://www.krds.go.kr/html/site/index.html).
- **지도 도구의 역할**: 확대/지도 유형 같은 조작을 분리한 공식 지도 컨트롤 안내를 참고합니다. 구글 API나 지도 데이터를 사용한다는 결정과는 별개입니다. [Google 지도 컨트롤](https://developers.google.com/maps/documentation/javascript/controls).
- **대량 가격 마커**: 단지마다 DOM 요소를 만들기보다 지도 layer와 cluster를 사용하고 선택한 항목만 상세 DOM으로 제공합니다. 대량 점에 layer를 쓰는 근거는 [Mapbox 공식 비교](https://docs.mapbox.com/help/dive-deeper/markers-vs-layers/)이며, MapLibre 적용 효과는 실제 검증합니다.
- **색·정보 위계**: 도로 등급은 선 두께·명칭/범례를 함께 쓰고 가격은 숫자와 단위를 유지합니다. 색만으로 매매/전월세나 상승/하락을 구분하지 않습니다. 지도 저작자 표시는 패널 아래 가리지 않습니다.

Apple Maps HIG 원문 URL도 확인했으나 이번 웹 추출에서는 본문이 JavaScript 안내 수준으로만 제공됐습니다. 읽지 못한 세부 지침을 확인한 것으로 인용하지 않았습니다. [후속 확인 대상](https://developer.apple.com/design/human-interface-guidelines/maps).

## 7. 10배 목표를 검증 가능한 항목으로 분리

‘10배 최적화’는 한 숫자로 합산하지 않습니다. 아래의 비율은 동일 사용자 작업·자료 범위에서 기준선 대비 비교하며, 2D에서 지형·그림자를 요청하지 않는 것은 새로운 기본 제품 흐름의 비용 절감으로 별도 보고합니다. 같은 3D 장면이 10배 빨라졌다는 주장으로 바꾸지 않습니다.

| 지표 | 제안 목표 | 측정·실패 판정 |
|---|---|---|
| 전국 첫 탐색 가능 시간 | 기준선의 1/10을 도전 목표; 별도 절대 목표 P95 2초 | navigation 시작→전국 기본지도 표시+검색/줌 사용 가능. 마지막 loading 프레임 시각과 혼동하지 않음 |
| 최초 유효 화면까지 전송량 | 기준선의 1/10 | 압축된 실제 응답 바이트; 2D 진입 시 Cesium·GLB·terrain 요청 0건을 네트워크로 확인 |
| 도시 이동 | 전경 warm 프레임 P95 33ms 이하; cold/loading도 별도 공개 | 서울·수도권·대전·세종·청주·부산·인천·제주·울릉·독도 동일 경로. 로딩 표본을 전체 결과에서 숨기지 않음 |
| 지도 입력 응답 | INP P75 200ms 이하를 목표 | 실제 입력 이벤트 기준. 서버 응답 시간과 분리 |
| JS 협력 작업 | P95 4ms, max 8ms 목표 | await/비가시 대기를 CPU로 합산하지 않되 단일 느린 호출은 그대로 기록 |
| 검색 | 로컬 warm 결과 P95 150ms 이하, 원격 주소 조회는 별도 | 동일 질의·결과 정확도·0건/오류 구분. 전체 주소 preload 금지 |
| 도시 왕복 메모리 | 10회 왕복 후 안정화, 무한 증가 0 | 활성/캐시/텍스처/엔진별 관측 범위 구분. 직렬화 바이트를 GPU 메모리라고 부르지 않음 |
| 서버 비용 | Free 한도 내, 과금 기능 추가 0 | 정적 요청과 API/DO 호출·쓰기량을 분리; 원천 페이지 단위 예약/중복 제거 |

Radeon 860M, 브라우저 버전, CSS viewport, DPR, 실제 canvas 크기, 전원 모드, foreground 확인, 네트워크/캐시 조건을 기록합니다. cold 5회 이상, warm 동일 경로 7회 이상을 목표로 paired 비교합니다. 별도 무거운 배치·배포 해시 스캔과 겹친 측정은 구분합니다. **백그라운드 약 1초 cadence 또는 `frameMs=null` 자료로 전경 FPS 통과를 판정하지 않습니다.** 이번 문서는 그 재측정을 수행하지 않았습니다.

구현 레버는 ① 초기에 2D 엔진만 로딩 ② 확대 수준별 타일과 서버 사전 집계 ③ 주소/상세/차트 지연 조회 ④ Worker 디코드와 전송 버퍼 재사용 ⑤ 화면 점·라벨 밀도 제한 ⑥ 선택 상태 갱신과 지도 소스 생성 분리입니다. 원본 형상·ID·단지 상세 접근 가능성을 유지하고, 정확도 저하를 성능 향상으로 숨기지 않습니다.

## 8. 무료 운영·URL·Git 원격화

### 정적 타일과 서버

Cloudflare 공식 현재 안내는 정적 자산 요청과 저장에 추가 비용이 없고, Free의 버전당 파일 수 20,000개·개별 파일 25MiB를 명시합니다. Worker 실행 요청은 별도 한도이며 `run_worker_first`로 정적 파일까지 Worker를 통과시키면 무료 요청 한도 초과 시 429가 발생할 수 있습니다. 기존 프로젝트의 더 보수적인 18,000개 목표와 24MiB 파일 정책을 유지합니다. [정적 비용](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [공식 한도](https://developers.cloudflare.com/workers/platform/limits/).

현재 3D 묶음에 전국 고확대 MVT 파일을 모두 덧붙이는 것은 파일 수 검사가 필요합니다. 선택지는 ① 지역별 패키지와 작은 인덱스 ② 별도 2D 정적 배포와 공통 릴리스 manifest입니다. 분리 시 CORS·origin·공유·복구·다운로드 게이트를 함께 검증합니다. 기존 3D 자료나 다른 서비스를 지워서 공간을 만들지 않습니다.

PMTiles는 HTTP Range로 필요한 타일만 읽을 수 있지만, **전국 단일 대용량 파일을 현재 Static Assets에 바로 올릴 수 있다는 뜻은 아닙니다**. 25MiB 이하 독립 archive로 나눌 수 있는지, 206/Content-Range/ETag/캐시/취소·해시 검증과 현재 전체 본문 다운로드 게이트가 호환되는지 먼저 실증합니다. 파일 일부만 읽으면서 전체 파일 SHA 검증을 했다고 보고하지 않습니다. 승인되지 않은 R2 활성화를 우회안으로 제시하지 않습니다. [PMTiles 공식 구조](https://docs.protomaps.com/pmtiles/).

거래 원천은 검증된 배치 스냅샷을 먼저 정적으로 제공합니다. 온라인 조회가 필요하면 기존 중앙 호출예산 패턴을 재사용하되 부동산 원천별 정책을 따로 둡니다. 교통 DO의 고정 테이블에 전국 거래 원문을 몰아넣지 않습니다. 페이지별 예약·허용 대상 검증·요청 중복 제거·키 비노출·실패 시 원천 직접 우회 금지를 지킵니다. 이번 조사에서 새 DB·cron·유료 서비스를 활성화하지 않았습니다.

### 개인정보 없는 서비스 URL

보유한 도메인이 있다면 서비스명 하위 도메인을 Worker Custom Domain으로 연결하는 것이 우선입니다. 소유·DNS 권한·인증서·기존 서비스 충돌을 확인해야 합니다. 보유 도메인은 이번 범위에서 확인하지 않았습니다. 도메인 구매는 금지된 결제에 해당하므로 자동 진행하지 않습니다. 무료 임시 대안은 사용 가능한 브랜드명 `pages.dev` 주소이지만 새 프런트 배포·API 연결 검증이 필요합니다. 계정 전체 workers.dev 하위 도메인을 바꿔 다른 프로젝트 주소까지 변경하지 않습니다. [Workers Custom Domain](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/), [Pages 도메인](https://developers.cloudflare.com/pages/configuration/custom-domains/).

브랜드명과 주소 변경은 API 원천 승인 도메인·CORS·SW scope·immutable preview origin·공유 복원·기존 링크 전환까지 검사합니다. 이 문서는 이름 가용성이나 도메인 확보를 주장하지 않습니다.

### GitHub와 복구

소스·잠금파일·스키마·배치·감사 스크립트·테스트·운영문서를 원격에 보존하고, `.local`·원본 대량 자료·비밀키·인증 세션·개인정보·생성 dist는 명시적으로 분리합니다. 작은 공개 fixture만 허용합니다. 현재 원격 상태와 merge 여부는 이 문서에서 조사/변경하지 않았습니다.

루트 담당 작업은 `비밀/라이선스 검사 → 기능 브랜치 push → CI → diff 검수 → merge → commit·데이터 release·배포 version 대응 기록`입니다. 소스 원격화와 3D/부동산 데이터 복구 백업은 별도 완료 조건입니다. 새 폴더에서 소스 설치와 portable 데이터 복원·preflight·배포 준비를 재현하기 전에는 로컬 삭제 조건을 충족했다고 보지 않습니다.

## 9. 실행 순서와 완료 조건

1. **기본 2D 탐색과 계약 분리**: 검색·필터·단지 선택의 공통 상태부터 만들고 기존 3D 공유·재생 경로 회귀를 유지합니다. Cesium 2D 단계를 거치면 2D용 bbox/스케일·pick·공유를 검증합니다.
2. **전국 경계·단지 식별**: 공개 파일의 코드/CRS/기준일과 좌표 저장권을 확인합니다. 단지 연결의 확정·후보·미연결 수를 지역별로 제시합니다.
3. **실거래 신청·샘플 계약 검증**: 매매 상세와 K-apt를 우선합니다. 실제 응답의 페이지/건수·해제/정정·단위·키 누락/쿼터 실패를 확인한 뒤 전국 지역·월 배치를 진행합니다. 샘플 도시의 성공을 전국 완료라고 부르지 않습니다.
4. **벡터2D 후보**: 원천 형상에서 타일을 만들고 총 파일 수·상세 선택 ID·도시/해안 경계·폰트 출처·로드 예산을 감사합니다. 3D는 선택 동작에서만 활성화합니다.
5. **차트·비교와 실제 사용 검사**: 같은 조건 비교, 자료 없는 지역, 모바일 검색/시트 겹침, 키보드, 뒤로가기, 저사양 전경 이동을 확인합니다.
6. **Git·브랜드 URL·배포**: 루트가 원격 보존·merge·불변 미리보기·공개·복구를 각각 검증합니다. 위 항목 완료와 전국 수집·10배 성능 입증은 별도 체크합니다.

즉시 채택할 수 있는 것은 제품 기본 흐름과 엔진/데이터 경계입니다. 확인이 남은 것은 개별 API 승인, 주소 좌표 저장·재배포 조건, 도로 최신 배포 라이선스, 지역별 데이터 연결 정확도, 2D 실기기 성능, 브랜드 주소 가용성입니다. 이번에 원문 추출에 실패한 Juso 세부 안내·Apple HIG의 세부 규칙은 확인된 정책으로 승격하지 않았습니다.
