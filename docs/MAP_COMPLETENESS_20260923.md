# 3D 건물·도로 누락 원인과 공간 선택 개선

기준일: 2026-09-23. 검사한 자료는 현재 공개 데이터 릴리스 `pub-b71d244ced0bff39`의 로컬 불변 사본입니다. 아래 변경은 소스와 로컬 검증 결과이며, 공개 반영이나 실제 GPU 성능 측정 결과가 아닙니다.

## 서로 다른 누락 원인

- 건물 상세에는 렌더 피처 3,687,718개, 논리 원본 건물 3,687,673개가 선언돼 있습니다. 대표 건물만 포함하는 중간 LOD에서는 일부 건물이 의도적으로 표시되지 않습니다. 원천의 모든 건물이 실제 건물 전체와 일치한다는 뜻은 아닙니다.
- 높이 품질 검토 대상은 임의로 높이를 만들어 채우지 않고 별도 외곽선으로 제공합니다. 실제 건물의 존재·형상·높이를 검증하는 과제는 남아 있습니다.
- 도로 상세 원천은 이미 존재해도 브라우저 작업량 제한으로 선택에서 제외될 수 있습니다. 특히 기존 선택기는 여러 개략 파일을 먼저 예약해 가까운 상세 도로에 남는 예산이 없어지는 경우가 있었습니다.
- 원본 행 순서로 GeoJSON을 크기 분할하면 서로 다른 파일이 같은 도시 범위를 넓게 덮습니다. 작은 화면에서도 필요 이상의 파일·정점을 읽게 됩니다.

## 브라우저 선택 수정

기존 바이트·정점·파일 상한을 유지합니다. 가장 가까운 개략 파일을 먼저 확보한 뒤, 각 레이어의 가까운 상세 파일이 추가 개략 파일보다 먼저 예산을 배정받도록 했습니다. 선택 중복으로 예산이나 렌더가 이중 계산되지 않도록 했으며, 선택한 심도·관측 자료의 기존 우선순위도 유지합니다.

현재 배포 카탈로그를 실제 `selectViewAssets` 함수에 입력한 결과입니다. 시야는 각 도시 중심에서 경위도 ±0.05°, 높이 6,500m로 고정한 시험 사각형입니다. 브라우저에서 측정한 카메라 범위나 FPS가 아닙니다.

서울 low의 전체 선택은 16,772,612 B / 111,585정점으로 기존 16MiB / 150,000정점 상한 안입니다. ±0.005°, ±0.02° 시험에서 세 도시의 상세 파일 선택 수는 바뀌지 않았습니다. 가까운 상세를 우선하면 후순위 자료의 지연 건수는 늘 수 있으며, 이 수정만으로 모든 상세가 동시에 표시되지는 않습니다.

## 이후 자료 생성의 공간 분할 수정

`emit_compact`의 크기 초과 분할을 원본 행 순서 대신 지물 중심의 가장 넓은 지리 축을 기준으로 변경했습니다. 변환 버전도 `spatial-retile-3`으로 올려 이전 작업의 fingerprint와 분리합니다. 지물을 절단하거나 정점을 단순화하지 않으며, 경계를 가로지르는 선·다각형은 원래 형상 그대로 남습니다. 전 지역 재생성이나 공개 카탈로그 변경은 실행하지 않았습니다.

서울 원천 3개 파일을 같은 입력으로 합친 후 이전 알고리즘과 새 알고리즘을 각각 적용했습니다. 두 후보 모두 4개 파일이며, 13,898행과 75,053정점, 원천 속성과 중복 행을 보존했습니다.

| 비교 | 기존 행 순서 분할 | 공간 분할 |
|---|---:|---:|
| 시청 ±0.005°에서 겹치는 파일 | 2 | 1 |
| 해당 파일 바이트 합계 | 3,307,227 B | 1,612,720 B |
| 해당 파일 정점 합계 | 36,738 | 16,433 |

작은 시야의 후보 바이트는 51.2% 줄었지만 전체 후보 크기는 6.5% 늘었습니다. 이를 전국 다운로드 절감이나 10배 렌더링 개선으로 해석하지 않습니다. 기존 공개 3개 파일을 직접 교체한 결과도 아닙니다. 게시 전에는 전국 파일 수·크기 한도와 실제 카메라 경로를 다시 검사해야 합니다.
