# 2D 지도 버튼의 이동 해상도와 성능 검사

2026-09-27. 범위는 MapLibre 확대·축소·북쪽 버튼이며 3D는 변경하지 않습니다.

기존 드래그와 휠은 입력 전에 framebuffer 해상도를 낮췄지만 NavigationControl의
버튼은 canvas 입력을 거치지 않았습니다. 버튼이 전달하는 `originalEvent`도
이동 중 resize로 제스처가 끊기는 것을 막는 기존 방어에 해당해 조절을 생략했습니다.

세 실제 버튼의 capture-click에 기존 controller를 연결했습니다. 버튼의 기본
클릭보다 먼저 적용하므로 Enter/Space가 발생시키는 클릭도 같은 경로를 이용합니다.
이벤트 취소나 별도 키보드 처리를 추가하지 않습니다. 포인터를 누르거나 이미 이동
중이면 변경하지 않으며, 무동작 클릭도 기존 settle 타이머가 원래 해상도로 복원합니다.
종료 시 리스너를 제거합니다. canvas 측정 클릭과 다른 UI 버튼에는 적용하지 않습니다.

실제 브라우저에서 버튼 시작 시 DPR 1, 정지 후 1.5 복원을 확인했습니다.
북쪽 버튼의 Enter 조작 후 같은 버튼에 초점이 남고 지도 오류는 0이었습니다.
기기 DPR 2, viewport 1280×720에서의 확인입니다. 이동 중 framebuffer 픽셀 수가
줄어드는 사실을 전체 지도 속도 개선율로 표현하지 않습니다.

## 같은 자료를 사용하는 전후 관찰

두 프로덕션 빌드를 따로 보존하고 같은
`map2d-e22f8d215bc46c855c12` 자료·천안 좌표(127.113, 36.815)를 사용했습니다.
각 10회 reload 후 zoom 12→13→12 버튼 조작을 수행했습니다. 화면 크기와 DPR은
같고 로컬 대량 변환·업로드는 종료했습니다. AC·균형 조정 상태를 확인했습니다.

| 항목 | 이전 | 이후 |
| --- | ---: | ---: |
| 실행 수 | 10 | 10 |
| 실행별 이동 프레임 P95의 중앙값 | 30.45ms | 31.55ms |
| 실행별 P95 범위 | 25.8–37.3ms | 28.5–34.8ms |
| 33ms를 넘은 실행 | 3 | 2 |
| 실행별 이동 표본 합계 | 455 | 485 |
| 지도 오류 | 0 | 0 |

이후 측정과 배포 파이프라인 fixture 테스트가 일부 겹쳤습니다. 브라우저 cache를
초기화하지 않았으며 20Mbps/50ms 네트워크 조건도 적용하지 않았습니다. 전후를
교차 무작위화하지 않은 관찰이고, P95들의 중앙값은 합친 원시 프레임의 P95가 아닙니다.
**큰 프레임 향상, 일반 탐색 33ms 목표의 전면 통과, 전체 10배 성능을 입증하지 않습니다.**
첫 준비 시간 변화도 이 버튼 수정의 효과로 해석하지 않습니다.

관련 controller/진단/측정 테스트 33개, 전체 웹 1,012개, 타입검사·ESLint·프로덕션
빌드가 통과했습니다. 결과는 버튼 입력 경로의 일관성과 조작 회귀 확인이며,
전국 지도 전체 성능 인수와 분리합니다. 냉/온 cache·장면별 프레임·다운로드·메모리의
통제된 반복 검증은 계속 필요합니다.

## 후속 연속 조작 확인

파이프라인 테스트까지 모두 종료한 뒤 같은 천안 장면을 한 번 열고 확대·축소를
10회 왕복했습니다. 이동 프레임 472개의 P95는 **29.10ms**, 지도 오류는 0,
정지 후 DPR은 1.5였습니다. 묶음과 디코딩 cache 합계는 16,018,654B로 64MiB
상한 안에 머물렀으며 동시 다운로드 최대 4개를 유지했습니다.
이 결과는 해당 장면의 연속 버튼 조작 기준 33ms 이하 확인입니다. 다른 도시,
냉 cache·회선 제한·터치·전체 기능의 성능 통과로 확대 해석하지 않습니다.
