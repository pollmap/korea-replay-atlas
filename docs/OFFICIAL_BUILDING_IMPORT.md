# 공식 건물 원천 연결 준비

2026-09-16 기준. **공식 GIS건물통합정보 SHP 본체는 아직 확보하지 않았습니다.** 이 작업은 공식 문서에 따른 입력·검토 어댑터이며 전국 정밀 건물 구현·정확도 검증·실제 배포 완료를 의미하지 않습니다. 테스트 자료는 인위적인 계약 검증용이고 서비스에 공개하지 않습니다.

## 구현 범위

`pipeline/official_buildings.py`는 `AL_D010` 전체 자료와 `CH_D010` 변동 자료를 구분하여 로컬 검토용 JSONL 기록을 생성합니다. 원본 파일은 읽기만 하고, 기존 Overture 건물·지형·공개 카탈로그·데이터베이스에는 쓰지 않습니다. 변동의 삭제도 **삭제 의도 이벤트**로 남길 뿐, 사용자 파일이나 이미 수집한 건물을 지우지 않습니다.

현재 입력은 다음 두 종류입니다.

- CSV: 공식 `A0`~`A28` 또는 `A30` 열과 `geometry_wkt` 열. `geometry_wkt`는 Polygon/MultiPolygon WKT입니다.
- GeoJSON: FeatureCollection, 각 Feature의 properties에 공식 A열, geometry에 Polygon/MultiPolygon입니다.

SHP/GPKG 직접 판독은 구현하지 않았습니다. Fiona/pyogrio 등 새 의존성을 설치하지 않았습니다. 원본 SHP/GPKG를 확보하면 QGIS의 ‘다른 이름으로 저장’으로 CSV(WKT)/GeoJSON을 별도 생성하여 입력하거나, 본체 판독 어댑터를 후속 추가할 수 있습니다. 내보낼 때 긴 식별번호와 앞자리 0을 문자열로 보존합니다.

## 검증한 공식 계약

정의서는 [브이월드 GIS건물통합정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18)에서 연결한 [국가중점데이터 컬럼정의서 2026-01-02](https://www.vworld.kr/contents/국가중점데이터_컬럼정의서(26.01.02)_배포용.xlsx)입니다. 실제 내려받은 원본과 필드 추출 결과는 `.local/research/national-sources/`에 있습니다.

| 의미 | 전체 `AL_D010` | 변동 `CH_D010` |
|---|---|---|
| 스키마 열 수 | A0~A28,29개 | A0~A30,31개 |
| GIS건물통합식별번호 | A1,문자열 | A1,문자열 |
| 원천 도형ID | A0 | A0 |
| 건축물ID | A19 | A19 |
| 높이(m) | A16 | A16 |
| 지상층/지하층 | A26/A27 | A26/A27 |
| 데이터기준일 | A22 | A22 |
| 생성변경일 | A28 | A28 |
| **A23** | **원천시도시군구코드** | **변동순번** |
| 입력구분 | 없음 | A29 |
| 원천시도시군구코드 | A23 | A30 |

공식 스키마에서 A29의 이름과 `U` 예시는 확인했지만 전체 변경 코드 의미를 완전하게 설명한 계약은 확보하지 못했습니다. 그래서 변동 입력은 **명시적인 이벤트 매핑 파일을 반드시 요구**합니다. 실제 받은 원본의 제공 명세를 확인하여 코드→`insert`/`update`/`delete`를 지정합니다. 모르는 코드는 추정하지 않고 `unmapped_change_code`로 남깁니다.

공식 페이지는 2023-08-08 이후 배포 CRS를 EPSG:5186, 그 이전 구간을 EPSG:5174로 안내합니다. 어댑터는 `--source-crs`를 필수로 요구하며 확장자·지역만 보고 추측하지 않습니다. 변환은 항상 x/y 순서를 사용하고 결과를 EPSG:4326으로 저장합니다. 최신 GeoJSON로 변환한 파일은 내보낸 파일 CRS를 입력해야 하며, **원본이5186이었다는 이유로 이미4326인 파일에5186을 다시 적용하면 안 됩니다.**

## 실행

원본 확보 및 별도 내보내기 후의 명령 예시입니다. 아래 경로는 사용자가 가진 실제 파일 경로로 바꿉니다. 이 문서의 예시 경로는 실데이터가 아닙니다.

```powershell
# WGS84 GeoJSON로 내보낸 전체 자료
.venv\Scripts\python.exe -m pipeline.official_buildings C:\data\AL_D010.geojson --table AL_D010 --source-crs EPSG:4326

# 원본5186 좌표를 유지하여 WKT 열을 만든 CSV
.venv\Scripts\python.exe -m pipeline.official_buildings C:\data\AL_D010.csv --table AL_D010 --source-crs EPSG:5186 --encoding cp949

# 제공기관 계약으로 검증한 변동 코드 매핑 JSON을 별도로 지정
.venv\Scripts\python.exe -m pipeline.official_buildings C:\data\CH_D010.geojson --table CH_D010 --source-crs EPSG:4326 --event-map C:\data\verified-change-codes.json
```

입력 한 파일당 검토 레코드를 최대200,000개로 제한합니다. 전국 전체를 한 번에 메모리에 올리지 않도록 원천 행정구역 또는 공간 구역별 파일로 나눠 입력합니다. 한도를 초과하면 해당 배치를 공개하거나 저널로 확정하지 않습니다. 이는 현 노트북의 검토 단계에서 정한 운영 제한이며 원천 제공기관 제한이 아닙니다.

## 기록과 재실행

기본 출력은 `.local/silver/official-buildings/journal/`입니다.

- `<batch hash>.jsonl`: 각 원본 레코드와 정규화 결과·이벤트·품질 검사 결과.
- `<batch hash>.manifest.json`: 입력 해시·CRS·테이블·변환 버전·코드 매핑·정상/불완전 건수·저널 SHA256.

배치 식별자는 원본 SHA256, 테이블, CRS, 인코딩, 이벤트 매핑, 변환 버전으로 결정합니다. 같은 입력·설정은 같은 결과를 재사용합니다. 동일 이름에 다른 내용이 있으면 덮어쓰지 않고 충돌로 중단합니다. 파일은 배타적 생성으로 기록하며, 저널 기록 중 프로세스가 종료되면 manifest가 없는 불완전 파일이 남을 수 있습니다. **manifest가 존재하고 journal SHA256이 일치한 배치만 유효하게 취급**해야 합니다. 불완전 파일을 자동 삭제하거나 복구된 것으로 가장하지 않습니다.

원본 A열과 알 수 없는 추가 열은 `source_properties`에 보존합니다. 출처에는 원본 파일명·해시·원본 행 번호·정의서·변환 버전을 기록합니다. 입력 파일을 읽는 동안 변경된 경우 해시를 다시 확인하여 기록 확정을 중단합니다.

## 누락과 높이 판정

`quality.complete`는 다음 조건에서 false입니다.

- 전체 또는 변동의 기대 필드가 하나라도 없음.
- 공식 필수 속성이 비어 있음.
- 식별번호 미존재/숫자 변환으로 정밀도 손실 위험, 관할코드·기준일 오류.
- 높이 결측·0·음수·비수치·무한대 또는 검토 상한900m 이상.
- 형상 없음/자기교차/비면형상/좌표 변환 오류/한국 검토 경계 밖/면적1㎡ 미만.
- 변동 코드 미해석·변동순번 없음, 동일 배치 중복 식별자.

900m와1㎡는 **오류 검토용 임계값**이며 실제 건물의 법적 정의나 실측 정확도 보증이 아닙니다. 경계값 밖 자료는 지우지 않고 원문과 오류 사유를 남깁니다. 지상층수×3m 또는 GHSL로 공식 높이 결측을 채우지 않습니다.

삭제 이벤트는 형상·높이가 없어도 식별자·관할·기준일·변동순번·명시적 코드 매핑이 유효하면 `event_valid=true`일 수 있습니다. 그래도 건물 레코드의 `complete=false`는 유지합니다. `event_valid`는 적용 완료가 아니며 자료의 삭제·변경을 실행하지 않습니다.

A16은 행정대장의 높이 속성입니다. 정의서에서 측정 기준·옥탑 포함·지면 기준 상세를 확인하지 못했으므로 LiDAR 실측 또는 지붕 최고점으로 단정하지 않습니다. 상대 건물높이와 바닥 절대고도를 분리하며, 지오이드 보정을 높이 자체에 더하지 않습니다.

## 공간 결합 제안 함수

`propose_matches(records, targets)`는 완전한 **전체 스냅샷 레코드**와 WGS84 GeoJSON target 건물 간 검토 제안만 반환합니다. 입력 변경 이벤트는 자동 매칭 대상에서 제외합니다.

1. EPSG:5186 미터 좌표에서 공간색인으로 겹치는 도형만 찾습니다.
2. 기본 IoU≥0.8, 중심거리≤10m, 면적비0.8~1.25를 모두 요구합니다.
3. 후보 관계에서 출발·도착 양쪽 모두1개인 경우에만 `matches`에 넣습니다.
4. 일대다·다대일은 `ambiguous_do_not_apply`; 중복 ID·불완전 레코드는 제외합니다.
5. 반환값 `applied=false`, `requires_review=true`를 유지합니다. 높이 덮어쓰기를 실행하지 않습니다.

`confidence=high_spatial_agreement`는 **높은 도형 일치**라는 뜻이며 실제 동일 건물 검증 완료가 아닙니다. 주소·대장·사용승인일·현장 표본 등 추가 근거로 검수해야 합니다. 원천 CRS를 잘못 입력하면 한국 내부의 엉뚱한 곳으로 이동할 수도 있으므로 실제 표본 위치 확인은 여전히 필요합니다.

## 현재 검증과 남은 연결

```powershell
.venv\Scripts\python.exe -m pytest tests/test_official_buildings.py -q
```

합성 계약 테스트19개 통과: CRS 변환, 식별번호 보존, 전체/변동 A23 분리, 희소 삭제 이벤트, 잘못된 높이, 코드 미해석, 결측·중복, 재실행 불변성, 원본 보존, 일대일·다대일·일대다 매칭, 미지원 파일 형식, 1m 미만 원천 높이·층수 충돌 보존. 테스트 중 ‘경위도를5186으로 잘못 선언했지만 한국 범위로 변환되는 경우’를 실제 발견하여 면적 검사로 보완했습니다.

`official-buildings-review-2`는 `raw_height_m`를 보존하고 `render_height_m=null`, `height_accuracy_verified=false`를 명시합니다. 필드·이벤트의 완전성 통과는 높이 실측 정확도 인증이 아닙니다. [높이 품질 정책](HEIGHT_QUALITY.md)의 기준에 따라 실제 개체 연결·측정 정의를 검토한 뒤 별도 공개 변환을 해야 합니다.

남은 것은 **허가된 실제 SHP/GPKG 확보→원본 인코딩·CRS·변동 코드 확인→실데이터 파싱 및 품질 감사→수작업 표본 검수→공개 허용 범위 확인→개별 자산 교체·배포 검증**입니다. 지금은 데이터 연결 준비 단계입니다.
