# 압축 거래 자료와 검사 결과 재사용

## 자료 계약

기존 PropertyAsset의 sha256·bytes는 압축 해제 후 JSON을 가리킨다. 선택 필드 transport는 encoding=gzip, 압축 파일 sha256·bytes를 가진다. 평문 자료는 기존 계약을 사용한다. HTTP Content-Encoding으로 내부 파일 압축을 추정하지 않는다.

게시 영수증 files의 sha256·byte_length는 실제 저장 파일을 가리킨다. 압축 파일에는 transport.encoding·decoded_sha256·decoded_bytes를 추가한다. 게시 전 실제 파일과 압축 해제 후 JSON을 모두 검사한다. 압축 해제는 최대 24MiB이며 출력 크기·UTF-8·JSON·해시가 일치해야 한다.

## 원본 검사 캐시

캐시는 원본 작업 입력 전체의 해시, 정규화/저장 코드 및 verify_snapshot AST 버전, 스키마, 원본 루트에 고정된다. 변경된 작업은 원본 재파싱을 수행한다. 동일 작업은 저장된 정규화 스냅샷의 해시·건수·거래 ID digest를 확인하여 재사용한다. 이동/복원 시 원본 파일 해시 검사는 별도 수행한다.

이전 임시 장부는 검사가 전부 passed인 경우에만 명시적으로 편입한다. 해당 실행의 Git 코드와 현재 정규화/검사 함수가 같고 고정 체크포인트 SHA·장부 건수가 일치해야 한다. 일반적인 외부 검사 장부를 자동 신뢰하지 않는다.

## 이전 공개본 보존 검사

공개된 고정 데이터 원점과 atlas manifest SHA에서 모든 속성 자료 참조를 확인한 복구본은 verified-public-property-baseline으로 구분한다. 원문 재파싱 완료라고 표시하지 않는다. continuity 비교만 이를 허용하며 신규 요약/게시 자료의 원본 감사 조건은 그대로 유지한다.

## 배포 순서

압축/평문 호환 클라이언트를 먼저 공개한다. 새 자료는 고정 수집본 → 검사 캐시 → 압축 거래 → 월별 요약 → 이전 공개 ID 보존 비교 → 후보 파일 감사 → 공개 후보 확인 순서로 만든다. 자료 후보가 통과하기 전 기존 데이터 포인터를 유지한다.

초기 전체 후보 생성과 원본 재파싱 생략은 구현됐다. 변경 지역만 재생성하는 전체 증분 게시, 정정 lane 운영, 자동 대표 주소 전환은 후속 작업이며 이 문서의 완료 항목이 아니다. 오피스텔·추가 권역·3D는 제외한다.

## 요약 자료와 기존 위치 연결

거래뿐 아니라 월별·단지별 요약 중간본과 공개 요약 묶음도 명시적 gzip으로 직접 기록한다. 참조에는 원문 SHA/크기와 transport 파일 SHA/크기를 분리한다. 압축 옵션은 요약 릴리스 식별자에 포함하며 과거 평문 자료는 변경하지 않는다. 월별 집계 그룹·거래 건수의 보존을 검사하고 압축 파일 손상을 거부한다.

기존 공식 주소 연결을 새 릴리스에서 유지할 때는 원천 단지 식별번호와 법정동·지번이 같고 주소 충돌이 없는지 검사한다. 모호한 연결은 보류하고 오래된 가격을 제거한다. 이 과정은 좌표 검증을 대신하지 않는다. 고정 공개본의 `/data/...` 경로 복원은 공개 루트를 제외한 로컬 상대 경로로만 읽으며, 원본 감사가 없는 공개 복구본을 신규 요약의 원천으로 사용하지 않는다.
