## 처리량을 줄이는 변경

### 건물 목록을 지역별로 받기

기존 목록에는 4,307개 타일 노드가 한 JSON에 들어 있습니다. Cesium의 `fromUrl`은 이 노드들을 동기적으로 생성합니다. 새 목록은 문서당 최대 96노드로 나누고, 필요할 때 외부 JSON을 읽습니다.

| 항목 | 검증 후보 |
|---|---:|
| 첫 JSON | 78,677 B / 96노드 |
| 외부 문서를 포함한 JSON | 137파일 / 3,638,849 B |
| 보존한 원래 타일 노드 | 4,307 |
| 원래 세계행렬과 비교한 최대 원소 차이 | 0 |
| 이 분할에서 재작성한 GLB | 0 |

각 문서의 경로·해시·접근 가능성, 자식 순서, 원래 콘텐츠, 메타데이터, bounding/request volume, geometricError, refine, 합성 좌표 변환을 검증했습니다. 중간 상세도와 원본 상세 형상은 유지합니다. 분할은 전체 JSON 용량을 줄이는 압축이 아니라 첫 단계의 동기 작업을 줄이는 방법입니다.

외부 JSON 참조는 Cesium 내부 트리에 추가 깊이를 만듭니다. 따라서 원래 LOD 의미를 보존했어도 skip-LOD의 실제 요청 순서까지 같다고 보장하지 않습니다. 빈 화면·불필요 요청·확대 후 상세 표시를 브라우저에서 별도로 확인해야 합니다. [공식 외부 타일셋 규칙](https://github.com/CesiumGS/3d-tiles/blob/main/specification/README.adoc#external-tilesets)

설치된 Cesium 1.145.0의 실제 `Cesium3DTileset.fromUrl` 초기 노드 생성 경로를 Node에서 비교했습니다. 입력마다 준비 2회 후 교차 7회 측정에서 경과시간 중앙값은 **147.679→5.297ms**, P95는 **170.872→6.317ms**였습니다. 최초 입력은 3,570,255 B와 4,307노드입니다. 원천 JSON을 메모리에서 반환하는 부분만 대체했고 네이티브 노드 생성과 해제는 그대로 실행했습니다. JSON 파싱·네트워크·외부 JSON 상세화·GLB·GPU·전체 지도 로딩·Chrome FPS는 측정 밖입니다. Windows CPU 카운터는 작은 구간에서 15~16ms 단위로 양자화돼 별도 기록했으며 위 표는 고해상도 경과시간입니다. [측정 원본](../.local/national-upgrade-20260919/tileset-construction-benchmark.json)

### GPU 준비 작업에도 제한 적용

도로·시설 builder가 공유하는 `PrimitiveAdmission`은 장면 전체에서 준비 중인 배치를 최대 2개로 제한합니다. Cesium의 실제 `ready`가 확인된 후 슬롯을 반환합니다. JavaScript 생성 함수 종료와 GPU 준비 완료를 같은 시점으로 취급하지 않습니다.

라인·면이 섞인 배치는 다음 슬롯을 기다리기 전에 장면에 넣습니다. 취소·오류·해제 시 대기와 슬롯을 정리합니다. 준비 중인 도형은 숨겨진 재사용 캐시에 넣지 않고 해제합니다. 숨김 컬렉션은 Cesium 업데이트가 멈춰 슬롯을 계속 점유할 수 있기 때문입니다. 준비가 완료된 도형은 기존 메모리 예산 안에서 재사용합니다.

이 제한은 타일셋 GLB·지형·텍스처의 모든 GPU 업로드를 통합 제한하는 기능은 아닙니다. 또한 큰 단일 폴리곤의 처리시간이나 모든 생성 작업 8ms 이하를 보장하지 않습니다. 전국 물 영역 한 자산의 97,352정점은 이후 원본을 보존하는 공간 분할 검토 대상으로 남습니다.

## 건물 부품과 개수

검증한 16개 원본 건물을 61개 부품 형상으로 교체했습니다. 새 상세 GLB 8개는 승인 후보와 바이트가 같고 기존 GLB 4,295개를 재사용합니다. 부품을 새로운 건물로 더하지 않습니다.

| 계약 | 값 |
|---|---:|
| 논리 원본 건물 행 | 3,687,673 |
| 부품을 포함한 렌더 피처 | 3,687,718 |
| 별도 검토 외곽 행 | 42,853 |
| 건물 레이어 record_count: 렌더 피처 + 외곽 | 3,730,571 |

`logical_source_building_count`, `building_parts_parent_count`, `building_parts_feature_count`를 별도 보존하며 `렌더 수 = 논리 원본 수 - 교체 부모 수 + 부품 수`를 게시 전에 검사합니다. 과거 자료에 논리 수가 없으면 미확인으로 남깁니다. 이 건수는 모든 실제 건물의 존재·높이·형상이 정확하다는 검증이 아닙니다. GHSL 평균 높이 추정과 검토 대상은 계속 구분합니다.

## 공식 도시철도 설정

공식 명세의 16쌍을 [노선별 근거와 범위](SEOUL_SUBWAY_COVERAGE.md)에 정리했습니다. 1~9호선, 경의중앙선, 공항철도, 경춘선, 수인분당선, 신분당선, 우이신설선, GTX-A입니다. 최종 미리보기에서 00:38:25~00:38:36 KST에 노선당 1회, 재시도 없이 조회해 10노선의 현재 역 상태와 6노선의 정상 0건 응답을 확인했습니다. 조회 당시 2·3·9호선·수인분당선·신분당선·우이신설선이 0건이었습니다. 이 결과로 해당 노선의 운행 종료나 미지원 여부를 단정하지 않습니다. [최종 16노선 조회](../.local/national-upgrade-20260919/preview-subway-final/verification.json)

처음에는 원천의 최상위 `INFO-200`, `total: 0` 응답을 중첩 오류 형식과 달라 거부했습니다. 실제 HTTP 200이면서 body의 status가 500인 경우도 있어 코드·건수·목록의 일관성을 함께 검사하도록 수정했습니다. 인증·한도 오류는 여전히 별도로 분류하며 비어 있지 않은 목록과 0건 선언의 충돌은 거부합니다. 원인 확인을 위한 운영자 직접 요청 1회는 중앙 예산 밖에서 실행됐으며 [민감 원문을 제외한 결과](../.local/national-upgrade-20260919/seoul-empty-envelope.json)에 구분했습니다. 키·요청 URL·원천 메시지·차량 원문을 증빙에 저장하지 않았습니다.

노선마다 요청 한도를 새로 만드는 대신 서울 원천의 공용 800회 예약 상한과 120초 캐시를 유지합니다. 노선을 선택하기 전 모든 노선을 자동 조회하지 않습니다. 역 상태는 GPS 좌표가 아니며 센서 관측 시각을 만들어 넣지 않습니다. 공식 명세에 없는 노선과 다른 도시의 교통은 별도 연결 과제입니다.

## 검증과 남은 작업

### 불변 색인의 바이트 보존 수정

첫 후보 `16ba1e5ea8904da1` / 미리보기 `dba03552-c642-4c09-98af-fc7c9462ed59`는 공개 전환 대상에서 제외했습니다. 기존 지역 색인 324개를 같은 URL에서 JSON 키 순서만 바꿔 쓰는 게시기 문제가 발견됐습니다. 의미가 같더라도 SHA가 달라져 기존 브라우저 캐시의 무결성 검사와 충돌할 수 있습니다. 공개 트래픽은 기존 `095795c4` 그대로입니다.

기존 `e79c3faf906a102e` 묶음의 정확한 바이트를 324개 로컬 색인에 복원했고, 제외한 후보의 바이트는 별도 묶음에 남겨 증빙을 보존했습니다. `immutable_json`은 기존 값이 같으면 쓰지 않고, 새 파일은 결정적인 키 순서로 만듭니다. 같은 공개 데이터 URL에서 해시나 크기가 바뀌면 새 stage 디렉터리를 만들기 전에 차단하는 검사도 추가했습니다. 관련 게시 검사 45개가 통과했습니다. 이 수정 뒤 새 묶음을 다시 감사하며, 첫 후보의 정적 파일 검증을 최종 후보의 검증으로 대체하지 않습니다.

### 자동 검사와 화면 판정

- 전체 웹 테스트 648개 통과. 지도 후보의 린트·타입·프로덕션 빌드는 통과했으며, 이후 비공개 서버의 0건 파서 수정은 관련 93개 검사와 타입·범위 린트를 통과한 뒤 Wrangler로 별도 번들링·배포했습니다. 지도는 검증한 `fc22359b` Worker 바이트를 유지하며, 교통 원천 파서는 schema 2의 필수 브로커 경로에서 실행됩니다.
- Python 전체 507개 통과, Windows 실제 심볼릭 링크 생성 검사 1개는 권한 때문에 건너뜀, 기존 경고 4개. 경로 이탈·해시·좌표 변환 등 나머지 회귀는 통과했습니다.
- 건물 수·게시·커버리지 관련 70개 검사 통과. 새 형상 공개 경로 관련 44개 검사도 통과.
- 준비 슬롯·취소·혼합 배치·캐시 교착 회귀는 실제 Cesium 객체를 사용하되 `ready`를 fixture로 제어한 검사입니다. 실제 GPU 성능 시험은 아닙니다.
- Windows 조작 도구가 브라우저 URL을 확실히 판정하지 못해 전경 조작을 중단했습니다. 이번 수치로 전경 프레임 P95 33ms 목표를 판정하지 않습니다.
- 미리보기 HTTP 검사와 새 자료의 화면 확인 후 공개 전환·복귀 검증이 필요합니다. 원본·이전 릴리스·로컬 소스는 보존합니다. 외부 백업과 재구축 검증이 끝나기 전 로컬 삭제를 진행하지 않습니다.
