# 비공개 후보의 검사 캐시·압축 출력 — 2026-10-09

## 변경 범위

`pipeline.property_candidate`는 고정된 닫힌 조회 DB에서 비공개 후보를 만듭니다. 원천 호출·수집 장부 쓰기·공개 포인터 변경·배포·원본 삭제는 수행하지 않습니다.

- 후보 작업 폴더의 `verification.sqlite`를 `VerificationCache`에 연결합니다. 입력 장부·검사 코드 버전이 같은 완료 작업의 검사 결과를 재사용하고, 정상·오류 경로 모두 연결을 닫습니다.
- 거래 묶음은 `compressed_transactions=True`, 단지/월별 요약과 월 묶음은 `compressed_assets=True`로 생성합니다. 원문·전송 바이트의 서로 다른 SHA·크기를 담은 기존 explicit gzip 계약을 사용합니다.
- 기존 평문 공개본과 압축 공개본을 모두 읽습니다. 압축 전환은 별도의 불변 산출물을 만들며 기존 평문 공개본을 덮어쓰거나 삭제하지 않습니다.
- 고정 30GiB 대신 기본 2GiB 복구 여유를 사용하며 CLI `--reserve-bytes`로 명시할 수 있습니다. 음수·불리언·정수가 아닌 값은 거절합니다. 각 단계의 기존 시작 전 여유 공간 검사와 파일별 쓰기 전 reserve 검사를 유지합니다.
- 장부에 기록된 정규화 snapshot descriptor만으로 참조 수·고유 파일 수·저장 바이트·해제 바이트·최대 단위를 기록합니다. 이 사전 계산에서 XML·snapshot 본문을 읽거나 해제하지 않습니다. 게시에서 사용하지 않는 상태는 집계에서 제외합니다.

## 공간 계산의 한계

입력 descriptor 합계는 새 후보의 실제 출력량이나 상한이 아닙니다. gzip 압축률과 요약·단지 참조에 따라 출력량이 달라집니다. 따라서 상태의 `input_sizes.publication_upper_bytes`는 `null`이며 전체 후보가 끝까지 생성될 용량을 확보했다는 보장으로 쓰지 않습니다.

실행 초기에 최소 게시 작업 단위와 복구 여유를 검사하고 이후 각 단계·파일의 기존 guard를 사용합니다. **완전한 후보 전체의 동적 디스크 상한 산정은 미완료**입니다. 공간 부족·검사 실패 시 직전 `last-verified.json`과 고정 조회본을 보존합니다. 중간본 보관 정책이나 자동 삭제는 이번 변경에 포함하지 않습니다.

## 재사용과 검사 버전

새 후보의 작업별 캐시는 원본 참조·정규화 코드·스키마를 포함하는 기존 검증 키를 사용합니다. 실행별 `verification_execution`은 캐시 적중·미적중 수와 버전을 기록합니다. 미적중 수를 모든 원문 페이지의 재파싱 건수로 표현하지 않습니다. 완료가 아닌 상태의 이전 정상 snapshot은 기존 게시기의 재검증 경로를 사용합니다.

PR104 게시기의 release fingerprint에는 정규화·원본 해석 코드, `verify_snapshot` 검사 함수와 스키마 버전의 지문이 포함됩니다. 같은 장부에서도 이 지문이 바뀌면 새 릴리스와 새 작업별 검사 키를 사용합니다. 완료된 작업의 호출 시각만 바뀌고 원본·정규화 결과가 같으면 기존 게시물을 재사용하며, 재사용 전에 파일 SHA·참조·건수의 연결 관계를 검사합니다. 이 후보 연결 작업은 해당 게시기를 그대로 사용하며 `real_estate_publish.py`를 수정하지 않았습니다.

재사용 결과의 `audit.verification_cache`는 최초 게시 때의 감사 기록입니다. 지금 실행에서 실제로 캐시를 조회했는지는 `status.json`의 `verification_execution`으로 판단합니다. 게시물 자체를 재사용한 실행은 캐시 적중·미적중 모두 0입니다.

## 실행

```sh
python -m pipeline.property_candidate \
  --data /path/to/project-data \
  --output /path/to/private-candidate \
  --reserve-bytes 2147483648
```

수집 원본 폴더와 조회 DB 세대 폴더 안에는 후보 검사 캐시를 만들지 않으며, 캐시 파일의 하드링크도 거절합니다. 기존 후보 잠금과 대형 작업 잠금을 유지하며, 중단 후에는 원래 고정 장부를 재개합니다.

## 검증과 운영 상태

최신 게시기(0211fb3) 위에서 관련 pytest **136개를 통과**했습니다. 소형 fixture로 거래·요약·월 묶음의 gzip 바이트와 해제 SHA, 기존 평문 보존, 거래 ID 보존, 동일 입력 재실행 시 원문 파싱 0·산출물 증가 0, 완료 호출 시각만 달라진 조회 세대의 같은 게시물 재사용, 한 작업 변경 시 다른 작업의 캐시 재사용, 같은 장부에서 정규화 코드 지문 변경 시 새 후보 재검사, 캐시 정상/오류 close, reserve 부족 시 이전 정상본 유지, CLI 인자 전달, 동시 실행 잠금과 고정 장부 재개를 검사했습니다.
