# 2D 중심 저장·배포 운영

2026-10-03 사용자 승인: 불필요한 3D 자료와 재생성 중간본을 정리합니다. 원문 거래, 수집 장부, 복구본, 현재 2D 타일과 다른 서비스는 제거 대상이 아닙니다.

- 미사용 3D 건물·지형·계층·부품·스트림 대용량 자료는 새 앱에 포함하지 않습니다. 검증한 기존 불변 Pages 주소에만 남기고 정확한 경로를 302로 연결합니다. 과거 공유와 2D 자료는 유지합니다.
- `node scripts/pages-release.mjs lean-app <private-options.json>`은 `receiptPath`의 검증된 Pages 앱에서 시작합니다. `legacy3dOrigin`은 실제 확인한 8자리 불변 `korea-replay.pages.dev` 배포 주소만 허용합니다. 기존 redirect 규칙이 다른 경우 덮어쓰지 않습니다.
- 첫 전환만 기존 앱 전체를 검증합니다. 이후에는 작은 lean Pages receipt를 원본으로 사용하므로 3D 중간본을 다시 내려받을 필요가 없습니다. 3D 원본을 삭제한 옛 전체 bundle은 일반 frontend_release의 재사용 입력으로 사용하지 마세요.
- 후보와 공개본은 같은 내용 해시, 고정 데이터 버전, API 전용 함수 라우팅, 정적 404와 기존 검증 절차를 유지합니다. 대표 주소 전환 전에 실제 2D 조작과 3D 경로의 리다이렉트를 검사합니다.
- 지역 수집은 경기·서울·인천 → 대전·세종·청주·천안·아산 → 부산입니다. 이 외의 신규 API 호출은 하지 않습니다. 이미 확보한 원문과 장부는 보존합니다.
- 수집·백업과 후보 생성은 같은 `bulk-work.lock`을 사용합니다. 다른 대량 작업 중 수집기는 기다리고 자동 재개하며 오류 hold를 만들지 않습니다. API는 닫힌 조회본을 계속 제공합니다.
- 후보 생성은 원문 감사 직후 거래 묶음으로 직접 출력합니다. 전체 원문 JSON과 묶음 두 벌을 만들지 않습니다. 30GiB 안전 여유와 일일 원천 호출 예산은 유지합니다.
- 삭제 전 프로젝트 내부 절대 경로·심볼릭 링크·실행 프로세스·현재 2D 의존·하드링크를 검사합니다. 논리적 파일 크기 합과 실제 확보 공간은 별도로 측정합니다. 공유 서버 전체 prune은 사용하지 않습니다.
- 운영 원본과 CAS 백업의 SHA 복구 검사는 계속 유지합니다. 같은 디스크 백업을 서버 장애 대비 외부 백업이라고 부르지 않습니다.

실제 제거 경로·확보 용량·공개 결과는 비공개 operations 기록에 남기고, 배포 완료와 자료 수집 완료는 별도로 보고합니다.
