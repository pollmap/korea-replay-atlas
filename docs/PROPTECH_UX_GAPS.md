## 1. 지도에서 찾은 지역을 단지 분석으로 이어주기

**사용 상황:** 처음 이용하는 사람이 지도에서 관심 지역을 찾은 뒤, 그 지역의 단지를 보고 후보를 고르려 합니다. 전문가도 지역의 행정 코드와 분석 조건을 잃지 않고 지도를 오가야 합니다.

아실 도움말은 지역 이동·조건 검색과 비교 진입을 같은 지도 기능으로 안내합니다. KB 상세 공개 본문에는 지도 이동과 단지 정보가 함께 있습니다. 이는 탐색과 단지 이해를 연결하는 근거이며, 두 서비스의 실제 클릭 횟수나 전환 속도를 측정한 결과는 아닙니다. [아실 상세 도움말](https://asil.kr/app/sub/help.jsp?target=help4), [KB 단지 페이지](https://www.kbland.kr/se/c/14489)

**현재 구현과 남은 부분**

|---|---|---|

**최소 구현안**

1. 검증된 지역 코드가 있는 경계/지역 결과에 **이 지역 단지 보기**를 제공합니다. 단지 이름만으로 지역·원천 ID를 추정하지 않습니다. 경계 코드와 실거래 조회 코드가 다르면 검증한 연결표를 먼저 사용합니다.
2. 패널에 현재 지역과 거래 유형을 유지하고, 그 지역의 단지 이름·법정동으로 목록을 좁힙니다. 동명 단지는 지역·법정동·공식 식별자로 구별합니다. 전국의 원시 거래를 검색 때마다 미리 받지 않습니다.
3. 좌표가 없는 단지도 목록에서 거래를 살펴보고 비교할 수 있게 합니다. 지도 핀은 검증된 좌표를 확보한 경우에만 추가합니다. 지역 선택을 지도에 반영할 때도 확인된 경계 범위를 사용합니다.
4. 지도를 다시 조작해도 선택한 분석 조건이 자동으로 다른 지역으로 바뀌지 않게 합니다. **현재 지도 범위에서 찾기**와 **선택 지역 유지**를 명시적으로 구분합니다.

초보자는 지역을 다시 입력하지 않고 다음 단계로 이동하게 하고, 전문가에게는 현재 지역 코드·경계 기준일을 펼쳐 볼 수 있게 합니다. 위치 연결 미완료를 숫자나 임의 핀으로 감추는 작업은 포함하지 않습니다.

**완료 확인:** 서로 다른 시도의 동명 단지를 구별할 수 있고, 지역 선택 → 단지 → 뒤로가기로 돌아왔을 때 지역·검색 조건이 유지되어야 합니다. 미연결 좌표는 지도 이동 없이 분석을 계속할 수 있어야 합니다. 목록 변경 때문에 3D 엔진이나 전국 거래 자료를 새로 적재해서는 안 됩니다.

## 2. 후보를 고른 뒤, 비교할 조건과 자료 수부터 맞추기

**사용 상황:** 단지 2~3곳을 골랐지만 면적·계약월·임대 유형이 다르면 가격 차이를 해석하기 어렵습니다. 같은 면적을 골라도 한 단지는 거래가 없고 다른 단지는 수집 전일 수 있습니다.

KB의 2026년 안내는 단지 선택 수에 따라 분석/비교를 나누고 면적 선택을 포함합니다. 실제 단지 페이지는 조사 시세·최근 신고 거래·매물 가격을 구분하며 전세와 월세도 별도로 제시합니다. 여기서 참고할 것은 **비교 기준을 먼저 정하고 서로 다른 숫자를 구별하는 구조**입니다. 해당 서비스의 시세·AI 판단·이미지를 가져오는 제안은 아닙니다. [KB 비교 이용 안내](https://kbthink.com/realestate/basics/blog/260618.html), [KB 단지 페이지](https://www.kbland.kr/se/c/14489)

**최소 구현안**

1. 비교표 바로 위에 **계약월 · 거래 유형 · 전용면적**을 고정해서 보여주고, 조건 아래에 단지별 유효 신고 건수/미수집 상태를 먼저 제시합니다. 기본은 현재의 단일 계약월을 유지합니다.
2. 임대 비교는 원천 월세 금액으로 **월세 0인 계약 / 월세가 있는 계약 / 금액 미확인**을 구별합니다. 전세·월세 명칭을 적용할 때 이 분류 기준을 설명합니다. 월세는 보증금과 월 납부액을 함께 보되, 두 중앙값이 같은 계약 한 건을 뜻하지 않는다고 표시합니다. 임의 전월세 전환율로 한 가격을 만들지 않습니다.
3. 면적 선택에 단지별 자료 존재 여부를 붙입니다. 공통 면적이 없으면 이유를 보여줍니다. `84.9㎡`와 `84.99㎡`를 자동으로 같게 만들지 않습니다. 면적 범위 비교는 별도의 사용자 선택과 집계 계약을 마련한 이후에 추가합니다.
4. 통계표의 취소·검토 제외 정책과 전문가 원본 목록의 포함 옵션을 계속 구별합니다. 새 임대 유형 필터를 넣으면 차트·원본 목록·CSV·공유 복원에도 같은 필터를 전달합니다.

초보자는 비교 가능한 자료의 수와 조건부터 이해하게 하고, 전문가는 정확한 조건과 원천 목록으로 내려가 확인하게 합니다. 현재의 한 달 자료로 다년 추세를 그리거나, 검증되지 않은 가격 지수·예측을 더하지 않습니다.

**완료 확인:** 같은 면적에 월세 0인 계약과 월세가 있는 계약이 섞인 예제로 분리를 확인합니다. 0건/미수집/부분 수집은 각각 유지되어야 합니다. 면적이 정확히 다르면 합산하지 않고, 공유 링크를 다시 열어도 기간·면적·임대 유형·검토 기록 옵션이 일치해야 합니다.

**최소 구현안**

1. **이 비교 저장**으로 이름·저장 시각·검증된 버전 고정 공유 URL만 기기에 보관합니다. 예를 들어 최대 20개로 제한하고, 저장 차단/용량 오류가 나면 URL 복사를 계속 사용할 수 있게 합니다. 원시 거래나 인증값은 저장하지 않습니다.
2. 저장 목록에는 지역·단지 수·계약월·거래 유형을 표시합니다. 열기·이름 변경·개별 삭제만 우선 제공합니다. 계정 가입과 서버 동기화는 필요하지 않습니다.
3. **저장한 자료 그대로 열기**를 기본으로 합니다. 이전 릴리스가 없으면 누락 상태를 보여주고, 최신 자료로 조용히 대체하지 않습니다.
4. **새 자료로 다시 비교**는 사용자가 누르는 별도 동작으로 둡니다. 새 릴리스에서 같은 조건을 확인한 후 다른 비교로 저장하며, 사라진 단지·미수집 월·건수 변화를 명시합니다. 수집 주기와 운영 장부를 검증하기 전에는 자동 알림을 약속하지 않습니다.

초보자는 후보를 다시 찾을 수 있고, 전문가는 과거 판단에 사용한 자료와 이후 갱신 자료를 분리할 수 있습니다. 참고 서비스의 관심 기능을 그대로 복제하는 대신 현재의 불변 데이터·공유 계약에 맞추는 안입니다.

**완료 확인:** 창을 닫고 다시 열어도 후보와 조건이 복원되어야 합니다. 이전 릴리스 미존재와 네트워크 실패는 서로 구별해야 합니다. 새 자료 확인을 누르기 전에는 저장된 링크나 비교 결과가 바뀌지 않아야 합니다.

## 실행 순서와 검증 경계

| 순서 | 실행할 잔여 항목 | 착수 전에 필요한 것 | 완료 판정 |
|---|---|---|---|
| 1 | 임대 유형을 분리하고 비교 조건·건수를 가까이 표시 | 원천 월세 금액의 분류 계약, 공유 필터 확장 | 혼합 임대 사례와 결측/0건·CSV·공유 회귀 확인 |
| 2 | 지도 지역 선택 → 공식 단지 목록 연결 | 경계 코드와 조회 코드의 검증된 연결, 위치 미연결 상태 유지 | 전국 여러 시도의 동명 단지·뒤로가기·키보드 흐름 확인 |
| 3 | 기기 내 비교 보관함 | 현재 버전 고정 공유 URL 생성 성공, 저장 실패 처리 | 다시 열기·과거 릴리스 누락·명시적 새 자료 비교 확인 |

이번 확인은 위 파일의 소스 읽기와 공식 웹 본문 조사입니다. 기존 [property-view.test.ts](../tests/property-view.test.ts)의 결측/필터 복원 검사와 [property.test.ts](../tests/property.test.ts)의 정확한 면적·기간 집계 검사는 읽었으며, 이 문서 작업에서 테스트를 재실행하지 않았습니다. 제품 코드·원본 자료·인증·배포는 변경하지 않았습니다.

후속 브라우저 검증은 지역 선택부터 비교까지의 **완료 성공률, 조건을 다시 입력한 횟수, 잘못 고른 동명 단지 수, 이동·복원 때의 다운로드량**을 확인하는 것이 좋습니다. 모바일 패널의 실제 겹침·스크롤, 키보드 초점, 대기 시간은 별도로 측정해야 합니다. 이번 조사만으로 10배 성능 향상, 모든 단지 좌표 연결, 모든 과거 월의 전국 완전성을 주장하지 않습니다.
