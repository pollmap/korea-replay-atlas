## 높이 유효성 및 범위

- `height`, `base_height`, `min_height`에 숫자형 비유한 값이 없었습니다. `height=null` 42,507행은 명시적인 높이 미상으로 분리했습니다.
- 0 이하 높이, 음수 `min_height`, `min_height > height`, 1,000m 초과 높이 검토 표식은 모두 0건입니다. 1,000m는 검토 기준이며 오류를 단정하는 기준이 아닙니다.
- 바닥 타원체고(`base_height`) 범위는 약 **−78.74835–1,698.11834m**입니다. 건물 자체 높이와 단위 의미가 다르며, 음수라는 이유만으로 실패 처리하지 않았습니다. 지면 관통·부유 또는 실제 지형과의 일치는 별도 공간 검수가 필요합니다.
- `min_height` 범위는 **0–154m**입니다.

## 검증 방법과 한계

SQLite 읽기 트랜잭션에서 자산 목록을 한 번 고정했습니다. 각 정규화 GeoJSON의 SHA-256을 먼저 확인하고, UTF-8을 객체 단위로 읽으며 디스크 SQLite 대장에 두 ID를 기록했습니다. 읽는 동안 계산한 해시도 다시 대조했습니다. 한 원천 자산에 오류가 있으면 해당 자산의 대장 기록을 되돌리도록 되어 있으며, 이번에는 발생하지 않았습니다.

공개 3D는 카탈로그의 모델 수와 tileset의 정규화 원천 해시를 대조했습니다. 높이 미상 GeoJSON은 실제 행 수도 검사했습니다. 이 도구 자체는 GLB 내부 feature table 전수 검사, 브라우저 렌더링, 공간 도형의 실측 일치, 현재 시점의 실제 건물 누락률을 검증하지 않습니다. [커버리지 보고](COVERAGE.md)의 “해당 생성기 자체는 ID 중복 미검증” 문구와 이 별도 ID 검사 결과를 구분합니다.

## 극단값 표본: 원천 DEM과 건물 속성 대조

`building-identities.json`의 `height_flags={}`는 앞서 정의한 유한성·0 이하·min/height 관계·1,000m 초과 조건에 해당하는 값이 없었다는 뜻입니다. **실제 데이터 품질 이상이 없거나 정밀 지도 검수가 완료됐다는 뜻이 아닙니다.** 별도 `building-height-extremes.json`은 다음 검토 표식을 기록하며 `data_quality_complete=false`를 유지합니다.

| 후속 검토 표식 | 임계값 | 이번 증빙 표본 |
|---|---|---:|
| `source_height_below_1m` | 원천 상대 높이 < 1m | 2건 |
| `ellipsoidal_base_below_minus_30m` | 건물 바닥 타원체고 < −30m | 3건 |

이는 검토 대상을 찾기 위한 임계값이며 실측 오류 판정 기준이 아닙니다. 표본 수는 이번에 추가 대조한 사례 수이며, 임계값별 전국 총수를 새로 전수 집계한 값이 아닙니다. 원천 값은 보존하고, 정밀 지형·육해 경계·시설별 의미를 보강한 후 교체 여부를 판단해야 합니다.

아래 좌표는 외곽 도형 안의 대표점이며, 단위는 미터입니다. 해당 원천 타일을 다시 읽어 4개 픽셀의 bilinear 보간과 EGM96 → 타원체고 변환을 재계산했습니다. 세 건 모두 공개 바닥 높이와 0.000001m 이내로 일치했습니다.

고성 건물은 [OSM way 1016061834 버전 2](https://api.openstreetmap.org/api/0.6/way/1016061834/2.json), 서해대교안전센터는 [way 618024363 버전 6](https://api.openstreetmap.org/api/0.6/way/618024363/6.json)에서 실제 `building=yes` 태그와 명칭/주소를 확인했습니다. 세 번째 외곽의 Overture 원출처는 `doi:10.5281/zenodo.8174931`의 `east_asian_buildings`입니다.

**확인된 사실:** 음수 값은 보정 과정에서 새로 만들어진 것이 아니라 Terrarium 원천 픽셀에 들어 있습니다. 해당 픽셀에 결측 표식 −32768은 없습니다. **해석 및 남은 검증:** 해안·수면과 주변 육지의 표고 혼합, 원천 지형 이상 또는 외곽 좌표의 불일치 가능성이 있으며, 독립적인 고해상도 DEM·육해 마스크와 대조하기 전에는 원인을 하나로 단정할 수 없습니다. 특히 지상 시설을 음수 원천 고도에 배치하는 품질 문제를 현재 형식·ID 검증만으로 잡지 못합니다.

0.01m 사례 두 건도 변환기가 새로 만든 값이 아니었습니다. Overture 원본 Parquet와 동일 버전의 OSM API 모두 아래 값을 제공합니다.

- [의정부역, way 1364007203 버전 2](https://api.openstreetmap.org/api/0.6/way/1364007203/2.json): `building=train_station`, `height=0.01`, `building:levels=3`, `layer=3`.
- [인접 지붕, way 172002822 버전 48](https://api.openstreetmap.org/api/0.6/way/172002822/48.json): `building=roof`, `height=0.01`, `building:levels=3`, `layer=2`.

현재 변환기는 양수 원천 높이를 층수보다 우선하므로 두 건을 0.01m로 유지합니다. 이처럼 건물·지붕의 의미와 층수 관계를 고려한 후속 검수가 필요합니다. 이번 감사에서는 9m 또는 다른 추정값으로 바꾸지 않았습니다. 좌표·원천 ID·DEM 타일 해시·픽셀값·OSM 버전 태그의 제한된 증빙은 `.local/audit/building-height-extremes.json`에 기록했습니다.
