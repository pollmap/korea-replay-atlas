## 무손실 전송 압축 확인

실제 Cloudflare의 별도 버전 미리보기에서 원시 GLB와 압축 응답을 비교했습니다. 해당 시험 버전은 운영으로 전환하지 않습니다.

| 항목 | 결과 |
|---|---|
| 표본 원본 | 3,822,800 B |
| gzip 전송 | 614,452 B, 83.93% 감소 |
| 압축 해제 | 원본 SHA-256 일치 |
| gzip을 허용하지 않는 요청 | 원본으로 변환되어 정상 응답 |
| 중첩 폴더·HEAD·304·404 | 통과 |
| Range | 부분 범위 대신 정상 200 전체 본문 응답 |

서로 다른 크기의 로컬 GLB 10개 합계는 gzip 6에서 83.61% 감소했습니다. 전국 전체 가중 평균은 아니며, 서버 압축 수준에 따라 다를 수 있습니다. 두 원격 시험 보고서의 43개 검사가 통과했습니다.

증빙: `.local/compression-probe-20260917/remote-proof.json`, `remote-wildcard-proof.json`.

`_headers`는 `/data/*.glb`에 `Content-Encoding: gzip`과 `Vary: Accept-Encoding`을 설정합니다. 파일을 사전 gzip으로 바꾸면 런타임에서 이중 압축될 수 있으므로 원본을 그대로 둡니다. [Cloudflare Response 인코딩](https://developers.cloudflare.com/workers/runtime-apis/response/), [정적 헤더 규칙](https://developers.cloudflare.com/workers/static-assets/headers/).

## 도시 왕복과 전송 복구 검사

같은 미리보기에서 대전→세종→청주→대전을 두 번 왕복했습니다. 첫 왕복의 대전 복귀 JS heap은 191,036,432 B, 두 번째 복귀는 190,628,448 B였고, 두 복귀 시 Cesium의 tileset 메모리 보고값은 모두 130,969,766 B였습니다. 숨긴 geometry의 캐시 추정치는 15,320,946 B로 16MiB 한도 안에 있었고 재사용 누적은 3→10건으로 늘었습니다. 강제 GC를 하지 않은 짧은 관찰이므로 장기 메모리 누수가 없다는 증명은 아닙니다. 로컬 파일 감사와 동시에 진행해 이 왕복의 프레임 시간은 정식 비교에 쓰지 않았습니다.

첫 청주 이동에서 지형 4건의 `ERR_FAILED`가 있었고 두 번째 왕복에서는 증가하지 않았습니다. 4개 원격 파일은 모두 HTTP 200·원본 SHA 일치로 확인했습니다. 파일 누락은 아니지만 당시 상세 예외를 기록하지 않아 전송 실패와 Service Worker 내부 예외의 최종 구분은 미확정입니다. 정상 취소로 집계에서 제외하지 않았습니다. 제한된 전송 재시도와 pathname·단계·예외 이름만 포함한 원인 진단을 보강했습니다.

증빙: `.local/performance-20260917/city-tour-ui.json`, `city-tour-network.json`.

최종 컴파일된 다운로드 관리자(`36689707d66da6e1`)로 별도 로컬 HTTP 응답의 본문을 의도적으로 끊어 실제 브라우저에서 검사했습니다. 한 번 끊기는 파일 4개는 각각 2번째 요청에서 회복됐고, 계속 끊기는 파일은 3회 시도 후 실패했습니다. 동시 요청 최대 4개, 최종 완료 4건·실패 1건·재시도 6건·최종 정상 본문 192 B를 정확히 집계했습니다. 취소·HTTP 404/3xx·크기 초과를 재시도하지 않는 회귀를 포함해 다운로드 관련 40개, 전체 웹 423개 검사가 통과했습니다. 외부 연결이 항상 성공한다는 보장은 아니며, 고의로 끊은 이 시험의 실패 1건은 실제 지도 오류 수에 합산하지 않습니다.
