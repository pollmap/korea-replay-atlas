# 작업량 기준 저장공간 검사와 후보 보관

2026-10-08. 공개 앱/데이터 릴리스 변경과 별도인 운영 수정입니다.

## 장애와 수정

VPS 파일시스템 가용 공간이 0이 되어 수집기 컨테이너가 종료됐습니다. 48시간 이상 사용하지 않은 Docker 빌드 캐시를 정리한 직후 `df -B1` 가용 공간은 5,164,552,192바이트였습니다. Docker가 보고한 캐시 회수량 5.887GB와 실제 파일시스템 가용 공간 증가는 구분합니다. 다른 서비스 이미지·볼륨은 삭제하지 않았습니다.

상위 VPS 사전 검사는 작업량을 사용했지만 Collector 내부에는 예비 공간 외에 고정 5GiB가 남아 있었습니다. 다음 XML 응답·정규화 결과의 상한과 1MiB 작업 여유를 검사하도록 변경했습니다. 매 응답 전 검사와 체크포인트·호출 한도는 유지합니다. 읽기 DB 게시와 로컬 백업 CLI에 남아 있던 기본 30GiB도 제거했습니다. 온라인 DB 복사 및 백업은 자체 예상 사용량을 계속 검사합니다.

## 후보 정리

`python -m pipeline.pages_retention --root <project> --protect <current-receipt> --protect <previous-receipt> --protect <source-receipt> --protect <active-candidate-receipt>`는 먼저 계획만 출력합니다. `--apply`가 있어야 실행합니다.

- 현재·직전 정상본·빌드 입력·활성 후보를 모두 보호 목록에 지정합니다.
- 24시간 이상 지난 완성된 Pages 후보의 `client/`만 제거합니다.
- manifest 해시·파일 목록·크기를 대조하며 링크·추가 파일·불완전 후보는 삭제하지 않습니다.
- receipt·manifest·검증 기록은 남깁니다. 원본, 장부, Git 및 사용자 파일, 원격 배포는 대상이 아닙니다.
- 이미 정리된 후보를 다시 실행하면 파일을 추가하거나 다시 제거하지 않습니다.

현재는 명시적인 보호 목록으로 실행하는 도구입니다. 공개 포인터를 자동 조회해 매일 정리하는 예약 작업은 아직 연결하지 않았습니다. 원본 XML 작업본의 압축 객체 전환도 별도 작업이며 이 변경에 포함되지 않습니다.
