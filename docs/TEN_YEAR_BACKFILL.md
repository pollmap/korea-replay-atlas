# 아파트 실거래 10년 수집: 검증된 범위와 복구

기준: 2026-09-24 KST. 이 문서는 **로컬 원장과 실제 공식 API 조회** 상태입니다. 공개 사이트의 10년치 게시, 역사적 전국 전수, 노트북을 끈 상태의 자동 수집을 뜻하지 않습니다. 기존 게시 후보와 3D 서비스는 그대로 유지합니다.

## 범위와 현재 증거

- 2026-09-19T17:08:31Z를 기준으로 2026년 8월까지의 완료된 120개월과 2026년 9월 잠정 1개월, 총 **121개월(2016-09~2026-09)**을 계획했습니다. 법정 시군구 현행 조회 코드 256개 × 매매·전월세 2종 = **61,952 지역·월·유형 작업**입니다.
- 키·네트워크 없이 생성한 공개 코드 기준 계획은 `.local/property-plan-local/ten-year-plan.json`(3,966,709B, SHA-256 `1887466c477aaa28709fa6805c0d081dc500c4f0081a137d19496552c847065c`)입니다. 계획 작업 수는 수집 성공 수가 아닙니다.
- 기존 61개월 SQLite 원장은 일관된 SQLite backup API로 `.local/real-estate-20260920/backups/checkpoint-before-121-20260924.sqlite`에 복사했습니다(12,558,336B, SHA-256 `4c0b484b2d73d7314af44562b7913123b87b9e5d417920d43524de24da1f4ea6`). 원본 XML·스냅샷·후보·사용자 자료는 삭제하거나 덮어쓰지 않았습니다.
- `--extend-window`는 같은 공식 코드 registry와 동일한 선행 월 순서를 요구합니다. 진행 중인 수집 lease가 있거나 기존 작업 수가 맞지 않으면 거부합니다. 이관 전 31,232개의 작업 행, 기존 호출 7,595건 및 스냅샷을 대조해 모두 보존됐음을 확인했습니다.
- 2026-09-24T03:47:46Z 원장 시점에 **2016년 9월의 512개 작업은 493개 자료 있음·19개 정상 빈 응답**, **2016년 10월의 512개 작업은 499개 자료 있음·13개 정상 빈 응답**으로 각각 미완료 0개입니다. 전체 61,952개 중 자료 있음 8,029개·정상 빈 응답 286개·실패 1개·대기 53,636개입니다. 실패 1개는 이 두 달의 작업이 아닙니다. 공식 API의 2016년 응답을 실제 원본과 해시 스냅샷으로 보존했습니다.
- 이 범위는 **현행 지역 코드로 조회한 결과**입니다. 폐지·분할·신설 지역의 효력일 대응표가 없으므로 과거의 전국 전수 또는 동일 경계의 시계열로 해석하지 않습니다. 특히 빈 응답은 그 코드·그 월의 API 응답일 뿐, 개편 전 지역의 거래가 없었다는 뜻이 아닙니다.

## 안전한 실행

아래 명령은 저장소 루트에서 실행합니다. 비밀키는 출력이나 명령줄 값에 넣지 않습니다. 이미 확장한 원장에는 `--extend-window`가 필요하지 않지만, 같은 명령을 재실행해도 기존 월을 초기화하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -B -m pipeline.real_estate_fetch --root .local/real-estate-20260920 --regions .local/real-estate-20260920/official-codes/registry.json --as-of 2026-09-19T17:08:31Z --months 121
.\.venv\Scripts\python.exe -B -m pipeline.real_estate_fetch --root .local/real-estate-20260920 --regions .local/real-estate-20260920/official-codes/registry.json --as-of 2026-09-19T17:08:31Z --months 121 --collect-month 201610 --max-requests 600 --max-bytes 67108864 --daily-budget 8000 --min-interval 0.3 --secret-file .local/auth/your-secret.json --execute
```

첫 명령은 API를 호출하지 않습니다. 새 원장을 기존 61개월에서 한 번만 확장할 때에는 첫 명령에 `--extend-window`를 붙이고, **그 전에** 별도 위치로 SQLite online backup 및 원본 파일 백업을 완료해야 합니다. `--collect-month`가 없으면 원장 우선순위에 따라 수집하며, `--max-requests`와 `--max-bytes` 중 먼저 도달한 예산에서 멈춥니다. 실패·부분 상태를 0건으로 전환하지 않습니다. 서비스별 KST 하루 8,000회 상한은 **이 로컬 원장의 호출만** 합산하므로 같은 키를 쓰는 다른 프로그램의 호출량은 별도 확인해야 합니다.

복원 시험은 기존 원장을 건드리지 않고 새 격리 디렉터리에서 수행합니다. SQLite 온라인 백업 파일뿐 아니라 registry, 원본 XML, 모든 과거 스냅샷의 불변 파일과 SHA 목록이 있어야 합니다. `PRAGMA integrity_check`, 작업·호출·스냅샷 행 대조, 참조 파일 전량 SHA 검사, 게시 후보 재생성을 통과해야 독립 복구입니다. 현재 위 SQLite 사본은 **로컬 보호 사본**이며 다른 기기의 원격 백업이나 원본 전량 복구 증빙은 아닙니다.

## 게시와 자동화의 별도 관문

1. 과거 유효 코드의 효력일과 당시 시군구·법정동 경계를 검증한 조회 장부를 만듭니다. 현행 코드로 조회한 2016년 자료를 현재 행정경계에 자동 합산하지 않습니다.
2. 121개월의 각 지역·유형 작업에 대해 성공/정상 빈 응답/실패/대기를 감사하고, 취소·정정 및 지연 신고 재조회 일정을 기록합니다. 지금의 2016년 9~10월 두 달 완료로 10년 수집 완료를 선언하지 않습니다.
3. 자료 게시기는 검증된 월과 지역만 공개 release에 추가해야 합니다. 프런트엔드는 release의 실제 보유 기간을 보여주고 없는 기간을 빈 거래로 그리지 않아야 합니다.
4. 서버 자동 수집은 원본·호출 예약·SQLite 상태의 **내구성 있는 외부 저장과 단일 수집 소유권**, 무료 사용량 제한, 실패 후 복구를 먼저 요구합니다. 현재 공개 GitHub 계획 workflow는 API 수집을 하지 않으며, Cloudflare 정적 호스팅은 새 거래를 스스로 가져오지 않습니다. Actions 임시 artifact를 장기 유일 사본으로 사용하지 않습니다.
