첫 명령은 계획만 생성하고 키·네트워크를 사용하지 않습니다. 둘째 명령은 완료되지 않은 작업부터 이어갑니다. 한 실행 최대 64MiB, 한 페이지 최대 8MiB, HTTP 60초, 페이지당 최대 1,000행, 리다이렉트·인증서 예외·HTTP 다운그레이드 없음, 자동 재시도 0회입니다. **새 수집·재처리·후보 생성은 여유 35GiB 이상에서 시작하고, 작업 중에도 30GiB를 보존합니다.** 단일 수집 임대로 동시 실행을 막고, 성공한 페이지 파일을 SHA로 보존한 뒤 모든 페이지가 일치할 때만 해당 작업을 완료합니다.

`--collect-month 202608`은 특정 월만, 반복 옵션은 여러 월만 처리합니다. `--retry-failed`는 원인을 검토한 실패 작업을 다시 대기 상태로 만들고, `--refresh`는 선택 범위의 완료 작업을 새로 조회합니다. 두 옵션 모두 기존 원본·스냅샷을 지우지 않습니다. 제공기관 인증·쿼터 오류나 비밀 반사, 저장소 오류는 즉시 중단합니다. 그 외 연속 오류 3회도 중단합니다. 실패를 0건으로 게시하지 않습니다.

## 원본 보존과 정규화 스냅샷 압축

[비공개 스냅샷 저장 모듈](../pipeline/real_estate_storage.py)은 이후 생성하는 정규화 JSON을 결정론적 gzip으로 저장합니다. 원본 XML, 공개 자산의 JSON, 기존 비압축 스냅샷은 바꾸거나 삭제하지 않습니다. 원장의 descriptor는 저장 파일의 SHA·바이트와 복원 JSON의 SHA·바이트를 각각 고정하며, 게시기는 두 해시를 검사한 다음 원본 XML 재파싱 결과와 비교합니다. 기존 비압축 파일도 계속 읽습니다.

압축 해제는 최대 128MiB로 제한하고 잘린 파일·CRC 오류·추가 gzip member·뒤따르는 바이트·선언 크기 및 SHA 불일치를 거부합니다. 실제 기존 스냅샷 8개의 메모리 내 검사에서 4,866,638B가 432,294B로 줄었고, 8개 모두 원본 바이트와 일치했습니다. **91.117%는 이 표본의 비공개 정규화 저장 크기 감소율**이며, 전체 60개월 압축률·HTTP 전송량·GPU 성능 결과가 아닙니다. 증빙은 `.local/real-estate-20260920/snapshot-compression-audit.json`입니다.

### Actions artifact와 cache를 영구 원본 보관소로 쓰지 않음

2026-09-20 확인한 [GitHub 요금 안내](https://docs.github.com/en/billing/concepts/product-billing/github-actions)와 [한도 표](https://docs.github.com/en/actions/reference/limits)는 Free의 artifact 저장량을 500MB, Pro를 1GB로 안내하며 Packages와 공유한다고 설명합니다. 공개 저장소의 표준 runner 사용이 무료라는 설명과 원본 보관 예산을 구분하고, **5GB를 일반적인 무료 artifact 보관 한도로 전제하지 않습니다.** 실제 계정의 적용 요금제·다른 저장소 사용량·초과사용 차단 설정은 별도로 확인해야 합니다.

[Actions artifact](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/remove-workflow-artifacts)는 기본 90일 후 만료되며 workflow run 삭제에도 영향을 받습니다. [cache](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching)는 기본 7일 미접근 시 삭제되고 용량에 따른 퇴거도 있어 checkpoint의 유일한 사본으로 삼을 수 없습니다. 장기 원본을 포함하지 않는 작은 검증 보고서만 artifact에 두는 것을 권합니다. 이것은 운영 제안이며 현재 계획 workflow가 원본을 업로드하는 기능을 갖고 있다는 뜻이 아닙니다.

또한 [공개 표준 Ubuntu runner의 공식 저장소 사양](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)은 14GB입니다. 계획 전용 모듈은 16MiB 출력 상한과 별도의 64MiB 여유 하한을 적용해 대량 수집과 분리했고, 14GB 조건과 workflow 본문을 로컬에서 검증했습니다. 실제 `Collector` 생성자는 계속 30GiB 여유를 검사하고 수집 시작에는 35GiB를 요구하므로, **실제 수집 CLI를 그대로 표준 Actions로 옮기는 문제는 아직 남아 있습니다.** 제한된 CI 임시 공간·외부 원본 보존·증분 게시를 별도로 구현해야 하며 노트북의 기준을 낮춰 해결하지 않습니다. 실제 Actions 수집 실행은 아직 검증하지 않았습니다.

### 권고하는 무료 복구 구성 — 아직 제안

공개 소스/정적 제공과 분리한 **프로젝트 전용 비공개 GitHub 저장소의 Releases**를 재현 자료 보관 후보로 권합니다. [공식 Releases 문서](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)는 자산당 2GiB 미만·릴리스당 1,000개를 허용하고 전체 릴리스 크기·대역폭 제한은 없다고 안내합니다. 이를 일반적인 무제한 파일 백업 서비스로 표현하지 않고, 이 프로젝트의 릴리스 재현에 필요한 자료로 범위를 한정합니다.

운영 제안은 256~512MiB 단위의 불변 원본/스냅샷 묶음, SHA·바이트·파일 허용목록을 담은 base+delta manifest, 정제 코드 commit·공식 registry SHA, 일관된 SQLite online backup을 함께 보존하는 방식입니다. 실행 중인 `checkpoint.sqlite` 파일만 복사하면 WAL의 상태를 빠뜨릴 수 있으므로 일관된 DB 백업이 필요합니다. `meta/jobs/calls/snapshots`와 원본·과거 스냅샷·출처를 모두 복원 대상으로 고정하되, 실제 키·`.dev.vars`·인증 폴더·키 포함 요청 URL은 대상에 넣지 않습니다.

비공개 저장소·해당 저장소만 접근하는 최소 권한 인증·업로드/재다운로드·외부 사본만 사용한 복원은 **아직 구성하거나 실행하지 않았습니다.** 기존 로컬 파일을 유지하고 외부 다운로드, 압축 해제 경로/중복/누락 검사, 모든 파일 SHA, DB 무결성, 후보 재현을 통과한 뒤에만 독립 복구가 가능하다고 판정해야 합니다. 문서에 적은 제안만으로 원본 삭제가 허용되거나 원격 백업이 완료되지 않습니다.

### 실제 증분 수집·게시를 켜기 전에 필요한 구현

1. **호출 예산을 실행 전에 외부에 보존합니다.** 이전 SQLite의 KST 일일 `calls`와 계획 창·registry 해시를 복원해야 하며, 같은 키를 쓰는 로컬/Actions 작업에 하나의 수집 소유권을 적용해야 합니다. GitHub `concurrency`는 다른 로컬 수집기까지 잠그지 않습니다. 작업 종료 시 checkpoint를 업로드하는 것만으로는 요청 후 runner가 중단될 때 호출 예약이 유실되는 문제를 막지 못합니다. 요청 또는 제한된 요청 묶음의 외부 영속 예약이 먼저 필요합니다.
2. **새 원본과 델타를 검증한 뒤 최신 장부를 전환합니다.** 외부 저장에 실패하면 새 조회를 멈추고 미완료 상태를 유지해야 합니다. 사본 누락을 API 재조회나 빈 배열로 조용히 대체하지 않습니다. 상태 포인터는 이전 버전과의 일치를 확인하고 바꿔 병렬 실행이 서로의 원장을 덮지 못하게 해야 합니다.
3. **변경 지역·월만 처리하는 게시기를 구현합니다.** 현재 게시기는 완료된 모든 원본을 다시 읽어 정규화 결과를 대조하고 전체 후보를 새로 만듭니다. 이는 검증된 로컬 전체 게시 경로이며 원격 증분 게시기는 아닙니다. 61개월 전체를 매번 artifact/runner에 복사하지 않으려면, 이전에 검증된 불변 자산·감사와 새 변경분을 결합하는 계약 및 검증이 필요합니다. 이전 자료의 감사 재사용과 새로 원본을 전수 재검수한 결과를 구별해야 합니다.
4. **전체 의존 파일과 저장 예산을 다시 확인합니다.** 변경분만 수집했더라도 공개 후보의 전체 61개월 참조·지도 참조·파일 수·크기·SHA가 닫혀 있어야 합니다. 새 자료만 든 후보를 전체 자료처럼 전환하지 않습니다. 임시 처리 공간·외부 저장·실제 계정 무료 한도를 넘는 작업은 시작하지 않습니다.
5. **월 이관·복원·중단을 실제로 검증합니다.** 새 달에도 일일 호출 이력을 보존하고, 강제 중단 후 재시작·백업 실패·부분 페이지·해제/정정 재조회·외부 복원 테스트를 통과해야 합니다. 현재 `planning_window_changed_requires_migration` 방어를 원장 삭제로 우회하지 않습니다. 이 조건을 충족하기 전에는 현재의 로컬 수집과 계획 전용 workflow를 유지합니다.
