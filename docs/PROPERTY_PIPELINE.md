## 재실행 명령

키는 실행 환경의 `DATA_GO_KR_SERVICE_KEY`에만 둡니다. 명령줄 인자나 기록 파일에 키 값을 넣지 않습니다. 아래 예시는 원장 기간을 명시적으로 고정합니다.

```powershell
.\.venv\Scripts\python.exe -B -m pipeline.real_estate_fetch --root .local/real-estate-20260920 --regions .local/real-estate-20260920/official-codes/registry.json --as-of 2026-09-19T17:08:31Z --months 61
.\.venv\Scripts\python.exe -B -m pipeline.real_estate_fetch --root .local/real-estate-20260920 --regions .local/real-estate-20260920/official-codes/registry.json --as-of 2026-09-19T17:08:31Z --months 61 --max-requests 600 --max-bytes 67108864 --daily-budget 8000 --min-interval 0.3 --execute
```

첫 명령은 계획만 생성하고 키·네트워크를 사용하지 않습니다. 둘째 명령은 완료되지 않은 작업부터 이어갑니다. 한 실행 최대 64MiB, 한 페이지 최대 8MiB, HTTP 60초, 페이지당 최대 1,000행, 리다이렉트·인증서 예외·HTTP 다운그레이드 없음, 자동 재시도 0회입니다. 저장소 여유 30GiB를 보존하고, 단일 수집 임대로 동시 실행을 막습니다. 성공한 페이지 파일을 SHA로 보존한 뒤 모든 페이지가 일치할 때만 해당 작업을 완료합니다.

`--collect-month 202608`은 특정 월만, 반복 옵션은 여러 월만 처리합니다. `--retry-failed`는 원인을 검토한 실패 작업을 다시 대기 상태로 만들고, `--refresh`는 선택 범위의 완료 작업을 새로 조회합니다. 두 옵션 모두 기존 원본·스냅샷을 지우지 않습니다. 제공기관 인증·쿼터 오류나 비밀 반사, 저장소 오류는 즉시 중단합니다. 그 외 연속 오류 3회도 중단합니다. 실패를 0건으로 게시하지 않습니다.

달이 바뀌어 동일 원장의 계획 창을 조용히 62개월로 늘리거나 호출 장부를 초기화하지 않습니다. 다른 창은 `planning_window_changed_requires_migration`으로 거부합니다. 다음 계획 창으로 옮길 때는 기존 일일 호출 예약을 보존하는 명시적 이관이 필요하며, 그 자동화는 아직 구현되지 않았습니다.

정규화 규칙을 바꾼 후 기존 원본을 재검수하려면 네트워크·키 없이 실행합니다.


게시기는 읽기 트랜잭션으로 원장을 고정하고, 완료 작업의 모든 원본 XML을 다시 파싱해 저장된 스냅샷과 바이트 단위로 대조합니다. 원본이 바뀌거나 재처리가 일치하지 않으면 최종 후보 폴더를 만들지 않습니다. 검증 중 실패한 준비 폴더는 조사용으로 남깁니다. 기존 후보·`public`·배포 포인터를 덮어쓰지 않습니다.

## 파일 계약과 20,000파일 예산

후보 폴더의 `publication.json`은 `files[{path,sha256,byte_length}]`와 `property_release:{path,sha256,release_id}`를 제공합니다. 진입점은 `data/property/property-<해시>/manifest.json`이며, 앱은 작은 전국 목록을 읽고 선택한 지역의 자료만 읽습니다. 배포 담당 도구가 파일 SHA·크기·폐쇄적인 의존 목록을 다시 감사한 후 지도 자료와 같은 데이터 Pages 프로젝트에 결합합니다.

| 자산 | 파일 수 계산 |
|---|---:|
| 거래: 같은 지역·월의 매매+전월세를 물리적으로 합침 | 256 × 61 = 15,616개, 추가 크기 분할 전 |
| 지역별 작업/지표 색인 | 256개 |
| 단지 목록 | 최대 256개, 현재는 좌표 null |
| 전국 목록·진입점 | 2개 |
| 부동산 기본 합계 | **16,130개** |

각 거래 파일은 4MiB를 목표로 나누며 24MiB를 넘으면 실패합니다. 최근 두 달은 월 파일 512개로 추가 분할이 없었습니다. 모든 과거 월도 이 크기라는 보장은 없습니다. 기본 계산상 지도와 공통 파일에 남는 몫은 **3,870개**이며, 실제 지도 상세 후보와 합친 감사가 통과해야 공개할 수 있습니다. 지도 최초 시도 후보는 27파일이나 전국 상세 최종 수는 아직 미확정입니다. 합산 한도를 넘으면 연도/반년 묶음 등 저장 파티션을 변경해야 하며, 모든 60개월의 파일 수를 확인했다는 뜻이 아닙니다.

## 아직 연결하지 않은 부분

- 현행/폐지 법정코드의 효력일 이력과 지도 경계 시점 대조.
- 공식 공동주택/건축물/필지 ID를 통한 좌표 연결. 단지명·주소 문자열만으로 위치를 만들어 넣지 않습니다.
- 원천에 없는 거래 고유번호를 이용한 확정 정정·취소 사건 연결. 현재는 스냅샷 행 차이와 출처만 보존합니다.
- 전국 60개월 전체 조회, 새 달로 원장을 넘기는 자동 이관, 공개 후보 갱신의 운영 자동화.
- 인구·공급·공시가격·가격지수·경공매 지표. 이 문서의 매매·전월세 수집 완료와 혼동하지 않습니다.

신규 Python 의존성은 추가하지 않았습니다. stdlib XML·Decimal·SQLite·HTTPS·ZIP을 사용하고 실제 데이터는 비공개 `.local`에 보존합니다. 자동 CI는 기본적으로 수동 시작과 검수된 산출물 artifact까지만 맡아야 하며, 이전 SQLite 원장을 복구하지 않고 새 작업마다 호출 예산을 초기화해서는 안 됩니다.
